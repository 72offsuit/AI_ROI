# ADR-0010 · "공허한 통과"를 스키마로 막는다

**상태** 확정 · 2026-09-11 · James
**발견** Jonnathan (예시를 읽다가) · **실측** 리드 · **판정** 이 문서

## 문제

```jsonc
{ "id":"DQ-01", "title":"event_id 전역 유일",
  "status":"pass", "violations":0, "examined_rows":0,
  "scope":"… 오늘은 0행이므로 위반이 없는 것이 아니라 검사 대상이 없다 …" }
```

`status` 가 `pass` 다. **순진하게 구현하면 초록 ✓ PASS 로 그려진다 — 아무것도 검사하지 않았는데.**
`scope` 가 산문으로 경고하지만 **산문은 색을 이기지 못한다.**

리드가 개정 전 예시를 세었다:
```
examples/empty-sink/data_quality_report.json
  검사 18건 중 status="pass" ∧ examined_rows==0  →  7건 (39%)
```

`gate_result: incomplete` 라 **게이트 층은 정직했다.** 거짓말한 것은 **개별 검사 행**이다.
*"미실행을 통과로 표시하지 않는다"* 의 한 층 아래 변종 — **"검사했지만 검사 대상이 0행이었다."**

## 결정

**`checks[].status` 에 `vacuous` 를 신설하고 두 층에서 강제한다.**

| 층 | 규칙 |
|---|---|
| 검사 행 | `examined_rows == 0` → `status` 가 **`pass` 일 수 없다** |
| 검사 행 | `status == "vacuous"` → `examined_rows == 0` ∧ `violations == null` ∧ 사유 필수 |
| 검사 행 | `status == "pass"` → `examined_rows >= 1` |
| **게이트** | `gate_result == "pass"` → **모든 검사가 `pass`** (→ `vacuous` 하나만 있어도 `pass` 불가) |

## 근거

**Jonnathan 은 화면 규칙(`V-12`)으로 막겠다고 했고, 스스로 "당신 쪽에서 더 강하게 만들 여지가 있다"고 되물었다. 그 말이 맞다.**

| | 화면 규율 | 스키마 |
|---|---|---|
| 뚫리는 조건 | **구현자 한 명이 놓치면** | 게시가 실패한다 |
| 화면의 부담 | `pass` 와 `examined_rows` 를 **함께 읽어 판정**해야 한다 | `status == "vacuous"` 를 그리면 된다 |
| 다른 소비자 | 리포트·CI 는 여전히 속는다 | 전부 보호된다 |

그리고 **이미 같은 패턴이 계약에 있다** — `denominator == 0 → status:"ok"` 불가(`ADR-0008`).
*"분모가 없는데 계산됐다고 말하지 않는다"* 와 *"검사 대상이 없는데 통과했다고 말하지 않는다"* 는 **같은 문장의 두 적용**이다. 한쪽만 스키마로 막는 것은 정합적이지 않다.

## 검증 (실행함)
```
거부됨 ✅  ★ V-12 · 검사 대상 0행인데 pass 라고 한다 (공허한 통과)
거부됨 ✅  ★ V-12 · vacuous 인데 위반 건수를 0으로 적는다

개정 후 실측:
  empty-sink: 검사 18건 · gate=incomplete · 공허한 pass 0건
              vacuous 7건 [DQ-01 · DQ-02b · DQ-04 · DQ-07 · DQ-08 · DQ-10 · DQ-11]
```
리드가 센 7건과 정확히 일치한다.

## 기각한 대안
| 대안 | 사유 |
|---|---|
| 화면 규칙으로만 (`V-12`) | 구현자 한 명이 놓치면 39%가 초록이 된다. 리포트·CI 는 여전히 속는다 |
| `pass` 를 유지하고 `vacuous: true` 플래그 | 플래그는 무시된다. **`status` 는 무시할 수 없다** — 그것이 렌더링의 분기점이다 |
| `not_run` 으로 흡수 | **실행은 했다.** 안 한 것으로 적으면 그것도 거짓이다. 셋(`pass`/`vacuous`/`not_run`)이 다 다르다 |
| `gate_result` 만 `incomplete` 로 | 개정 전이 그랬고, **그래서 개별 행이 거짓말했다.** 요약만 보는 사람은 속지 않지만 표를 보는 사람이 속는다 |

## 남는 것

`vacuous` 는 **오늘 이 저장소의 정상 상태다** — 데이터가 0행이므로. 화면이 그것을 실패로 그리면 안 되고, 통과로 그려도 안 된다.
Jonnathan 이 `unconnected`(info) + *"공허한 통과 · 검사 대상 0행"* 으로 렌더링하기로 했다. **정확한 처리다.**
