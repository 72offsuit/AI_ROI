# ADR-0004 · 봉인된 `isolation.yml` 을 고치지 않고 새 워크플로를 추가한다

**상태** **제안 · 사용자 확인 대기 (결정 D-19)** · 2026-09-11 · James
**맥락** T2.9 · 가정 A7

## 문제
pyarrow·PyYAML 을 넣으면 의존성 없는 `isolation.yml` 잡이 `ImportError` 로 실패할 수 있다.
그런데 그 파일은 **봉인**이다 (task-graph §4 — W6 Matthias + 사용자 승인).

## 결정
1. **모듈 경계에서 의존성을 가둔다** — 계산층은 표준 라이브러리만. `config_loader.py` 만 PyYAML 을 본다
2. 선택 의존성은 **guarded import + 명시적 skip**
3. **`isolation.yml` 을 편집하지 않는다.** 대신 `.github/workflows/tests-with-deps.yml` 을 **새로 만든다**

## 근거
봉인의 목적은 *"격리 검사가 조용히 헐거워지는 것"* 을 막는 데 있다.
그 파일에 `pip install` 을 넣으면 **"의존성 없이도 전 테스트가 돈다"(`ISO-005`)는 보장 자체가 사라진다.**
새 파일을 추가하면 두 보장이 동시에 성립하고, 두 잡의 **skip 수 차이가 곧 "의존성이 필요한 검증"의 목록**이 된다.

## 기각한 대안
| 대안 | 사유 |
|---|---|
| `isolation.yml` 에 설치 단계 추가 | `ISO-005` 보장을 없앤다. 봉인 파일 편집 |
| 새 워크플로 없이 로컬 실행 증거만 | `B-1`(Parquet 검증)이 CI 에서 영구히 미검증으로 남는다 |
| YAML 파서를 자체 구현해 PyYAML 을 피한다 | 부분 구현 파서는 **조용히 다른 값을 읽는다.** 경제 규칙 config 에서 그것은 치명적이다 |

## 결과
- **새 워크플로 추가는 편집이 아니지만 CI 를 바꾸는 일이다. 사용자 확인 없이 만들지 않는다**
- 확인 전까지 Parquet 검증은 로컬 증거로만 남기고 `DQ-17` 은 `blocked` 를 유지한다
- `import yaml` 이 `config_loader.py` 한 파일에만 있음을 테스트로 고정한다 (A7-6)
