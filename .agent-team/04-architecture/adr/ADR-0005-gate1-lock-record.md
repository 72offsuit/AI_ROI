# ADR-0005 · Lock 기록을 `config/gate1_lock.yaml` 에 둔다

**상태** 확정 (결정 D-26 대기) · 2026-09-11 · James
**맥락** T2.11 · `#49`

## 문제
`#49` 는 *"누가 언제 무엇을 Lock 했는지 추적할 수 있다"* 를 요구한다. 사람이 읽는 체크리스트만으로는 **해시 대조가 불가능**하다.
그런데 `data_spec` §15.2 가 버전 기록을 두라고 한 `data/data_version.yaml` 은 **`.gitignore` 대상**(`data/`)이라 커밋되지 않는다 — 다음 사람이 대조할 수 없다.

## 결정
사람용과 기계용을 나눈다.
- **`docs/gate1_checklist.md`** — 절차·선행 조건·범위 한정 문구·해제 절차 (`#49` 가 지정한 이름)
- **`config/gate1_lock.yaml`** — Lock 기록 (해시·커밋·KST 시각·주체·9종 항목). **커밋한다**

## 근거
- 봉인 대상 config 옆에 두는 것이 자연스럽다 (`economic_config.yaml` 이 Lock 대상이다)
- **커밋되어야 다음 사람이 대조할 수 있고, `git log` 가 재봉인 이력을 보존한다** — 이것이 *"결과를 본 뒤 고치는 것"* 에 대한 유일한 흔적이다
- 형태가 `data_spec` §15.2 의 `data_version.yaml` 선례와 같다

## 비용
SRS §31 이 `config/` 에 열거한 4파일에 없는 **5번째 파일**이다. 구조 확장이며 **리드 인지가 필요하다.**

## 기각한 대안
| 대안 | 사유 |
|---|---|
| `docs/gate1_lock.yaml` | 기계 기록을 문서 디렉터리에 두는 것이 어색하고, 봉인 대상 config 와 멀어진다 |
| `docs/gate1_checklist.md` 안에 임베드 | 사람 문서와 기계 기록을 섞어 **둘 다 나빠진다.** 파싱도 어렵다 |
| `data/data_version.yaml` 에 합친다 | **`.gitignore` 대상이라 커밋되지 않는다.** 대조 자체가 불가능해진다 |
