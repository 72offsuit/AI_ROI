# ADR-0007 · 출처별 결과를 분기가 아니라 입력 분할로 만든다

**상태** 확정 · 2026-09-11 · James
**맥락** T2.6 · `EC-2` · 창구 중립성

## 문제
`MEA-002` 는 출처별(커머스/시뮬레이터) 결과를 요구한다. 가장 쉬운 구현은 계산 함수 안의 분기다.
그러나 `src/AGENTS.md` 는 *"`measurement` 는 아무에게도 의존하지 않는다. 창구가 한쪽 편을 들면 계약이 아니다"* 를 못박는다.

`if source == COMMERCE: return unavailable(...)` 한 줄이면 오늘 요구는 충족되고, **그 순간 창구가 커머스의 구현 상태를 알게 된다.**

## 결정
1. `kpi.py`·`economics.py` 는 **순수 함수**다. 파일을 읽지 않고 출처를 모른다
2. 출처를 아는 자리는 **`publish.py` 의 `partition_by_source()` 한 곳**이다
3. 출처별 결과는 **같은 함수를 다른 입력으로 두 번 호출**해 만든다
4. 계산 가능 여부는 **`has_cost_basis(order)`** — 근거의 유무로 가른다 (`EC-2`)
5. **소스 검사 테스트로 고정한다** — `economics.py`·`kpi.py` 에 `commerce`·`simulator` 문자열이 없다

## 근거
| | 분기로 구현 | 입력 분할로 구현 |
|---|---|---|
| 커머스가 `unit_cost` 를 넣으면 | 코드를 고쳐야 한다 | **자동으로 계산된다** |
| 시뮬레이터가 원가 없는 상품을 만들면 | 출처가 시뮬레이터라서 **잘못 계산된다** | **거부한다 — 올바르다** |
| 계약이 아는 것 | 커머스의 구현 상태 | **자기 계약뿐** |
| 검사 | 사람이 코드를 읽는다 | **테스트가 실패한다** |

## 결과
- `publish.py` 가 유일한 조립 지점이 된다 (`code-structure.md` §2.1)
- `config_loader` 가 **용도별로 분리된 객체**를 돌려준다 — `economics.py` 는 원가율을 손에 넣을 방법이 타입에 없다 (`EC-9`)
- `tests/test_neutrality.py` 신설
