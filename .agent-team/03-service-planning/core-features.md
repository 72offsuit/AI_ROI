# 2. Core Feature 상세

## CF-1 · 이벤트 계약의 값 수준 강제

**문제** 스키마가 **필드의 존재**는 엄격히 강제하지만 **값**은 전혀 검사하지 않는다.
`page_type="아무거나"` · `category="우주선"` · `customer_id="test-user-1"` 이 **문제 0건으로 통과**한다(리드 재현 확인, `#54`).

**왜 핵심 기능인가** 측정 계층은 커머스와 시뮬레이터 **양쪽의 계약**이다(`src/AGENTS.md`). 계약이 *"어떤 값을 써야 하는가"* 에 답하지 못하면 계약이 아니다.
그리고 **`EVENT SCHEMA v1` Lock 이후에는 되돌릴 수 없다**(`gate1-lock-scope.md` §3 G-1~G-5).

**포함** `category` 5종 Enum · `page_type` 8종 Enum · `validate_event()`의 `check_identifier()` 호출 · 카테고리 어휘 정본 확정(**영문 코드 권고**) · 두 테스트 파일의 어휘 통일 · `docs/event_schema.md` 재생성
**제외** 커머스 측 식별자 변경(별도 저장소) · 매핑 계층 구현(맞추는 쪽은 소스)

## CF-2 · Event Sink 신뢰성 복구

**문제** 실행으로 재현된 결함 3건(리드 재현 확인, `#53`).

| | 결함 | 영향 |
|---|---|---|
| D1-1 | 동일 root 재기록 시 파티션 **덮어씀** (2건+3건 → 3건) | **데이터 소실** |
| D1-2 | `strict=False`가 무효 레코드에 **크래시** | `MEA-003` 정면 충돌 |
| D1-3 | **타임존 미강제** — UTC가 통과하고 파티션이 하루 어긋남 | 코호트·리텐션 왜곡 |

**왜 데이터 생성 이전에 고쳐야 하는가** D1-1은 **데이터 소실형**이다. `data/raw`에 쌓인 뒤 고치면 이미 사라진 것은 돌아오지 않는다.
**포함** 세 결함 각각에 **먼저 실패하는 테스트**를 추가한 뒤 수정 · 독트링과 실제 동작 일치 · 타임존 정책 결정과 문서화
**제외** Parquet 경로 검증(pyarrow 미설치 → `BLOCKED`) · `write_batch()` · `_digest()` 성능

**정본** `docs/data_spec.html` §9 · `#48`
**핵심** *"하나라도 실패하면 파이프라인은 중단한다(**경고로 넘어가지 않는다**)."*

**→ 실행 불가 항목은 `BLOCKED`·`미실행`으로 리포트에 남긴다. 통과로 적지 않는다.**

## CF-6 · 측정 산출물 게시 계약 *(이슈 없음 — 새로 발견)*

**왜 필요한가** `usp.md` §1.4 조건 C-1. `DB-014`의 대시보드 읽기 허용 목록은 **`results/`와 `data/processed/` 뿐이고 `data/raw/`가 없다.**
그런데 관측 화면군의 원천(`manifest.json`)은 Sink root(= `data/raw/`) 아래에 있다.
→ **측정 계층이 `results/` 아래에 게시하고 대시보드는 그것만 읽는다.** `DB-013`·`DB-014`를 한 글자도 고치지 않고 성립한다.

**정본이 이미 같은 방향을 규정했다** — `data_spec` §9: *"모든 검사는 `src/measurement/validate.py`에서 실행하고 **`results/data_quality_report.json`** 에 결과를 남긴다."*
그리고 `tests/test_isolation.py`의 `FORBIDDEN_PATHS`가 `src.measurement`의 `results/` 접근을 **막지 않는다**(실측 확인).

**포함** 수집 건전성·KPI·품질·봉인 상태를 `results/` 아래 파일로 게시 · **출처 분류와 계산 불가 판정을 게시 시점에 완료**(`DB-012` — 대시보드는 계산하지 않는다) · 게시물에 `data_version`·커밋·생성 시각 포함(`DB-013`)
**부수 효과** W1 보완점 **W-7**(출처가 저장 레코드에 남지 않아 대시보드가 전량 재분류해야 한다)이 **해소된다**

> **이 기능을 소유한 이슈가 없다.** 신규 초안 `AIROI-M8`이 필요하다 → `issue-priority.md` §4. **발행은 사용자 지시 후.**
