> **미봉인을 봉인으로 적지 않고, 미실행 검증을 통과로 적지 않는다**(AGENTS.md).

# 2. Lock 순서 검증 (W1이 지목한 순서)

W1의 강제 순서: **`#54`(값 강제) → `#45`(M-3 기록 계약) → `#49`(M-7 GATE 1 Lock)**

## 2.1 판정 — **순서는 옳다. 그러나 불완전하다.**

| 링크 | 검증 | 판정 |
|---|---|---|
| `#54` → `#45` | `#54` 본문: *"**`#45`(M-3)의 선행 조건입니다** — 계약 문서가 이 값들을 인용합니다"* | ✅ 확인 |
| `#54` → `#49` | `#54` 본문: *"**`#49`(M-7) GATE 1 Lock 이전에 끝나야 합니다.** … 값 규약이 빠진 채 Lock되면 되돌릴 수 없습니다"* | ✅ 확인 |
| `#45` → `#49` | **`#49`의 의존성 목록에 `#45`가 없다** — `[M-1] 이벤트 스키마, [M-4] KPI 정의, [M-5] 경제 규칙`만 있다 | ⚠️ **이슈에는 없으나 필요하다** (§2.2) |
| **누락** | **`#46`(M-4) · `#47`(M-5)이 `#49`의 명시적 선행인데 W1의 순서에 없다** | ❌ **보완 필요** |
| **누락** | **`#53`(Sink 결함) D1-3(타임존)이 스키마 값 규약의 일부다** | ❌ **보완 필요** |

## 2.2 왜 `#45`가 `#49` 앞이어야 하는가 — 이슈에 없는 근거

M-3 기록 계약은 **스키마에서 파생되는 문서**이므로 형식상 Lock의 선행이 아니다.
그러나 **계약 문서를 실제로 쓰는 행위가 스키마의 표현력을 검산한다.**

W1이 발견한 두 공백이 이 검산에서만 드러난다:

| 공백 | 계약 문서를 쓸 때 드러나는 방식 |
|---|---|
| **파생 상태 기록 경로 부재** (W1 D-7) — `DerivedStateType`이 `EventType` 밖이라 **Sink에 기록할 수단이 없다** | *"`at_risk` 상태를 어떻게 기록하는가"* 를 쓰려는 순간 답이 없음이 드러난다 |
| **`shipping_subsidy` 필드 부재** (`kpi-definition-v1.md` §5.4) — 기여이익식이 빼는 항목이 스키마에 없다 | *"배송 보조를 어떤 필드로 기록하는가"* 를 쓰려는 순간 드러난다 |

**Lock 이후에 이것을 발견하면 `FREEZE-003` 전량 재실행이다.** → **`#45`를 Lock의 최종 검산으로 둔다.**

## 2.3 확정 순서 — C1 Lock 경로

```

                  └ D1-3 타임존 정책 확정    └ 어휘·식별자·page_type 확정
                              ↓ 스키마 계약의 값 수준이 닫힌다

Phase 4           #49  M-7 GATE 1 Freeze 절차 + 부분 Lock 실행

(Lock과 독립 · Phase 2와 병렬 가능)
```

**Phase 3에서 공백이 드러나면 Phase 4로 진행하지 않는다.** 멈추고 보고한다.

## 4.6 ⚠️ `CHURN DEFINITION v1` — **부분 가능**

| Lock 한다 | Lock 하지 않는다 |
|---|---|
| **판정 방식** — 고정 윈도우 · `rule_operator: OR` 구조 | `at_risk_days` = 28 (**가설값**) |
| **운영 상태(후향)와 모델 라벨(전향)의 분리** (`kpi-definition-v1.md` §6) | `no_purchase_days` = 42 (**가설값**) |
| **`label_window_days = 42`** — 운영 정의와 독립인 고정 상수 | `no_login_days` = 60 (**가설값**) |

**임계값을 Lock하지 않는 이유:** `data_spec` §5.1이 확정 절차 5단계(Warm-up 구매 간격 P75/P90 → Generated Churn Rate 15~25% 확인)를 규정했고, **①~④가 전부 시뮬레이터를 요구한다.** 절차를 건너뛴 Lock은 미실행 검증을 통과로 적는 것이다.
상세 근거는 `kpi-definition-v1.md` §1.1. **Caleb의 "42일 유지 Lock" 권고를 부분 기각한 지점이다.**

> ⚠️ **`data_spec` §15.3은 GATE 1 확정 항목에 "Churn 임계값"을 넣었다.** 즉 정본은 GATE 1에서 임계값이 확정되기를 기대한다.
> **모순이 아니다** — 정본은 **GATE 1 전체 통과**를 전제하고, C1은 GATE 1을 통과시키지 않는다(§1). 임계값은 **범위 C(시뮬레이터) 완료 시점에 GATE 1의 나머지 항목과 함께** 확정된다.

## 4.7 ❌ `TREATMENT RESPONSE v1` — 불가

`data_spec` §4.3의 `τ_i` 생성식과 강도 가드레일(ATE 3.0~6.0%p · 쿠폰 사용률 25~40% · Sleeping Dog 8~15% · 4분면 분포). **전부 `src/simulator/` 소유이고 Hidden Trait을 입력으로 쓴다.**

> **혼동 주의 — Treatment *비용*과 Treatment *반응*은 다르다.**
> **비용**(T0~T4 단위 비용, `data_spec` §6.2)은 `ECONOMIC RULE v1`에 속하고 **C1에서 Lock한다**.
> **반응**(`τ_i`, `treat_boost_i(t)`, 4분면)은 `TREATMENT RESPONSE v1`에 속하고 **C1에서 Lock하지 않는다**.
> 둘을 섞으면 시뮬레이터 파라미터를 측정 계층이 봉인하는 셈이 되어 **창구 중립성이 깨진다.**

**6개 테이블을 제외하는 이유:** `data_spec` §7.1이 요구하지만 **`sink.py:191`은 `events`만 구현했다**(W1 D-4 · `#44` OPEN 사유 1). **정의되지 않은 것을 Lock할 수 없다.**
→ **`docs/gate1_checklist.md`에 "`EVENT SCHEMA v1`의 Lock 범위는 `events` 테이블에 한정된다"를 명시**한다. 나중에 "스키마를 Lock했다"는 문장이 6테이블까지 덮는 것으로 읽히면 안 된다.

**Parquet을 제외하는 이유:** 저장 형식은 스키마 계약이 아니다. 단 **`NFR-001` 재현성(`events.parquet` SHA-256 일치)이 검증되지 않은 상태**임을 체크리스트에 `BLOCKED`로 남긴다.

## 4.9 ⚠️ `KPI DEFINITION v1` — **부분 가능**

**확정안:** `kpi-definition-v1.md` · **정본 충돌 해석:** 같은 문서 §7.4

## 5.1 Lock 위반 탐지 — "깨졌을 때 어떻게 아는가"

`#49`가 요구하는 절차이며 **설계는 James T2.11 소관**이다. 기획 관점의 요구만 남긴다.

| 요구 | 왜 |
|---|---|
| Lock된 정본 파일의 **현재 해시와 기록된 해시를 대조**할 수 있어야 한다 | 조용한 변경을 탐지하는 유일한 수단 |
| 대조 결과가 **대시보드 V6(봉인 상태)** 에 보여야 한다 | charter §2.2-3 *"화면으로 증명한다"* |
| 불일치 시 **경고가 아니라 명시적 실패**로 다뤄야 한다 | `data_spec` §9: *"하나라도 실패하면 파이프라인은 중단한다(경고로 넘어가지 않는다)"* |
| 대조를 실행하지 않았으면 **`미실행`으로 표시**한다 | 통과로 표시하지 않는다 |

# 6. Lock 후 남는 위험 — 정직하게

| 위험 | 왜 남는가 | 완화 |
|---|---|---|
| **시뮬레이터가 스키마에 없는 신호를 필요로 할 수 있다** | 시뮬레이터가 아직 없다. 스키마를 먼저 Lock하는 것이 `data_spec` §15의 구축 순서지만, 검산 대상이 문서뿐이다 | `#45`(M-3) 계약 문서를 **Lock 최종 검산**으로 둔다 (§2.2) |
| **커머스가 계약을 못 지킬 수 있다** | 커머스 식별자 4종이 전부 형식 위반이고(`ECOM-E8`) 이벤트 기록 자체가 없다 | 맞추는 쪽은 소스다(`#54`). 측정 계층에 예외를 넣지 않는다 |
| **부분 Lock이 "전체 Lock"으로 읽힐 수 있다** | 문장이 짧아지면 한정이 사라진다 | 체크리스트에 **범위 한정 문구를 필수 항목**으로 (§5) |
| **환불 미반영 가정이 잊힐 수 있다** | 가정은 시간이 지나면 사실로 읽힌다 | 산출물에 `refund_adjusted: false` 플래그 (`economic-rule-v1.md` §6.4) |
| **`data/raw`에 데이터가 쌓인 뒤 `#53` D1-1을 고치면** 이미 덮어써진 데이터는 복구되지 않는다 | 결함이 데이터 소실형이다 | **`#53`을 Phase 1에 둔 이유.** 데이터 생성 전에 고친다 |
