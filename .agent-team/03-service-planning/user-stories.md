- [ ] 위 항목을 **스크린샷으로 증명**한다 (대시보드 실행 명령은 W5-C에서 정의되므로 여기서 명시하지 않는다)

**나온 곳** CF-7 ← USP-1 · **charter §3.1③**

## US-12 · 커머스와 시뮬레이터가 갈라져 보인다

> **P-리드**로서 나는 **어떤 숫자가 커머스 실측이고 어떤 것이 시뮬레이터 생성인지** 화면에서 알고 싶다.
> 왜냐하면 `MEA-002`가 *"실험 결과 산출에는 시뮬레이터 생성분만 사용한다. 실측분을 섞으면 처치·통제 배정이 성립하지 않는다"* 고 규정했기 때문이다.

**인수 조건**
- [ ] 수집 현황·필드 충족률·KPI에서 **커머스 / 시뮬레이터가 갈라져** 보인다
- [ ] 합산 표시를 쓸 때는 **합산임이 이름이나 라벨에 드러난다**
- [ ] 출처 판정이 **`simulator_version`·`random_seed`의 null 여부**에서 파생된 것임이 화면 또는 문서에 설명된다
- [ ] **대시보드가 출처를 재분류하지 않는다** (US-10 게시물 사용)

**나온 곳** CF-7 ← USP-1 · **charter §3.1③-2**

## US-13 · 계산 불가가 0으로 보이지 않는다

> **P-팀**으로서 나는 **계산할 수 없는 지표가 0으로 표시되지 않기를** 원한다.
> 왜냐하면 이것이 **이 프로젝트가 증명하려는 것 자체**이기 때문이다 (USP-1).

**인수 조건**
- [ ] "계산 불가"가 **0과 다른 시각 상태**로 렌더링된다 — 숫자 `0`으로 표시되지 않는다
- [ ] 각 계산 불가에 **사유가 화면에 붙는다** (7종 사유 코드)
- [ ] **커머스 실측분의 `contribution_profit`이 `계산 불가 · 원가 근거 없음`으로 표시**되고, 같은 화면에서 `revenue`는 값으로 표시된다 — **USP-1의 대표 증명 장면**
- [ ] 데이터가 하나도 없는 초기 상태에서 화면이 **계산 불가로 가득한 것이 정상 동작**임이 화면 또는 문서에 설명된다
- [ ] 위 항목을 **스크린샷으로 증명**한다

**나온 곳** CF-7 ← **USP-1** · **charter §3.1③-3** · PRD §10.1 · charter 절대제약 6

## US-14 · 지금 보는 것이 어느 버전인지 안다

> **P-리드**로서 나는 **화면의 숫자가 어느 스키마·어느 커밋·어느 config에서 나왔는지** 알고 싶다.
> 왜냐하면 봉인이 깨진 것을 탐지하는 유일한 수단이 **해시 대조**이기 때문이다.

**인수 조건**
- [ ] `schema_version` · config 해시 · 생성 시각(**KST**) · 커밋 SHA가 화면에 보인다
- [ ] Lock된 항목과 **아직 열려 있는 항목**이 구분되어 보인다
- [ ] 해시 대조를 **실행하지 않았으면 "미실행"으로 표시**된다 — 통과로 표시하지 않는다
- [ ] 데이터 품질 검사 결과가 **PASS / FAIL / BLOCKED / 미실행** 4상태로 보인다

**나온 곳** CF-7 ← USP-2 · CF-9
