# 1. 첫 화면이 답해야 하는 질문 하나

charter §7.1의 1차 독자와 요구:

| 사용자 | 첫 화면에서 답을 얻어야 하는 질문 |
|---|---|
| **이 팀 (2~5인)** | **"이벤트가 제대로 쌓이고 있는가"** — 계약 위반·결손을 **즉시** 발견 |
| 다음 사이클 시뮬레이터 개발자 | 무엇을 어떤 스키마로 기록해야 하는가 |
| 다음 사이클 AI 개발자 | KPI·경제 규칙이 봉인된 정의 |

## 1.1 ★ 설계 판단 — 첫 화면은 지표 그리드가 아니라 **판정**이다

관측 대시보드의 기본형은 "KPI 카드 4~8개를 격자로 깐 요약 화면"이다. **C1에서는 틀린다.**

근거: `kpi-definition-v1.md` §8 — 계층 0 수집 건전성 지표가 **12종**이고, C1 초기에는 이 중 대부분이 0 또는 미수신이다. 12개 카드를 깔면 읽는 사람은 **12개를 직접 읽고 스스로 판정**해야 한다. 그것은 "즉시 발견"이 아니다.

> **확정: 첫 화면 최상단은 단일 판정 배너다.** 질문 *"이벤트가 제대로 쌓이고 있는가"* 에 **한 줄로 답한다.**
> 판정 근거 수치와 해당 화면으로 가는 이동 수단을 같은 줄에 둔다.

### 판정 배너의 우선순위 — 하나만 보여준다

| 순위 | 판정 | 상태 | 문구 예 |
|---|---|---|---|
| 1 | 계약 위반 존재 | `violation` | `✕ 계약 위반 3건 — 게시물이 기준을 누락했습니다` |
| 2 | 미실행 검사 존재 | `not_run` | `? 데이터 품질 검사 2건 미실행 — 통과로 볼 수 없습니다` |
| 3 | 거부 이벤트 존재 | `violation` | `✕ 거부 1,204건 — 사유별 보기` |
| 4 | 차단된 결손 존재 | `blocked` | `⚠ 차단된 결손 3건 — unit_cost · 배송비 필드 · pyarrow` |
| 5 | 게시물 없음 | `unconnected` | `○ 게시물이 없습니다` (+ 생성 안내 — **명령 미확정**, `missing-state-spec.md` L-4) |
| 6 | 출처 전부 미연결 | `unconnected` | `○ 수집된 이벤트 0건 — 커머스 미연결 · 시뮬레이터 미구현` |
| 7 | 정상 | `ok` | `✓ 수집 중 · 계약 위반 0건 · 거부 0건` |

> **규칙 F-1 — 배너는 항상 정확히 하나.** 여러 개를 쌓으면 판정이 아니라 목록이 되고, 목록은 첫 화면의 두 번째 블록부터 시작한다.
> **규칙 F-2 — 판정 배너에 "정상"을 쓸 수 있는 조건은 순위 1~6이 전부 비어 있을 때뿐이다.** 부분 정상을 정상으로 쓰지 않는다.
> **규칙 F-3 — `○ 수집된 이벤트 0건`(순위 6)은 `error`·`warning`을 쓰지 않는다.** `2026-09-11` 현재 이것이 **정상 상태**다(`Ecommerce #28` 미착수). 오류로 칠하면 실제 오류가 묻힌다.

**2026-09-11 현재 예상 판정: 순위 5 또는 6.** 게시물이 아직 없고 커머스 이벤트가 0건이다.

## 2.2 결과 화면군 8개를 어떻게 "자리만" 잡는가

A8 판정의 변경 **CH-2**: *"C1이 이후 사이클이 얹힐 껍데기까지 세운다 — 라우팅·레이아웃·토큰 파이프라인 연결. 그러지 않으면 결과 화면군을 만들 때 앱을 다시 만든다."*

> **확정: 사이드바에 `결과 (이후 사이클)` 그룹으로 8개 항목을 **보이게** 두고, 각 항목을 `planned` 상태로 렌더링한다.**
> 라우트 파일은 C1에서 만들지 않는다. 내비게이션 항목은 링크가 아니라 **비활성 항목**이며 사유를 가진다.
>
> ```
> 결과 (이후 사이클)
>   · Churn            계산 불가 · 모델 산출물 없음
>   · Cohort           계산 불가 · 모델 산출물 없음
>   · Uplift           계산 불가 · 모델 산출물 없음
>   · CLV              계산 불가 · 모델 산출물 없음
>   · Segment          계산 불가 · 모델 산출물 없음
>   · Optimization     계산 불가 · 비교 전략 없음
>   · A/B              계산 불가 · 비교 전략 없음
>   · Target List      계산 불가 · 모델 산출물 없음
> ```

**세 가지를 동시에 얻는다:**
1. **CH-2 충족** — 이후 사이클은 `app/churn/page.tsx`를 추가하고 비활성 항목을 링크로 바꾸면 된다. 앱을 다시 만들지 않는다
2. **A8 판정이 화면에 보인다** — "화면은 둘, 앱은 하나"가 사이드바 구조로 표현된다
3. **내비게이션 자체가 USP-1을 따른다** — 없는 화면을 숨기지 않고 `planned` 상태 + 사유로 표시한다. 상태 어휘가 지표에만 쓰이는 게 아니라 **화면 전체의 문법**이 된다

> **`Plan/DESIGN.md` 준수:** *"비활성 — `button-disabled` 색 또는 대응 컨트롤 색, **실제 비활성 동작 적용**. 필요한 이유는 주변 문구 제공."* 사유 문구가 그 "이유"다.
>
> **대안과 기각 근거:** ⑴ 빌드 전까지 숨긴다 → CH-2의 "껍데기"가 내비게이션에 남지 않아 이후 사이클이 IA를 새로 정한다. ⑵ 라우트를 만들고 "준비 중" 화면을 띄운다 → 8개 빈 라우트는 W6 리뷰·격리 검사 대상이 되며, 내용 없는 파일을 유지보수한다. **⑶ 비활성 항목(채택)** — 비용이 사이드바 8줄이다.
>
> **사용자·리드 결정 여지:** 사이드바 8줄이 C1 화면에 불필요한 소음이라고 판단하면 ⑴로 내린다. 그 경우 **IA 결정을 이후 사이클에 넘긴다는 점을 `design-handoff.md`에 한계로 적는다.**

## 4.2 보조 동선

| 독자 | 동선 | 무엇을 얻는가 |
|---|---|---|
| **P-시뮬** 다음 사이클 시뮬레이터 개발자 | `/` → `/fields` → `/metrics` | 무엇을 어떤 스키마로 기록해야 하는가. `missing_fields`와 `계산 불가` 지표가 **기록해야 할 목록**이다 |

**`/metrics`가 세 독자의 교차점이다.** USP-1 대표 장면을 여기 두는 이유이기도 하다.

### 이번 대조로 확인한 것 — 히어로 지표 충돌 없음

계약이 **계층 1·2 KPI에 `combined`를 스키마 수준에서 금지**한다(R-7). 리드가 판정 배너 설계와 충돌하는지 확인하라고 지시했다 — **충돌하지 않는다.**
- 판정 배너와 진입 카드가 쓰는 것은 **상태 건수**(`kpi_report.summary` · `checks[].status` · `items[].status`)이고 **계층 1·2의 합산 지표값이 아니다**
- 계층 0(수집 건전성)은 계약이 `combined`를 허용하므로 `events_ingested` 합계는 쓸 수 있다
- 내 설계는 **애초에 히어로 합산 지표를 두지 않았다**(규칙 S-3 · R-7). 첫 화면 최상단이 숫자가 아니라 **판정 한 줄**인 이유가 이것과 같은 방향이다

| 모델 지표 렌더링 (AUC·Qini·CLV) | **상태 어휘 8종** — `NEEDS_MODEL_OUTPUT`이 `available`로 바뀌기만 한다 |
| 실험 판정 (p-value·95% CI) | `inconclusive` 예약 슬롯 (`missing-state-spec.md` §4.4) |
| 증감·시계열 | V-11이 막아 둔 자리. 이력 보관 계약이 생기면 해제 |
| 트리거 5종 동작 | `/triggers`가 계획된 부재 표로 이미 존재 (T2.16) |

> **이 표의 요점:** 이후 사이클은 **상태 어휘를 다시 설계하지 않는다.** `NEEDS_MODEL_OUTPUT` → `available` 전환만으로 결과 화면이 켜진다. 상태 어휘를 C1에 제대로 만드는 것이 이후 사이클의 최대 절약이다.
