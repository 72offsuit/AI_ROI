# 1. ★ 코드 수준 함정 — JavaScript/TypeScript에서 가장 많이 깨지는 지점

**계약은 `status != "ok"`이면 `value`를 항상 `null`로 준다**(스키마가 강제). 그 `null`을 JS 관용구가 **조용히 0으로 바꾼다.** 화면이 USP-1을 어기는 가장 현실적인 경로가 이것이다.

## 1.1 금지 패턴 — 전부 0 채우기다

```ts
value ?? 0                      // ✕ null → 0
value || 0                      // ✕ null·0·"" 전부 → 0
Number(value)                   // ✕ Number(null) === 0
(value ?? 0).toLocaleString()   // ✕ "0"
value?.toLocaleString() ?? '0'  // ✕ "0"
counts[name] || 0               // ✕ 키 부재를 0으로 둔갑
parseFloat(value) || 0          // ✕
value.toFixed(1)                // ✕ null 에서 throw → 막으려고 위 패턴으로 도망간다
```

`(null).toLocaleString()`이 예외를 던지기 때문에 구현자는 **예외를 막으려고** `?? 0`을 쓴다. 그 순간 USP-1이 깨진다. **예외를 막는 올바른 방법은 분기지 기본값이 아니다.**

## 1.2 올바른 형태

```ts
// 게시물이 포맷까지 끝낸 문자열을 준다. 화면은 숫자를 포맷하지 않는다 (DB-012)
const EM_DASH = '—';                       // — U+2014. hyphen(-) 아니다
const display = m.status === 'ok' ? m.value_formatted : EM_DASH;
```

| 규칙 | 내용 |
|---|---|
| **`status`로 분기한다.** `value`의 falsy 여부로 분기하지 않는다 | `value === 0`은 **정직한 값**이다. `0`과 `null`을 같은 조건으로 묶는 모든 코드가 버그다 |
| **`value`를 숫자로 받아 포맷하지 않는다** | 통화·소수·천단위 결정은 계산이다(`DB-012`). `Plan/DESIGN.md`: *"디자인에서 새로 계산하지 않는다"* |
| **키 부재는 `0`이 아니라 계약 위반이다** | 계약이 `minProperties: 16`(event_type)·22 고정(필드)·`minItems: 9`(Lock)로 키 존재를 보장한다. 없으면 `violation` 칩을 띄운다 |

## 1.3 차트 라이브러리 함정

| 함정 | 결과 |
|---|---|
| 데이터 배열에 `null`을 넣으면 라이브러리가 **0으로 플로팅**하거나 **선을 이어버린다** | 없는 값을 만든다. 규칙 V-5 위반 |
| `filter(d => d.value > 0)` | **0건 항목이 조용히 사라진다.** 규칙 V-0 위반 |
| `partitions`에서 `present: false` 행을 빼고 차트에 넘긴다 | 수집 공백이 화면에서 사라진다 |

**올바른 형태:** 0건 날짜는 **막대를 그리지 않고** 1px 점선 윤곽 빈 슬롯 + baseline 틱으로 그린다. 선 차트를 쓰지 않는다 — 결손 구간에서 이으면 없는 값을 만들고, 끊으려면 라이브러리와 싸워야 한다. **막대를 택한 이유가 이것이다.**

# 2. 어기기 쉬운 시각 규칙 — 전부 "좋은 디자인처럼 느껨지는" 것들

아래 7개는 **선의로 어기게 된다.** 각 항목에 *왜 그렇게 하고 싶어지는지*를 같이 적었다.

## 2.1 ★ `—`를 작게·흐리게 만들지 않는다 (규칙 V-1)

> **가장 자주 깨질 규칙이다.** "화면이 시끄럽다 / 결손은 부차적이니 작게" 라는 판단이 자연스럽게 든다.

| | |
|---|---|
| **금지** | `—`를 값보다 작은 글자로 · `colors.text-muted`로 · `opacity`를 낮춰 · 이탤릭으로 |
| **확정** | `—`는 **대체한 값과 같은 타이포그래피 토큰·같은 크기·같은 자리**. 값이 `text-metric`(2rem/700)이면 `—`도 그렇다. 표에서는 `text-table-number` + **우측 정렬 유지** |
| 색 | **`colors.text-secondary`** (#525252, 흰 배경 **7.82:1**) |
| **`text-muted` 금지 범위** | `—` 값 슬롯 · 사유 문구 · 조치 줄. (`text-muted` 자체는 `Plan/DESIGN.md`가 허용한 용도 — 보조 배지·날짜 — 에서는 쓸 수 있다) |
| 왜 | `Plan/DESIGN.md`가 `text-muted`를 *"보조 배지, 날짜 등 부가 정보"* 로 한정했다. **결손은 부가 정보가 아니다.** 2rem 굵은 em dash는 시각적으로 무겁고, **무거워야 한다** |

## 2.2 ★ 결손을 숨기지·접지·기본 필터하지 않는다 (규칙 V-0)

> "계산 불가 19행은 너무 길다 / 기본으로 접고 토글을 주자" — **UX 개선처럼 보이기 때문에 가장 위험하다.**

| 금지 | 구체적으로 |
|---|---|
| accordion · "더 보기" · `<details>` 기본 닫힘 | 계산 불가 지표 · 0건 `event_type` · 결손 필드 · `notices[]` · 빈 출처 열 |
| 기본 필터 `status === 'ok'` | 기본값이 "정상만 보기"면 결손을 보러 온 사람이 결손을 못 본다 |
| 빈 커머스 열 접기/축소 | 전폭으로 남아야 프로젝트 실제 상태가 보인다. 접으면 "시뮬레이터만 있는 시스템"처럼 보인다 |
| **빈 상태 일러스트로 대체** | 이벤트 0건을 빈 상태 화면으로 **바꾸지 않는다.** 16종·47지표·품질 검사 목록을 **전부 그리고 전부 계산 불가로** 표시한다 — 그것이 USP-1 증명이다 |
| 정렬 기본값 = 건수 내림차순 | 0건이 항상 아래로 밀려 숨는 효과가 생긴다. **고정 순서**(스키마·정본 표 순서)를 기본으로 한다. 예외는 V3(충족률 오름차순 — 결손이 위) |

**1차 독자는 결손을 찾으러 오는 사람이다**(charter §7.1). 찾는 대상을 숨기는 화면은 쓸모가 없다.

## 2.3 ★ 상태 글리프를 생략하지 않는다

> "색으로 충분하다 / 아이콘이 번잡하다" — 그런데 **`gap`·`env_blocked`·`provisional`이 같은 `warning` 색이다.**

| 시각 상태 | 값 슬롯 | 선 | 글리프 |
|---|---|---|---|
| `gap` (근거의 공백) | `—` | **채움** | **⚠** 삼각 |
| `env_blocked` (환경 제약) | `—` | **점선 윤곽** | **⊘** 사선 원 |
| `provisional` (잠정값) | **숫자** | **실선 윤곽** | **◐** 반원 |

`provisional`은 **값 슬롯 자체가 다르다**(숫자 vs `—`) — 가장 강한 구분이다. `gap`/`env_blocked`는 **선 종류와 글리프로만** 갈린다.
→ **글리프를 빼면 흑백 인쇄·스크린샷 축소에서 두 상태가 구분되지 않는다.** 그리고 `Plan/DESIGN.md`가 *"색상만으로 의미를 전달하지 않습니다"* 를 금지한다.
→ **모든 글리프에 `aria-label`**(문구 전문). 아이콘은 장식이 아니다.

## 2.4 기준(basis)을 생략하지 않는다 (규칙 V-2·V-3)

> "카드가 길어진다" — 그런데 **기준이 "측정됨"의 유일한 증거다.**

```
0원
기준: coupon_use 1,204건 중 0건      ← "세어봤고 0이었다"의 증거
```

- **모든 `status: "ok"` 값은 기준을 동반한다.** 분모 · 모집단(`population`) · 기간(`window`) · 제외 인원
- **기준이 게시물에 없으면 `violation` 칩을 띄운다** — 값은 그리되 `기준 미표기 — 분모를 확인할 수 없습니다`
- `DB-012` 위반이 아니다: 지표를 계산하지 않고 **필수 필드의 존재 여부만** 본다

## 2.5 사유를 호버·툴팁에 숨기지 않는다 (규칙 V-9)

> "인라인이 지저분하다" — 그런데 **호버 상태는 스크린샷에 남지 않는다.**

US-11·US-13 인수조건이 **"스크린샷으로 증명"** 을 요구한다. **증명할 수 없는 상태는 증명 수단이 아니다.**
→ 사유 코드 · `reason_detail` · 기준 · 영향 · 조치는 **전부 상시 표시**. 호버는 보충에만(정본 문서 링크 등).
→ 부가로: 계산 불가 19개를 19번 호버하게 만드는 화면은 "즉시 발견"이 아니고, 호버는 터치·키보드에서 동등하지 않다.

## 2.6 증감·델타·스파크라인을 만들지 않는다 (규칙 V-11)

> "대시보드엔 전기 대비 증감이 있어야" — 그런데 **비교 기준이 없다.**

C1 게시물은 **단일 시점 스냅샷**이고 이력 보관 계약이 없다. `Plan/DESIGN.md`: *"없는 비교값을 생성하지 않습니다."*
→ `↑`·`↓`·`+12%`·스파크라인을 **렌더링하지 않고 슬롯도 두지 않는다.** 빈 증감 슬롯은 "변화 없음(0%)"으로 읽히고, **그건 0 채우기의 변종**이다.
→ PRD §71 트리거 5종이 전부 `↑`/`↓`를 전제하므로 **C1에서 작동하는 트리거는 0개**다. `/triggers`는 계획된 부재 표이고 **경보 UI·임계 입력·토글을 만들지 않는다.**

## 2.7 "전체" 히어로 지표를 만들지 않는다

> "대시보드라면 큰 숫자가 하나 있어야" — 그런데 **계층 1·2 KPI에 `combined` 키가 스키마 수준에서 금지**다(R-7).

출처를 섞으면 처치·통제 배정이 성립하지 않는다(`MEA-002`). 계층 0(수집 건전성)에서만 `combined`가 있다.
→ 계층 1·2는 **항상 출처 2열**(왼쪽 커머스 `◼ 실측` / 오른쪽 시뮬레이터 `◇ 생성`, **순서 불변**, 적층 시 커머스 위).
→ 합산을 표시할 때는 **제목에 `· 합산` + `합산` 칩.** 숫자만 내놓지 않는다.

# 3. 계약에서 파생되는 것 — 화면이 새로 판정하지 않는다

시각 상태는 계약 `(status, reason_code)`의 **순수 매핑**이다. 분기 로직을 화면이 발명하면 `DB-012` 위반이다.

| 계약 `status` | `reason_code` | 시각 상태 |
|---|---|---|
| `ok` | — | `measured` (측정된 0 포함) |
| `unconfirmed` | `PARAM_UNCONFIRMED` | `provisional` + **사용한 파라미터 표시** |
| `unavailable` | `NEEDS_TWO_STRATEGIES` · `NEEDS_MODEL_OUTPUT` · `PRECONDITION_MISSING` | `planned` |
| `unavailable` | `NO_SOURCE_EVENT` | `unconnected` |
| `unavailable` | `NO_COST_BASIS` · `MISSING_FIELD` | `gap` |
| `blocked` | `BLOCKED` | `env_blocked` |
| `not_run` | `NOT_RUN` | `not_run` |
| (화면 자기 검사) | — | `violation` |

**추가 규칙 3개:**
- **`not_run`을 `pass`로 표시하지 않는다** (계약 R-5 · AGENTS.md). 값 슬롯에 `—`가 아니라 글자 **`미실행`** 을 쓴다 — `—`는 "없음", `미실행`은 "모름"이다
- **`gate_result: "incomplete"`에 `success` 토큰을 일절 쓰지 않고 "통과"를 단독으로 쓰지 않는다.** 문구는 `미완 · 통과 N / 미실행 M / 차단 K`
- **규칙 V-12 — `status == "pass"` ∧ `examined_rows == 0`이면 초록으로 그리지 않는다.** `공허한 통과 · 검사 대상 0행` + `scope` 인라인. `✓`도 쓰지 않는다. (`scope`가 산문으로 경고하지만 **산문은 색을 이기지 못한다**)

# 5. 보안 — 거부 레코드의 값을 렌더링하지 않는다

`rejected.jsonl`에는 `validate_event()`가 거부한 레코드가 **원문 그대로** 있고(`sink.py:203-206`), 거부 사유 중 하나가 *"측정 계층을 통과할 수 없는 필드"* — 즉 **Hidden Trait·τ·Potential Outcome이 담긴 레코드가 거기 남는다.**

> **V2 거부 샘플은 `offending_fields`(필드 **이름**만)를 쓰고 값을 일절 렌더링하지 않는다.**
> 계약이 화이트리스트(`event_type`·`partition_date`·`source`·`problems`·`offending_fields`)만 게시하고 `additionalProperties: false`로 강제한다. **화면도 그 목록 밖을 그리지 않는다.**
> 필드 이름으로 거부 사유를 이해하기에 충분하고, 충분하지 않더라도 **누수 경로를 열 근거는 되지 않는다.**

# 6. ★ fixture 규칙 — 리드 판정 J-1 추가 조건 (2026-09-11)

USP-1 대표 장면(`revenue`는 값 / `contribution_profit`은 `계산 불가 · 원가 근거 없음`)을 C1에서 증명하는 방법은 **fixture**로 확정됐다. 다만 조건이 붙는다.

> ### fixture는 **손으로 쓴 게시물 JSON이 아니라, 실제 측정 계층 파이프라인을 통과한 산출물**이어야 한다.

| 방식 | 스크린샷이 증명하는 것 |
|---|---|
| 손으로 쓴 게시물 JSON → 화면 | **화면이 그 JSON을 그릴 수 있다**는 것뿐 |
| **합성 이벤트 → 실제 Sink → 실제 게시 → 화면** | **파이프라인이 실제로 계산 불가를 판정하고 게시한다**는 것 |

**USP-1은 "화면이 회색 칩을 그릴 수 있다"가 아니라 "측정 계층이 계산 불가를 계산 불가로 말한다"다. 후자만 그것을 증명한다.**

- 합성인 것은 **입력**이고 **파이프라인은 진짜**다 → 배지 문구 `표본 데이터 — 실측이 아닙니다`가 정확하다 (파이프라인이 가짜라는 뜻이 아니라 **입력이 합성**이라는 뜻)
- **`표본 데이터` 배지는 타협 불가다.** 표본을 실측처럼 보이게 하는 것은 이 설계가 금지하는 바로 그 행위다
- 게시물 JSON을 손으로 써서 `public/` 이나 테스트 픽스처에 넣고 스크린샷을 찍는 **지름길을 쓰지 않는다.** 그렇게 찍은 스크린샷은 US-13 인수조건을 충족하지 않는다
- 필요한 합성 입력: `unit_cost`가 없는 `purchase` 이벤트 1건 이상. 그러면 `revenue`는 `ok`, `contribution_profit`은 `unavailable`+`NO_COST_BASIS`가 **파이프라인에서** 나온다

# 7. 자기 검사 — 화면이 게시물 계약을 검사한다

`DB-012` 위반이 아니다. 지표를 계산하지 않고 **필수 필드의 존재·정합성만** 본다.

| 조건 | 렌더 |
|---|---|
| `contract_version`이 다르다 | **렌더링하지 않고** `계약 버전 불일치`를 표시 (계약 R-6) |
| 산출물 `run_id` ≠ `index.json`의 `run_id` | `게시가 진행 중이거나 불일치`. **화면으로 들어가지 않게 막는다** (계약 §6.2) |
| `status: "ok"`인데 기준이 없다 | 값 + `violation · 기준 미표기` |
| `status != "ok"`인데 `value`가 `null`이 아니다 | `—`로 렌더 + `violation · 계산 불가 상태에 값이 왔습니다` |
| `gap`·`env_blocked`·`not_run`·`violation`에 조치가 없다 | `조치 미정`이라고 **쓴다.** 빈칸으로 두지 않는다 — 빈칸은 "조치 필요 없음"으로 읽힌다 |
| 계약이 보장한 키가 없다 (16 / 22 / 9) | `violation · 계약이 보장한 키 누락` |
| Lock 항목이 `PARTIAL`인데 `scope_note`가 없다 | `violation · 범위 한정 문구 누락` |
| `index.json`이 없다 | 빈 화면을 그리지 않고 **게시 방법을 안내** (계약 R-7 · `DB-013`) |

**빈 상태 안내 확정 문구** — 실행 가능한 것처럼 제시하지 않는다:
```
○ 게시물이 없습니다
  측정 계층이 아직 산출물을 게시하지 않았습니다. 게시가 필요합니다.
  게시 명령은 W5-A 에서 신설됩니다 — 2026-09-11 현재 실행할 수 없습니다.
```
