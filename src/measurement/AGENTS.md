# `src/measurement/` — 창구 (Measurement Layer)

시뮬레이터와 의사결정 시스템이 만나는 **유일한 지점**이다. 실제 서비스 UI도 같은 스키마로 여기에 기록한다.

## 이 파트의 규칙

- **아무것도 import하지 않는다.** `src.simulator`, `src.decision`, `src.diagnostics` 전부 금지. 창구가 한쪽에 의존하면 계약이 아니게 된다.
- 여기 정의된 스키마·KPI·경제 규칙이 **양쪽의 계약**이다. 한쪽 편의를 위해 바꾸지 않는다.
- **GATE 1 이후 스키마를 변경하지 않는다.** 변경하면 이미 생성된 데이터와 학습 결과가 전부 무효가 된다.

## 여기에 흘러도 되는 것 / 안 되는 것

| 흘러도 됨 | 흘러서는 안 됨 |
|---|---|
| 고객이 언제 무엇을 보고 담고 샀는지 | `hidden_trait` (쿠폰 민감도, 이탈 성향 등) |
| 세션 길이, 페이지 뷰, 검색 횟수 | 처치 효과 `τ_i` |
| 쿠폰 노출·클릭·사용 기록 | Potential Outcome `Y(0)`, `Y(1)` |
| 주문 금액·상품·수량 | `persona` 라벨 |

**판단 기준: 실제 서비스에서 로그로 남을 수 있는 것만 통과한다.** 실제 커머스가 "이 고객의 쿠폰 민감도는 0.85"를 알 수 없다면, 여기에도 없어야 한다.

## 파생 상태 이벤트

`inactive` · `at_risk` · `churn` 상태는 기록하되, **Feature로는 사용 금지**다 (라벨과 동어반복). 대시보드 표시와 코호트 분석 전용이다.

## 검증

스키마를 바꾸면 `tests/test_isolation.py`와 데이터 품질 검사(`docs/data_spec.html` §9)를 함께 실행한다.
