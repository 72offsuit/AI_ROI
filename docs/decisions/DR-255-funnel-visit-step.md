# DR-255-funnel-visit-step — 퍼널 방문 단계를 `session_start ∪ return_visit` 으로 센다

| | |
|---|---|
| 태스크 | 이슈 255 · 관련 252 · 256 |
| 작성 | 인성(시스템 팀 리드, 에이전트 구현) · 2026-11-02 |
| 상태 | ① 이슈 본문의 제안대로 구현했다(사용자 지시 2026-11-02 "255 시작해줘") · ② 직렬화 형식은 이 기록이 고른 것이고 PR 리뷰에서 확정한다 |

## 무엇을 정하는가

1. 퍼널의 방문 단계를 무엇으로 여는가. `session_start` 만 받는가, `return_visit` 도 받는가.
2. 한 단계가 이벤트 유형 여럿을 받으면 `funnel.json` 단계 행에 그것을 어떤 형식으로 싣는가.

## 정하지 않으면 무엇이 막히나

#252(sim-0.8)부터 시뮬레이터는 구매 뒤 첫 방문 세션을 `session_start` 대신 `return_visit` 으로 연다(data_spec §3.4 ④ · DR-198). 방문을 `session_start` 로만 세면 그 세션의 조회 · 담기 · 결제 시작 · 구매가 순서 퍼널에서 모두 빠진다. 그래서 `funnel.json` 의 기간 창(`t1_to_t2`)에서 재구매 고객이 사라진다.

재현: 1일차에 첫 구매, 10일차에 재구매하는 합성 고객 1명, 창 [1/5, 1/20). 고치기 전에는 `[0, 0, 0, 0, 0]` 이었다(`tests/test_experiment_analytics.py` `TestFunnelReturnVisit`). 고치기 전까지 그 퍼널 수치는 발표 · 판정에 쓸 수 없다.

## 선택지

**① 방문 단계**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 방문 = `session_start` ∪ `return_visit`. 단계마다 이벤트 유형 목록을 둔다 | `return_visit` 이 "함께"(커머스)든 "대신"(시뮬레이터)이든 맞는다. #256 결정과 무관하다. 고객별 첫 도달 시각만 쓰므로 둘을 함께 남기는 출처도 이중 계산이 없다 | 단계 행의 형식이 바뀐다 |
| B | `session_start` 만 유지하고, `return_visit` 으로 열린 세션에 `session_start` 를 읽는 쪽에서 보충 | 퍼널 코드는 그대로다 | 관측 이벤트를 측정 계층 밖에서 만들어 넣는다. 출처마다 분기해야 한다 |
| C | #256 결정까지 기다린다 | 한 번만 고친다 | 그동안 기간 퍼널을 쓸 수 없다. 어느 정의로 정해지든 A 가 맞으므로 기다려서 얻는 것이 없다 |

**② 단계 행의 이벤트 유형 형식**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ②-1 | 키 `event_types`, 항상 목록 | 형식이 하나다 | 키 이름이 바뀐다 |
| ②-2 | 키 `event_type` 유지, 하나면 문자열 · 여럿이면 목록 | 기존 키를 유지한다 | 같은 키의 타입이 행마다 달라 소비처가 분기해야 한다 |
| ②-3 | 키 `event_type` 에 `"session_start\|return_visit"` 같은 문자열 | 타입을 유지한다 | 구분자가 계약에 없고 소비처가 다시 파싱해야 한다 |

## 조사한 것

| 출처 | 무엇을 말하나 | 우리 맥락에 얼마나 맞나 |
|---|---|---|
| #255 본문의 재현(main `6260f39`) | 시뮬레이터 방식 고객은 모든 단계 0, 커머스 방식 고객은 모든 단계 1 | 이번에 테스트로 고정했고 결과가 같다(main `80b1446`) |
| `docs/data_spec.html` §3.4 ④ · `DR-198-aux-events.md` | 구매 뒤 첫 방문 세션의 시작 이벤트는 `session_start` 대신 `return_visit` | 공개 문서다. 시뮬레이터 코드는 읽지 않았다 |
| 커머스 `event-log.ts` 276–278행(#255 본문 인용) | 이전 세션이 있는 고객의 새 세션마다 `session_start` 와 `return_visit` 을 함께 남긴다 | #255 본문 기준이다. 이번에 커머스 저장소를 다시 열지 않았다 |
| 소비처 `git grep`(main `80b1446`) | `funnel.json` 을 쓰는 곳은 `src/decision/analytics_report.py` 뿐이다. `dashboard/src` · `e2e` · `docs` 에 읽는 곳이 없다 | 키 이름을 바꿔도 깨지는 소비처가 없다 |

## 결정

- **① = 안 A.** `FUNNEL_STEPS` 의 각 단계가 이벤트 유형 튜플을 갖고, 방문 = `("session_start", "return_visit")` 이다. 단계 도달 시각은 그 유형들 가운데 가장 이른 이벤트 시각이다.
- **② = ②-1.** 단계 행의 키를 `event_types`(항상 목록)로 바꾼다. `steps` 인자에 문자열 하나를 넘기면 `TypeError` 다. 문자열은 글자 단위로 쪼개져 조용히 0 이 되기 때문이다.

**근거:** 퍼널은 고객별 첫 도달 시각만 쓰므로, 방문을 합집합으로 열어도 두 이벤트를 함께 남기는 출처에서 고객이 두 번 세지지 않는다(`test_session_start_with_return_visit_is_one_visit`). 따라서 A 는 #256 이 어느 정의로 정해지든 맞다. ②는 소비처가 하나뿐이고 그 소비처는 값을 그대로 쓰므로, 타입이 하나인 형식이 가장 단순하다.

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| B (보충 이벤트) | 관측 이벤트를 의사결정 계층에서 가공하는 것이다. 측정 계약 밖에서 이벤트를 만들면 출처 추적이 흐려진다 |
| C (#256 대기) | A 가 #256 의 세 안(A · B · C) 모두에서 맞으므로 기다릴 이유가 없다. 기다리는 동안 기간 퍼널을 쓸 수 없다 |
| ②-2 (키 유지 · 타입 혼합) | 행마다 타입이 다르면 소비처가 매번 분기한다. 지금 소비처가 하나라 키 변경 비용이 가장 낮은 때다 |
| ②-3 (구분자 문자열) | 구분자가 계약에 없다. 다시 파싱해야 하는 값은 목록보다 나을 것이 없다 |

## 이 결정이 틀렸다면 어떻게 드러나나

- 커머스 데이터로 만든 `funnel.json` 의 방문 n 이 이 수정 전후로 달라지면, "커머스는 모든 세션에 `session_start` 가 있다"는 전제(#255 본문)가 틀린 것이다.
- #256 이 `return_visit` 을 세션 없이도(세션 밖에서) 남기는 정의로 정하면, 그것을 방문으로 세는 것은 틀린다. 그때 이 결정을 다시 본다.
- 시뮬레이터 데이터에서 방문 n 은 늘었는데 상품조회 이후 단계가 거의 늘지 않으면, `return_visit` 으로 열린 세션 뒤에 여정이 이어지지 않는 것이다. "재구매 여정이 빠진다"는 진단부터 다시 본다.

## 민감도

- 커머스 데이터: 첫 세션 뒤의 세션마다 `session_start` 가 함께 있으므로 결과가 그대로다(테스트로 확인).
- 시뮬레이터 sim-0.8 데이터: 기간 창에서 `return_visit` 으로 세션을 연 재구매 고객만큼 방문 이후 단계가 늘어난다. 관측 전 구간(`overall`)은 고객의 첫 세션이 `session_start` 이면 그대로다. 실제 데이터로 얼마나 바뀌는지는 측정하지 않았다(아래).

## 남은 불확실성

- 실제 sim-0.8 데이터로 `funnel.json` 전후를 비교하지 않았다. 시스템 팀 에이전트는 시뮬레이터를 돌리지 않는다. 합성 이벤트 테스트로만 확인했다.
- `return_visit` 의 정의(언제 남기는가, `session_start` 와 함께인가)는 #256 에서 정한다. 이 수정은 그 결정과 무관하게 맞도록 했다.
- 이벤트 수를 그대로 세는 소비처(`sprint_table` 의 `return_visit_count_60d`, `churn_dl` 의 `visit` 채널)는 출처마다 값의 뜻이 다르다. 이 수정 범위 밖이고 #256 에서 다룬다.
- `src/measurement/schema.py` 의 `OBSERVABLE_METRIC_SOURCES["session_duration"]` 에 `return_visit` 이 없는 점(#255 "같이 볼 것")은 고치지 않았다. GATE 1 정본(봉인 해시 대상)이라 따로 결정해야 한다.
