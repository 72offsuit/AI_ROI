## 무엇을 정하는가

이탈(Churn) 모델과 Uplift 학습 방법을 **어떤 점수로 고르는지**, 보조 지표가 선택에 어떤 역할을 하는지, 그리고 그 기준 · 후보별 선택 점수를 CLI 요약 · 결과 파일 · 대시보드에 어떻게 보이는지. GATE 3 에서 이 규칙으로 고른 모델을 동결한다.

## 정하지 않으면 무엇이 막히나

- **GATE 3 동결 조건**(sprint_plan §6)이 "모델 선택 DR"을 요구한다. 기준이 문서로 고정되지 않으면 동결 뒤에도 "다른 점수로 보면 다른 모델"이라는 질문에 답할 수 없다.
- 11/17 멘토링 시연에서 CLI 요약이 무작위 5-Fold CV ROC-AUC 만 찍어 "랜덤 포레스트 점수가 더 높은데 XGBoost 가 확정"처럼 읽혔다. 선택은 의도대로(시간 순서 검증)였지만 화면이 선택 점수를 보여주지 않았다(#303 본문).
- #317(ML · LSTM 비교)도 같은 1차 기준(시간 순서 검증 ROC-AUC)과 보조 기록(상위 20% 리프트 · 보정)을 쓴다. 둘이 다르면 앙상블과 단일 모델의 선택 근거가 엇갈린다.

## 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 1차 = 시간 순서 검증 ROC-AUC 최댓값. 보조(상위 20% 리프트 · ECE · Brier)는 같은 데이터에서 싣고 선택을 바꾸지 않는다 | DR-215 그대로 — 결과를 보고 기준을 옮기지 않는다. 한 숫자로 재현된다 | 리프트 · 보정이 나쁜 모델이 뽑힐 수 있다 |
| B | 가중 합(ROC-AUC · 리프트 · ECE) | 여러 지표를 함께 본다 | 가중치에 근거가 없다. 결과를 본 뒤 가중치를 고르기 쉽다 |
| C | 1차 = 상위 20% 리프트 | 캠페인 대상 비율과 직접 이어진다 | 대상 비율에 민감하고 표본이 작으면 흔들린다. 예산(전략)이 대상 수를 정하므로 20% 가 운영 비율이라는 근거가 없다 |
| D | 무작위 교차검증 평균 | 표본을 다 쓴다 | 같은 t1 데이터로 튜닝 · 비교해 낙관적이고, 시간 분할 과제의 질문(미래 고객에 맞나)에 답하지 않는다 |

| SRS ML-009 · ML-011 · AT-ML-03, PRD §38.1 | 혼동행렬 · 상위 10/20/30% 리프트 · 포착률 · 확률 분포를 낸다. 선택 기준 · 후보별 선택 점수를 무작위 CV 와 구분해 표시한다. 선택 점수 최댓값 후보 = `best_proposed` | 표시 요구와 인수 시험 |
| 산업체 멘토 피드백(11/13 · 11/17) | ROC-AUC 만으로는 채택 근거가 부족하다 — 여러 지표를 함께 보고, 어떤 근거로 골랐는지 기준이 탄탄해야 한다 | 보조 지표를 **함께 싣는** 근거. 무엇을 1차로 할지는 말하지 않았다 |
| `src/decision/churn.py` 현재 동작 | `selection_basis` · `selection_metric` 은 이미 결과 파일에 있고, CLI 요약(`src/main.py`)이 무작위 CV 점수만 찍는다 | 결함은 선택이 아니라 표시 |

## 결정

**이탈 모델(안 A).**
- 1차: 시간 순서 검증 ROC-AUC(앞 기준일 t_prior 로 학습 → t1 학습 모집단에서 평가) — 제안 모델 중 최댓값. 동점이면 후보 순서(random_forest → hist_gb → xgboost → lightgbm)가 앞선 모델.
- 보조: 상위 20% 리프트 · ECE · Brier — 선택과 같은 데이터에서 후보마다 싣고 **선택을 바꾸지 않는다**. 고른 모델이 보조 지표에서 크게 뒤지면 그 사실을 보고서에 적는다.
- 쓰지 않는 것: 무작위 교차검증(시간 순서 검증이 있을 때는 참고) · 시간 홀드아웃(t2) · 과제 Test · Final Holdout.
- 앞 기준일 데이터가 없으면 무작위 CV 평균으로 고르되 **개발 실행용**으로 표시한다(`selection.official = false`). GATE 3 정식 선택은 `official = true` 인 실행에서만 한다.
- **정식(`official = true`) = 시간 순서 검증 그리고 ROC-AUC.** 설정(`tuning.metric`)이 허용하는 다른 지표(PR-AUC)로 고른 실행은 시간 순서 검증이어도 `official = false` 이고, `official_reason` 에 설정 지표를 · `official_criterion` 에 정식 기준을 적는다. 설정이 허용하는 것과 정식 기준은 다르다 — 고르는 알고리즘(최댓값 · 동점 순서)은 그대로다.

**Uplift.** DR-217-uplift-tuning 그대로 — train 안 Validation Qini 로 메타러너 × 규제를 고르고, Test 지표는 고른 뒤 보고만 한다.

**표시(ML-011).**
- 결과 파일: `churn_eval.selection`(규칙 · 기준 이름 · 후보별 `selection_score` · `rank` · 보조 지표 · 참고 `random_cv_score` · `official` · `official_reason` · `official_criterion`)과 `churn_eval.selection_report`(고른 모델의 ML-009 지표, 선택에 쓴 데이터에서).
- **표시는 실제 선택 기준을 따른다.** 시간 순서 검증으로 고른 실행은 무작위 CV 를 "참고 · 선택에 쓰지 않음"으로 따로 싣는다. 무작위 CV 로 고른 실행은 그 점수가 곧 선택 점수라 "참고" 줄 · 열이 없고, "정식 선택이 아니다"와 이유를 적는다. `selection` 블록이 없는 이전 판(#303 이전) 결과는 그 결과의 `selection_basis` · `selection_metric` 과 모델별 점수로 `selection_record` 와 같은 규칙의 블록을 다시 만들어 같은 형식으로 적는다 — 시간 순서 검증이면 모델별 `temporal_validation`, 무작위 CV 면 CV 평균의 그 지표가 선택 점수이고, 선택 대상은 제안 모델(`kind = proposed`)뿐이라 기준선은 "선택 대상 아님"으로 따로 적는다. 정식 여부도 같은 규칙(시간 순서 검증 ∧ ROC-AUC)이다. 값이 없는 후보만 결손으로 적고, 기준이나 지표가 결과에 없으면 어느 점수로 골랐는지 추정하지 않고 "알 수 없다"고 적는다. 이전 판에는 보조 지표가 없어 화면에서 그 열을 싣지 않는다.
- CLI 요약: 1행에 선택 기준, 2행에 제안 모델별 선택 점수와 확정 모델, 기준선은 "선택 대상 아님", 무작위 CV 는(시간 순서 검증으로 고른 실행에서) "참고 · 선택에 쓰지 않음" 줄에만. Uplift 는 Validation Qini 와 참고 Test Qini 를 나눠 적는다.
- **Uplift 학습 방법이 정해진 방식을 넷으로 나눈다**(기존 메타데이터만 읽는다): 선택(`best_method_selection.best_method` 있음 — 표는 고른 규제의 메타러너별 Validation Qini, 메타러너 × 규제 격자 전체는 `tuning.grid`. "메타러너 × 규제를 함께 골랐다"와 격자 설명은 `tuning.grid` 가 있을 때만 — 규제 후보가 하나(`tuning.enabled = false`)면 메타러너만 골랐다고 적고 선택 기준 줄도 "메타러너만(규제 후보 1개로 고정)"으로 적는다 — #320 재리뷰 전 결정 모듈은 후보 수와 무관하게 기준 문구에 "메타러너 × 규제를 함께"를 남겼으므로, 저장된 결과는 기준 문구 앞부분(Validation 비율 · arm)만 살리고 뒷부분을 바꾼다. 규제 튜닝 전(#294 이전) 결과처럼 `tuning` 이 없으면 메타러너를 골랐다는 것과 규제 선택 기록이 없다는 것만 적는다), 선택 불가(`best_method` 없음 · `tuning_report.selection_ok = false` — 실행 루프가 기본 학습 방법을 쓰고 `selection_reason` 을 적는다), 불러온 모델(`model_source` · `loaded_from` — 이 실행에서 고르지 않음), 기록 없음. 선택이 아니면 "Validation Qini 로 골랐다"고 쓰지 않는다.
- 대시보드: 이탈 화면 "모델 선택" 절(기준 · 확정 · 후보별 선택 점수 표, 무작위 CV 참고 열은 시간 순서 검증으로 고른 실행에만), 교차검증 표의 설명도 선택 기준을 따른다. Uplift 화면 "모델 선택" 절은 위 네 상태에 따라 설명을 바꾸고 선택일 때만 Validation Qini 표를 싣는다. 기존 표는 "Test(선택 뒤 보고만)".

**ML-009 지표.** `classification_report` — 운영 임계의 혼동행렬 · 상위 10/20/30% 리프트 · 포착률 · 확률 분포(10구간 고객 수). 시간 순서 검증(후보별) · 고른 모델(`selection_report`) · 시간 홀드아웃에 싣고, 교차검증 요약에도 상위 20 · 30% 리프트와 포착률 평균을 더한다. 규칙 기준선은 점수가 확률이 아니라 확률 분포를 싣지 않는다.

**노출 기록(실행 순서대로).** ① 11/12 예행 실행(`SP-20261112-134424-95f2164e`) — 후보별 무작위 CV 점수를 CLI 요약에서 봤다. DR-215 가 1차 기준을 정하기 **전**이다. ② 11/13 DR-215-churn-tuning — 1차 기준을 시간 순서 검증 ROC-AUC 로 정했다. ③ 11/16 예행 실행 · 11/17 시연 — 후보별 점수(시간 순서 검증 · 무작위 CV)를 다시 봤다. ④ 11/24 이 기록 — DR-215 의 기준을 바꾸지 않고 그대로 고정한다. 점수를 여러 번 본 뒤라 기준을 옮기지 않고(안 B · C 기각), 보조 지표의 역할을 "선택을 바꾸지 않는다"로 못 박는다.

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| B 가중 합 | 가중치 근거가 없고, 후보 점수를 이미 본 상태라 가중치를 고르는 것이 곧 결과를 보고 모델을 고르는 일이 된다 |
| C 리프트 1차 | 운영 대상 비율은 예산(전략)이 정한다 — 20% 를 1차로 삼을 근거가 없다. 리프트는 보조로 싣는다 |
| D 무작위 CV | 낙관적이고 시간 분할 질문에 답하지 않는다. 개발 실행의 대체 경로로만 남기고 그렇게 표시한다 |
| 화면에서 무작위 CV 표 삭제 | 멘토가 본 숫자를 지우면 "왜 다른 숫자가 있었나"를 설명할 수 없다. 남기되 "참고"로 표기한다 |

## 이 결정이 틀렸다면 어떻게 드러나나

- **1차 기준이 운영 목적과 어긋난다:** 고른 모델의 상위 20% 리프트가 2위 후보보다 낮고(시간 순서 검증) ECE 도 나쁘다 → ROC-AUC 만으로 고른 대가다. 보고서에 그대로 적는다. 기준을 바꾸려면 GATE 3 전에 새 결정으로 하고, 이미 본 점수를 노출 기록에 적는다.
- **시간 순서 검증과 무작위 CV 순위가 크게 다르다:** 선택 점수 1위가 무작위 CV 하위다 → 시간에 따른 분포 이동이 크다는 신호다. #304(기준일 이동 반복 검증)에서 기준일별 흔들림으로 확인한다.
- **표시가 다시 어긋난다:** CLI · 결과 파일 · 화면 중 하나가 선택 점수 대신 무작위 CV 를 "확정 근거"처럼 보인다 → AT-ML-03(`tests/test_churn_selection.py`)이 결과 파일 · CLI 쪽을 잡는다.

## 민감도

1차 점수 차가 작으면(예: ROC-AUC 0.005 미만) 선택은 사실상 동점이다. 순위가 바뀌어도 운영 차이는 작을 수 있다 — 그래서 보조 지표와 #304 의 기준일별 흔들림을 함께 싣는다. 규칙(최댓값 · 동점 순서)은 바꾸지 않는다.

- ML-010(관측 등급 · AI 세그먼트별 지표)은 #318 · #319 병합 뒤 다음 PR 에서 같은 `classification_report` 로 낸다.
