## 무엇을 정하는가

1. 이탈 모델을 **채택할 근거**로 무엇을 낼 것인가 — ROC-AUC 하나가 아니라 무엇을 함께 보나(멘토: "ROC-AUC 만으로는 부족").
2. 이진 판정 임계를 어떤 규칙으로 정하고, 그 근거를 무엇으로 보여 줄 것인가(ML-006 "임계값 비교표 + 비즈니스 목적 선택 근거").
3. 시간 홀드아웃(앞 시점 학습 → 뒤 시점 평가)을 **어느 고객**으로 잴 것인가(멘토: 학습 범위와 평가 범위가 다르다).
4. SHAP 을 어떤 모델 · 어떤 고객으로 그리고 설명할 것인가(FR-16).

## 정하지 않으면 무엇이 막히나

GATE 3 모델 동결(11/27)에 "왜 이 모델인가"를 말할 근거가 ROC-AUC 하나뿐이다. 멘토링(11/17)에서 같은 지적을 다시 받는다.
대시보드 Target List 는 "왜 이 고객인가"를 보여 줄 값이 없다(`shap_top` 은 전체 평균뿐).

## 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 보정 A | Brier + ECE(10 구간) + 구간표를 CV 지표에 더한다 | 순서(AUC)와 별개로 "확률이 맞는가"를 본다. 표준 지표 | class_weight 를 쓴 모델은 높게 나오는 것이 정상 — 해석 주석이 필요 |
| 보정 B | 보정 모델(CalibratedClassifierCV)로 확률을 고친다 | 확률이 실제 비율에 가까워진다 | 모델이 바뀐다 — 튜닝(2부)과 함께 정해야 한다 |
| 임계 A | F1 최대를 기본으로 두고 대안 행(상위 10/20/30% · 재현율 80% · 0.5)을 표로 낸다 | 현행 유지(위험 없음). 선택지를 보여 준다 | "비즈니스 목적"이 하나로 정해지지는 않는다 |
| 임계 B | 비용 기반 임계(기대 이익 최대) | 돈으로 말한다 | 임계가 지출을 정하지 않는 구조(아래)라 같은 값을 두 곳에서 정하게 된다 |
| 홀드아웃 A | Eligible(t2) ∩ t1 무처치 | 학습 모집단(Eligible(t1) ∩ RCT T0)과 같은 정의 | 고객 수가 줄어 불확실성이 커진다 |
| 홀드아웃 B | 지금처럼 Feature(t2) 전체 | 표본이 크다 | 학습 범위 밖 고객(최근 구매자 · 신규)이 섞여 AUC 가 부풀어 보인다 |

## 조사한 것

| 출처 | 무엇을 말하나 | 우리 맥락에 얼마나 맞나 |
|---|---|---|
| 산업체 멘토 피드백(2026-11-13, 비공개 문서 — 시뮬 팀 공유 금지) | ROC-AUC 만으로는 채택 근거가 부족, 시간 순서로 나눴다면 검증도 그렇게, 현업은 A/B · 오프라인 지표 · 책임자 판단으로 채택 | 그대로 반영했다. 시간 순서 검증은 2부 |
| Brier(1950) · Guo et al.(2017) ECE | 확률 예측의 정확도 · 보정 오차 | 표준 정의 그대로. 10 등간격 구간은 관례다 — 근거 있는 최적값이 아니다 |
| SRS ML-006 | 임계값 비교표와 비즈니스 목적 선택 근거 | 표와 선택 문장을 결과 파일(`churn_eval.threshold_table`)에 싣는다 |
| 저장소 구조(strategies · DR-145) | 쿠폰 대상은 전략이 점수 순서로 예산 안에서 고른다 | 그래서 churn 임계는 지출을 바꾸지 않는다 — 임계 B 기각의 근거 |
| 광진 5만 명 full 실행(11/12) | 시간 홀드아웃 범위가 Feature(t2) 전체(학습보다 넓다)이고 양성 비율이 학습과 크게 다르다 | 홀드아웃 A 의 근거. 수치는 여기 적지 않는다(두 팀 공용 문서) |

## 결정

1. **보정 = 안 A.** `churn._metrics` 에 `brier` · `ece` 를 더해 모든 교차검증 · 시간 홀드아웃 · 불러온 모델 평가에 같이 나온다. 확정 모델의 검증 fold 예측(OOF)으로 구간표 `churn_eval.calibration` 을 낸다. 규칙 기준선(`rule_recency`)의 점수는 확률이 아니라 순위라 보정 지표를 매기지 않는다(null).
2. **임계 = 안 A.** `predicted_label` 은 계속 **F1 최대**(학습 데이터 내부 OOF). `churn_eval.threshold_table` 에 F1 최대 · 확률 0.5 · 상위 10/20/30% · 재현율 80% 행의 임계 · 대상 비율 · 정밀도 · 재현율 · F1 을 싣는다. 표는 **학습 데이터 교차검증의 검증 fold 예측**으로만 만든다 — 시험 · 홀드아웃을 보지 않는다.
   **PR #280 리뷰 반영(2026-11-14).** ① 행마다 SRS ML-006 최소 비교 항목 `target_count`(임계 이상 고객 수 — **넘긴 학습 데이터의 CV OOF 기준**, t2 캠페인 대상 수가 아니다)와 `expected_campaign_cost` 를 싣는다. 비용은 이 표에 처치 · 단가 근거가 없어 **null + 사유**다(0 이나 임의 단가 없음) — **ML-006 은 부분 충족**이고, 남은 범위(임계별 비용)는 처치 · 단가가 정해지는 전략 단계와 연결할 때 채운다(`threshold_table.srs_ml006`). ② 표는 **고른 모델 종류의 바깥 CV OOF** 이고, 배치 객체의 임계는 `fit_best_churn` 이 전체 학습 데이터 **내부 OOF** 로 따로 정한다 — 같은 F1 최대 규칙을 다른 OOF 에 적용하므로 값이 다를 수 있다. 표에 `basis_model` 로 적고, 실행 루프가 배치 객체의 임계 · 규칙을 `churn_eval.deployed_threshold` 로 함께 남긴다.
   **근거(결과 파일에 같은 문장):** 이진 판정은 보고 · 위험 분포 표시에만 쓰이고, 실제 대상은 전략(S2~S5)이 예산 안에서 점수 순서로 고른다. 임계가 지출을 바꾸지 않으므로 정밀도와 재현율을 함께 보는 F1 최대를 기본으로 두고, 마케팅 수용량(상위 비율) · 놓치면 안 되는 비율(재현율)에 따른 대안을 표로 보인다.
3. **시간 홀드아웃 = 안 A.** 평가 고객 = Eligible(t2) 이면서 t1 실험에서 T1~T4 를 받지 않은 고객(T0 · 미배정). 라벨이 있는 전체 수와 제외 수(`n_labeled_all` · `n_excluded_not_eligible` · `n_excluded_rct_treated`)를 싣는다. 전체 고객으로 **다시 재지 않는다** — 확정 모델은 갈래마다 한 번만 평가한다(기존 계약 시험 `test_real_runner_uses_separate_main_windows_and_one_call_per_branch`). Eligible(t2) 가 없으면 not_run(전체로 대신하지 않는다).
4. **SHAP.** 다시 학습하지 않고 **배치될 확정 모델**(`fit_best_churn` 결과 · 불러온 모델)을 설명한다.
   - `shap_summary.png` — 학습 모집단 표본(최대 `shap_sample`)의 beeswarm, 결과 폴더에 함께 둔다. 실패해도 churn 단계는 이어 가고 `churn_eval.shap_summary` 에 사유를 남긴다.
   - SHAP Local — t2 점수 시점에 Eligible(t2) 안에서 이탈 확률 상위 200명, 고객마다 영향이 큰 Feature 3개와 방향(`raises_risk` · `lowers_risk`) → `churn_eval.shap_local`. **Eligible(t2) 가 0명이면 전체 고객으로 넓히지 않고 not_run**(PR #280 리뷰 N1). 후보를 정하지 않은 경우(None — purchase 를 만들지 않는 판)만 전체 점수 고객에서 고르고 `population: all_scored` 로 적는다.
   - **기여값의 단위는 모델마다 다르다**(PR #280 리뷰 N2) — TreeExplainer 기본 출력에서 기여 합 + 기대값이 RandomForest 는 **확률**, HistGB · XGBoost · LightGBM 은 **로그오즈**를 복원한다(실측 — XGBoost · LightGBM 은 #215 2부에서 추가, 시험 `test_shap_units_are_what_the_contributions_add_up_to`). 결과에 `shap_unit` 으로 싣는다 — 크기를 해석하는 화면은 이 값을 본다.
   - 그림에 `matplotlib==3.11.2`(개발 venv 판)를 `requirements.txt` 에 고정했다.
5. **모델 채택 기준(멘토 피드백, GATE 3 에 쓴다).** 아래 셋을 **모두** 만족할 때 채택한다. 하나라도 못 하면 단순 기준(규칙 · 로지스틱)을 쓴다.
   1. 무작위 실험(RCT)에서 처치 효과가 확인된다 — 이탈 모델이 쓰일 전략(S2~)의 전제다(`ab_test`).
   2. **학습에 쓰지 않은 데이터**(같은 범위의 시간 홀드아웃)에서 ROC-AUC · PR-AUC · Lift@10 이 규칙 기준선보다 낫고, 보정이 크게 어긋나지 않는다(ECE 를 함께 보고한다 — 판정 문턱은 2부에서 보정 여부와 함께 정한다).
   3. 전략 비교(가상 A/B — 같은 날 같은 고객 상태에서 갈라 진행)에서 규칙 기반 대비 이익 증가가 **seed 반복 실행에도** 유지된다(#220 · #226).

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| 보정 B(보정 모델) | 모델 자체가 바뀌는 결정이라 튜닝 · XGBoost/LightGBM(2부)과 함께 Validation 으로 정한다. 지금은 측정만 한다 |
| 임계 B(비용 기반) | 대상 선정은 전략과 예산이 한다 — 임계로 지출을 한 번 더 정하면 같은 결정을 두 곳에서 하게 된다 |
| 임계를 시험 · 홀드아웃에서 고르기 | 시험 데이터로 고르는 순간 시험이 아니다(`src/decision/AGENTS.md`) |
| 홀드아웃 B(전체 유지) | 학습 범위 밖 고객이 섞여 "학습에 안 쓴 같은 종류의 고객"에 대한 성능이 아니다 |
| 두 범위를 다 재기(전체는 참고) | 같은 확정 모델을 한 실행에서 두 번 평가하게 된다 — 범위 차이는 제외 수로 보인다 |
| SHAP 을 전체 데이터로 다시 학습한 모델로 | 배치되는 모델과 다른 모델을 설명하게 된다(기존 `churn_importance` 는 그렇게 한다 — 전역 순위 용도로 둔다) |

## 이 결정이 틀렸다면 어떻게 드러나나

- 같은 범위 홀드아웃의 표본이 너무 작아 지표가 실행마다 크게 흔들린다 → seed 반복(#220)에서 편차로 드러난다. 그러면 범위를 넓히지 않고 반복 수를 늘린다.
- 마케팅 수용량이 정해져(예: 상위 20%) F1 최대 임계와 크게 다르다 → 표의 해당 행을 기본으로 바꾸는 결정을 한다(이 DR 갱신).
- ECE 가 크고 전략이 확률 값 자체를 쓴다(S4 기대 이익 계산) → 2부에서 보정 B 를 채택한다.

## 민감도

- 보정 구간 수(10)를 ±20% 바꾸면 ECE 값이 조금 바뀌지만 모델 간 순서는 대개 같다 — 판단 지표가 아니라 보조 지표다.
- 상위 비율 행(10/20/30%) · 재현율 목표(80%)는 표의 행일 뿐이라 바꿔도 모델 · 지출이 바뀌지 않는다.
- SHAP Local 상위 200명은 화면 크기 상한이다 — 늘려도 결과 파일만 커진다.

## 남은 불확실성

- **로컬 BLOCKED:** 실제 시뮬레이터로 도는 오케스트레이션 테스트는 시스템 팀 로컬에서 돌리지 않는다. 시간 홀드아웃 범위 변경 · 그림 · 고객별 설명의 연결은 **CI 에서 확인**한다. 로컬에서는 시뮬레이터를 빈 가짜로 바꿔 보조 함수만 확인했다.
- 2부 — XGBoost · LightGBM · Validation 튜닝 · 시간 순서 검증(앞 시점 기준일로 학습 → t1 로 검증)은 아직이다. 채택 기준 ②의 ECE 문턱도 그때 정한다.
- 대시보드는 새 키(`threshold_table` · `calibration` · `shap_local` · 홀드아웃 제외 수)를 아직 그리지 않는다(#228).
