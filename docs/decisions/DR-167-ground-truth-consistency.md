# DR-167-ground-truth-consistency — 참 효과 형식 · 창 안 재배정 · 생성 성능 · 교환 묶음 커밋

|---|---|

| 작성 | 민정 · 2026-10-28 |
| 상태 | 제안 — 리뷰 성환 |

## 무엇을 정하는가

1. 참 효과(ground truth)를 어떤 형식으로 두고 어디에 그 형식을 적는가 — 문서(`src/simulator/_internal/AGENTS.md`)는 Parquet, 실제는 JSONL 이다.
2. 효과 창(42일) 안에서 같은 고객을 다시 배정하면 앞 배정의 참 효과가 관측과 어긋난다. 이것을 어떻게 드러내는가.
3. 20K × 600일 생성이 10분 목표(PR #160 실측 578.5초)에 여유가 작다. 무엇을 고치고 무엇을 넘기는가.
4. 교환 묶음 매니페스트 `source_commit` 에 판 이름(`sim-0.4`)이 들어가는 것을 계약(README §2 "생산 코드의 커밋")과 맞춘다.
5. #149 사후 리뷰의 사소 2건 — 가드레일 `ate_net_profit_krw` 내림 방향, `negative_response_trait_bp_reference` 이름.

## 정하지 않으면 무엇이 막히나

- **S8 채점(#224·#227)이 시뮬레이터 파일을 읽지 못한다.** 조사 중 확인한 결함이다. `src/diagnostics/report.py` 의 `GT_KEYS` 가 배정 팔을 `treatment_id`, τ 를 `tau` 로 찾는데 시뮬레이터는 `assigned` · `tau_purchase` 로 쓴다. 실제 파일을 넣으면 첫 행에서 `InputError` 다. 지금까지 합성 픽스처(`treatment_id` 키)로만 시험해 드러나지 않았다.
- GATE 1(스프린트 3) 봉인 뒤에는 참 효과 형식을 바꾸기 어렵다. 봉인 전에 형식과 그 정본 문서를 고정해야 한다.
- `simulator_commit` 은 FREEZE-003 대조 키다(`src/orchestration/AGENTS.md`). 교환 묶음이 판 이름을 커밋 자리에 실으면 같은 판 안의 코드 변경을 대조할 수 없다.

## 선택지

**참 효과 형식**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| F-A | JSONL 유지 · 형식을 `docs/simulator_api.md` 에 적고 `_internal/AGENTS.md` 를 고친다 | 시뮬레이터가 표준 라이브러리만으로 돈다(사용자 확정 U2, 3.10 무의존). 바뀌는 코드가 없다 | 큰 배정에서 파일이 Parquet 보다 크다 |
| F-B | Parquet 으로 바꾼다 | 문서 그대로 | pyarrow 가 시뮬레이터 필수 의존성이 된다 — U2 와 충돌 |

**창 안 재배정**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| R-A | 새 참 효과 행에 `supersedes`(끊긴 앞 배정의 시각 · 처치 · 끊기기 전 일수)를 싣고, 채점기가 파일마다 해당 행 수를 센다 | 기록만 늘고 동작 · 이벤트 · 골든이 그대로다. 채점 정책(뺄지)은 DR-S8 에 남긴다 | 소비자가 파일 사이를 맞춰 봐야 한다 |
| R-B | 효과 창 안 재배정을 `AssignmentError` 로 거부 | 어긋남이 생기지 않는다 | 공개 API 계약 변경. `T0` 으로 효과를 끝내는 기존 의미(#143)와 그 테스트를 깬다 |
| R-C | 앞 참 효과 파일을 다시 써서 끊긴 날 이후를 잘라낸다 | 한 파일만 보면 된다 | 이미 쓴 정답지를 고치는 경로가 생긴다. 잘린 창의 반사실은 다시 돌려야 한다(비용 · 정의 문제) |

**생성 성능**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| P-A | 실측으로 시간을 나눠 기록하고, 큰 몫(측정 계층)은 양 팀 합의 안건으로 넘긴다. 시뮬레이터 쪽은 바이트 동일을 깨지 않는 범위만 본다 | 계약 · 재현성을 건드리지 않는다 | 이 PR 로 시간이 줄지 않는다 |
| P-B | 시뮬레이터가 Sink 검증을 건너뛰는 경로를 만든다 | 빨라진다 | 측정 계약의 단일 관문을 우회한다 — 격리 원칙 위반 |
| P-C | 난수 체계(sha256 하나/추첨)를 바꾼다 | 엔진 몫이 준다 | 판 상향 · 골든 전면 교체. GATE 1 직전에 할 일이 아니다 |

**`source_commit`**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| C-A | 값을 계약에 맞춘다 — `git rev-parse HEAD`, 얻지 못하면 `null` + `null_reason`. 판 이름은 `simulator_version` 으로 따로 싣는다 | 시뮬레이터 팀 안에서 끝난다. 측정 계층 `repo_commit()` 과 같은 규칙 | 미커밋 변경은 드러나지 않는다 |
| C-B | 계약 문구를 "판 이름"으로 고친다 | 코드 변경 없음 | `docs/contracts/**` 는 `shared_read_only` — 한 팀이 단독으로 고치지 않는다. FREEZE-003 대조가 약해진다 |

## 결정

| # | 결정 (제안) |
|---|---|
| U1 | **F-A.** 참 효과는 JSONL. 행 형식의 정본은 `docs/simulator_api.md` 「참 효과 기록 형식」. `_internal/AGENTS.md` 표를 실제 경로 · 형식으로 고친다. 채점기 `GT_KEYS` 를 실제 키(`assigned` · `tau_purchase`)로 고치고, 파일 이름 정규식이 `world_id`(`W-` 뒤 16진수)의 하이픈을 견디게 한다 |
| U2 | **R-A.** 참 효과 행에 `supersedes` — 이 배정이 앞선 비-`T0` 처치의 효과 창 안이면 `{at, treatment_id, observed_days}`, 아니면 `null`. 채점 보고서는 파일마다 `superseded_rows` 를 싣는다. 채점에서 뺄지는 DR-S8(#224) |
| U3 | **P-A.** 실측 분해를 남긴다. 측정 계층 몫(59%)의 최적화는 시스템 팀과의 합의 안건으로 올린다(아래 "남은 불확실성"). 시뮬레이터 쪽은 이번에 바꾸지 않는다 |
| U4 | **C-A.** `source_commit` = 저장소 HEAD 커밋 또는 `null` + `null_reason.source_commit = PRECONDITION_MISSING`. `simulator_version` 필드를 더한다(읽는 쪽은 모르는 키를 무시한다 — `exchange.read_exchange`) |
| U5 | 가드레일 금액 평균을 `_bp` 와 같은 반올림(`_round_div`, 0.5 는 +∞ 쪽)으로. `_bp` 값은 정수 입력에서 이전과 같다(테스트로 대조). 참고값 이름을 `negative_response_customer_bp_reference` 로 — Negative 는 처치와 무관한 고객 단위 성향이라 T1 로 물은 값이 곧 고객 비율이다 |

**근거:** 형식 어긋남의 뿌리는 정본 문서에 형식이 없었다는 것이다. 형식을 적고 실제 파일로 채점기를 시험해 다시 어긋나지 않게 한다. 재배정 · 성능 · 커밋은 각각 공개 API · 측정 계약 · 공유 계약을 건드리지 않는 안을 골랐다. 그 셋은 GATE 1 직전에 한 팀이 단독으로 바꿀 것이 아니다.

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| F-B Parquet | 시뮬레이터 무의존 원칙(U2)과 충돌 |
| R-B 창 안 재배정 거부 | 공개 API 변경. `T0` 으로 효과를 끝내는 의미를 깬다 |
| R-C 앞 파일 다시 쓰기 | 정답지를 사후에 고치는 경로가 생긴다. 잘린 창의 반사실 정의가 새로 필요하다 |
| P-B 검증 우회 | 측정 계약의 단일 관문을 우회한다 |
| P-C 난수 체계 교체 | 판 상향 · 골든 전면 교체 — 봉인 직전 위험이 크다 |
| C-B 계약 문구 수정 | `shared_read_only` 단독 수정 금지, FREEZE-003 대조 약화 |

## 이 결정이 틀렸다면 어떻게 드러나나

- 채점기가 실제 참 효과 파일에서 `InputError` 를 내거나 `tau_mismatch` 가 0 이 아니면 U1 이 깨진 것이다 — `tests/test_simulator_ground_truth.py` 가 시뮬레이터가 쓴 파일로 확인한다.
- 창 안 재배정인데 `supersedes` 가 `null` 이거나, 창 밖(`advance(42)` 뒤 · 앞 배정 `T0`)인데 값이 있으면 U2 가 깨진 것이다(같은 테스트).
- 이미 드러났다: #243(sim-0.6)에서 20K × 600일이 **10.2분**으로 10분을 넘는다. 그래서 U3 의 측정 계층 안건은 "나중에"가 아니라 **스프린트 3 계획(10/29)에 올린다**. 그때도 합의가 안 되면 10분 목표 자체(출처가 PR #160 본문뿐이다)를 리드가 다시 정한다.
- 커밋을 얻을 수 있는 체크아웃에서 `source_commit` 이 `null` 이면 U4 구현 결함이다.

## 민감도

| 바뀌는 값 | 변화 | 무엇이 달라지나 |
|---|---|---|
| 고객 수 × 일수 | 2,000 × 300 → 20,000 × 600 | 이벤트 수에 거의 비례(측정 계층 몫도 이벤트당 비용이라 비율은 비슷하다고 본다 — 20K 에서 분해는 재지 않았다) |
| 효과 창 `window_days` | 42 → 다른 값 | `supersedes` 판정 경계가 따라 움직인다(같은 config 값을 읽는다) |

## 남은 불확실성

- **측정 계층 성능 안건(시스템 팀과 합의 필요):** `validate_event`(이벤트마다 필드 규칙 · 정규식) · `coverage.observe` · Parquet 쓰기가 `advance` 의 약 59%다. 생성 쪽이 이미 검증된 형태로 이벤트를 만든다는 전제로 검증을 묶음 단위로 바꾸는 안 등이 가능하지만, 측정 계약의 관문이라 이 DR 에서 정하지 않는다.
- #139(호출당 고정비 증가)는 닫혀 있다. 이 PR 에서 다시 재지 않았다 — 본선은 `advance` 를 T0 마다 몇 번만 부른다.
- `source_commit` 은 미커밋 변경을 드러내지 않는다. 봉인 실행은 깨끗한 체크아웃을 전제한다(FREEZE-003).
- `supersedes` 를 채점에서 어떻게 쓸지(제외 · 절단 · 그대로)는 DR-S8 몫이다.
