## 무엇을 정하는가

이슈 #75 "이어받는 생성" 절의 네 가지와 "미확정" 한 가지.

- `WorldState` 에 **무엇이 들어가나**, 각 항목이 **왜 상태인가**(창 경계에서 초기화되면 무엇이 깨지나)
- 상태 **판 관리** — 옛 상태를 어떻게 다루나
- `snapshot/restore` 와 `save_state/load_state` 의 **관계**
- **완전성 증명** — 연속 실행 ≡ 이어받기 등식을 무엇으로 비교하나
- **계보** — `run_id · parent_run_id · state_digest · window` 를 어디에 남기나, 출력 경로 일관성을 어떻게 확인하나
- 이슈 #75 "미확정": 내부 상태 표현(이벤트 로그 vs 스냅샷 트리) — S2 이후 바꾸지 않는다

## 결정

**사용자 결정 (2026-10-04 확정):** 3. `restore` 뒤의 쓰기는 호출자가 지정한 **빈** `output_root` 에만 허용. 이미 쓴 경로에 다시 쓰려 하면 오류. 자동 분기 경로 생성·메모리 전용 분기는 기각. 5. 카탈로그·주문 시점 원가는 `WorldState` 항목으로 **자리만** 확정(창 경계에서 원가가 바뀌지 않도록).

**사용자 결정 (2026-10-04 확인):** 본선 이어가기 — T0 에서 `save_state()` 와 `snapshot()` 을 모두 받고, 전략 분기는 `restore(snap, output_root=새 빈 경로)`, 본선은 `load_state(state_id, 본선 루트)` 로 잇는다. **런타임 정책** — Python 3.10 이상 모든 판에서 같은 seed 는 바이트 동일한 이벤트를 내고 상태 파일도 판을 넘어 읽힌다. 거부 조건은 `format_version`·`rng_scheme`·`simulator_version` 불일치로 한정하고, 저장·재개한 런타임은 계보 사이드카에 **기록만** 한다. 리드 기본값으로 확정: 커머스 이벤트와 시뮬레이터 이벤트를 한 Sink 루트에 섞지 않는다.

**사용자 결정 (2026-10-04 확인, R-1) — 3.10 호환 범위.** "`requirements.txt` 를 설치하면 모든 판(3.10 이상)에서 전 기능이 동작한다. 의존성이 없는 환경은 jsonl.gz 루트만 읽을 수 있다." 상태 파일과 생성은 판·의존성과 무관하게 같다. 관측(`events()`·`metrics()`)과 이어쓰기는 계보 루트의 저장 형식을 그 런타임이 읽을 수 있어야 한다 — parquet 계보를 pyarrow 없는 런타임에서 잇거나 관측하면 `SinkFormatError` 다(Matthias R-1 재현: 3.12 parquet 계보를 3.10 무의존성에서 새 루트로 이어간 세계의 `events()`). 근거: `requirements.txt:21` 이 고정한 `pyarrow==25.0.1` 은 PyPI 에서 `requires_python >=3.10` 이고 cp310~cp314 휠을 낸다(2026-10-04 PyPI JSON 으로 직접 확인). 대안 "시뮬레이터는 항상 jsonl.gz"는 사용자가 기각했다(아래 기각 표).

**상태 표현(이슈 #75 "미확정"의 답): 안 ②.** (2026-10-04 사용자 확인 결과에 따라 확정) 명시적 상태 객체, 정준 JSON 상태 파일(내용 주소), 실행마다 사이드카가 부모를 가리켜 디스크 위에 스냅샷 트리를 이룬다. 이벤트 로그는 **산출물이지 상태가 아니다.** 안 ①(재생)은 메커니즘이 아니라 **시험의 기준**으로 쓴다. S2 이후 고정되는 것은 이 표현 방식이고, 항목은 `format_version` 을 올리며 늘어난다.

**출력 체크포인트는 상태 다이제스트 밖에 둔다** (정정 2026-10-04, 아래 "정정" 항목). `output_root`·이 세계가 그 루트에 마지막으로 쓴 `run_id`·계보 머리 `run_id` 는 다음 쓰기가 어디에 이어지는지를 정하므로 반드시 보존하지만, **세계 내용이 아니다.** 두 곳에 둔다 — ① 프로세스 세션(활성 세계와 함께 들고 있는 출력 루트·루트 머리·계보 머리, 스냅샷 레지스트리 항목도 계보 머리를 상태 바이트 옆에 따로 든다) ② 계보 사이드카 `runs/{run_id}.json`(`output_root`·`window`·`start/end_state_digest`). 상태 파일과 `state_digest` 에는 세계 내용만 들어간다. 마지막 창은 사이드카 `window` 와 상태의 `now_ms` 로 충분하다.

**직렬화와 판.** 정준 JSON — `sort_keys=True`, `separators=(",", ":")`, `ensure_ascii=True`(바이트가 ASCII 뿐이라 인코딩 문제가 없다). **상태에 float 가 없다** — 시각·금액은 정수, 확률·비율은 정수 분수(`DR-S1-rng`). S2 의 Hidden Trait 도 정수 분수나 정수 척도로 싣는다. 고객 목록은 `customer_id` 순, 큐는 키 순으로 써서 힙 배열 배치가 바이트에 새지 않게 한다. `state_digest = sha256(정준 바이트)`, `state_id = "state-" + 다이제스트 앞 16자`. 읽을 때 **판 불일치·무결성·구조 위반**이면 `StateFormatError` 로 **거부**한다 — 변환하지도 추측하지도 않는다. 판 불일치는 `format_version`·`simulator_version`·`rng_scheme` 중 하나라도 다른 것, 무결성은 다시 정준화한 바이트가 파일과 같고 그 다이제스트가 `state_id` 와 맞는 것, 구조는 `decode` 가 모든 항목의 형태·타입·범위를 검사하는 것이다(정수 범위, `MAX_TIME_MS` 이하 시각, 고객 수 일치, 큐 항목 형태, profile 에서 유도되는 값과의 일치, 모르는 키 거부 등, `src/simulator/_internal/world.py:149-296`). 다이제스트는 누구나 다시 계산할 수 있으므로 무결성 검사만으로는 위조된 구조를 막지 못한다(Thomas L5 · Matthias D-2, 2026-10-04 리뷰 반영으로 범위를 넓혔다). **Python 판·플랫폼이 다른 것은 거부 사유가 아니다**(사용자 결정 2026-10-04).

**위치와 원자성.** 숨김 영역 `data/hidden/simulator/`(저장소 루트 기준, 테스트는 `hidden_root` 로 바꾼다) 아래 `states/{state_id}.json`. 같은 디렉터리의 임시 파일에 쓰고 `flush`·`fsync` 뒤 `os.replace`, 이어서 디렉터리를 `fsync` 한다. 실패하면 예외를 올리고 임시 파일을 지운다. **디렉터리 `fsync` (리뷰 반영 2차 — Thomas N5):** 이름 바꾸기가 성공한 뒤 디렉터리 `fsync` 가 `EINVAL`·`ENOTSUP`·`EBADF` 를 내면 실패로 보지 않는다 — 그 파일시스템(FUSE·CIFS 등)이 디렉터리 `fsync` 를 지원하지 않는 것이고, 파일은 이미 제자리에 있다. 다른 errno 는 실패다(`src/simulator/_internal/storage.py:27-41` · `:44-56`). 전원 손실 내구성(macOS 의 `F_FULLFSYNC`)은 이 DR 의 요구가 아니다(남은 불확실성). 내용 주소라 같은 상태를 두 번 저장해도 같은 파일이다.

**스냅샷과 저장 — 상태 정의 하나, 매체 둘, 계약 둘.**

| | `snapshot` / `restore` | `save_state` / `load_state` |
|---|---|---|
| 목적 | 한 실행 안에서 같은 시점·같은 난수로 여러 전략 비교 | 실행을 넘어 한 세계를 이어감(중단·재개) |
| 매체 | 프로세스 메모리(정준 바이트 그대로) | 숨김 영역 파일 |
| 수명 | 세계가 바뀌거나 `discard_snapshot` 까지 | 영구 |
| 이후 쓰기 | **빈 루트만**(사용자 결정 3) | 빈 루트, 또는 그 루트의 계보 머리가 **바로 이 상태에서 끝난** 경우만 |
| 아직 실행으로 기록되지 않은 상태 변경(`apply_treatment`) | 토큰과 함께 들고 가 `restore` 뒤 첫 실행의 사이드카 `mutations` 에 실린다 | 저장 시점에 남아 있으면 `derivations/` 기록에 실린다 |

둘은 같은 직렬화기를 쓴다 — 스냅샷이 저장보다 적게 담아 생기는 어긋남이 원리적으로 없다. 합치면 망가지는 것: 스냅샷을 파일로 하면 전략마다 Hidden Trait 이 담긴 큰 파일이 늘고, 저장을 메모리로 하면 프로세스를 넘는 재개(#91)가 안 된다. 무엇보다 **분기를 원래 루트에 이어 쓸 수 있게 되면** 전략 S2 의 42일이 본선 데이터에 붙는다 — #91 이 경고한 "이어받기가 전략 비교에 오염되는" 실패다.

**D9 루프가 본선을 이어가는 방법 (사용자 결정 2026-10-04).** `docs/data_spec.html:880-892` 의 `sim.restore(snap); sim.advance(campaign_interval_days)` 는 사용자 결정 3 아래에서 새 빈 루트를 요구한다. 그래서 본선은 `restore` 가 아니라 `load_state` 로 잇는다 — T0 에서 `state_id = save_state()` 와 `snap = snapshot()` 을 함께 잡고, 전략 분기는 `restore(snap, output_root=분기 루트)`, 본선 재개는 `load_state(state_id, 본선 루트)` 로 한다 — 본선 루트의 계보 머리가 바로 그 상태에서 끝났으므로 이어쓰기 검사를 통과한다.

**출력 루트 규칙.** "빈" = 경로가 없거나 항목이 하나도 없는 디렉터리. `init` 은 빈 루트만. 시뮬레이터는 **자기 루트에만** 쓰고 커머스 이벤트와 섞지 않는다.

- **쓰기 전 무결성 (fail-closed, 2026-10-04 리뷰 반영 — Thomas H1).** 비어 있지 않은 루트에 쓰기 전에(`advance`, 이어쓰기 `load_state`, CLI `advance`·`resume`) 그 루트 **전체**의 `sink.verify_lineage(루트)` 가 `ok` 가 아니면 `OutputRootError` 로 거부한다. **리뷰 반영 3차(F2, 사용자 승인 2026-10-04):** `advance` 의 쓰기 전 검사는 여기에 **계보 사슬 검증**(구성원이 주장한 파일의 sha256·건수, 아래 조상 루트 검사와 같은 기준)을 더한 것이다(`src/simulator/api.py:170-173`). 이어쓰기 `load_state`(`resolve_continuation`)와 같은 관문이고, CLI `advance`·`resume` 도 이 두 경로를 지난다. 이전에는 `advance` 가 `verify_lineage` 만 봐서, 바이트 하나가 뒤집힌 루트에 계속 쓰고 그 뒤 `events()` 에서야 실패했다(`src/simulator/api.py:169-173`, `src/simulator/_internal/lineage.py:128-137`). 중단된 쓰기가 남긴 주인 없는 파티션 위에 같은 창을 다시 쓰면 이벤트가 조용히 중복되기 때문이다(재현: 연속 254행 → 실패 후 재시도 362행, 중복 `event_id` 108건). **중단된 루트에는 다시 쓰지 않고 복구는 새 빈 루트로만 한다.** 부분 쓰기 잔재는 디스크에 남는다(남은 위험).
- **저장 형식 고정 (2026-10-04 리뷰 반영 — Matthias D-1).** 루트의 첫 쓰기가 형식을 정하고 이후 쓰기는 그 형식을 따른다. 빈 루트는 런타임 기본 형식(`sink.resolve_format("auto")`)을 쓴다. 형식이 섞인 루트, 모르는 형식이 있는 루트는 거부한다. 런타임이 그 형식을 다룰 수 없으면(parquet 인데 pyarrow 없음) 쓰기·읽기 **전에** `SinkFormatError` 로 거부한다(`src/simulator/_internal/lineage.py:26-90`). 계기: 3.12(parquet)에서 만든 세계를 3.10(pyarrow 없음)에서 이어 쓰면 루트가 두 형식으로 섞이고 `events()`·`metrics()` 가 계약에 없는 `ModuleNotFoundError` 를 냈다.
- 끝 시각이 `MAX_TIME_MS = 10¹³`(`session_id` 13자리 한계)을 넘는 `advance` 는 쓰기 전에 `ValueError` 다(`DR-S1-time-model`).

그 밖의 규칙: `advance` 는 쓰기 전에 Sink 의 `latest_run_id(루트)` 가 이 세계가 그 루트에 마지막으로 쓴 `run_id`(처음이면 `None`)와 같은지 확인한다 — 다르면 다른 누군가 썼다. `load_state` 의 이어쓰기 판정은 `latest_run_id(루트)` 의 사이드카 `end_state_digest` 가 불러온 상태의 다이제스트와 같고 그 사이드카의 `output_root` 가 이 루트인가다 — 체크포인트를 상태 안에서 읽지 않고 사이드카에서 읽는다.

**계보 — 시뮬레이터 소유 사이드카.** `advance` 1회마다 Sink 실행 1건이 루트 안 사슬에 남고(Sink 기본 동작), 시뮬레이터는 Sink `close()` 가 성공한 뒤 숨김 영역 `runs/{run_id}.json` 에 사이드카를 원자적으로 쓴다.

```
run_id               Sink 가 정한 값 (close() 의 매니페스트)
parent_run_id        이 세계 계보의 직전 실행 — 다른 루트일 수 있다. 첫 실행은 null
output_root          이 실행이 쓴 Sink 루트 (절대 경로)
window               from_ms · to_ms (반열린 [from, to)) 와 KST 표기
start_state_digest   이 실행이 시작한 상태 (이슈 #75 의 state_digest)
end_state_digest     이 실행이 끝낸 상태
world_id · simulator_version · seed · profile · num_customers · sink format · event_count
files · sha256 · rows Sink 매니페스트에서 복사한 무결성 기준값 — 주장한 파티션 목록, 파일 다이제스트
                     (EventSink._digest 정의), 행 수 (리뷰 반영 3차 — Thomas F1, api.py:219-221)
mutations            이 실행 시작 전에 적용된, 아직 기록되지 않은 상태 변경 목록
                     {kind, at_ms, assignments, before_digest, after_digest}  (2026-10-04 리뷰 반영 — Thomas M1)
runtime              이 실행을 돌린 Python 구현 · 판 · 플랫폼 — 기록만, 판정에 쓰지 않는다
```

`files`·`sha256`·`rows` 는 숨김 영역 쪽에 둔 **무결성 기준값**이다. 이 필드가 없는 사이드카는 거부한다 — 아직 배포한 데이터가 없어 하위 호환을 두지 않는다(필드가 없으면 사슬 검증이 형태 오류 `LineageBroken` 으로 끝난다, `_internal/lineage.py:148-158`). `num_customers` 는 부모 없는 실행의 시작 다이제스트를 `(seed, num_customers, profile)` 에서 다시 계산하려고 싣는다. 저장 시점에 실행으로 기록되지 않은 변경이 남아 있으면 `hidden_root/derivations/{정준 기록 sha256 앞 32자}.json` 에 `{state_digest, parent_run_id, mutations, world_id, simulator_version}` 를 쓴다(`src/simulator/api.py:428-435`, `_internal/storage.py:103-107`). 스냅샷도 미기록 변경을 함께 든다.

**`parent_run_id` 결정 규칙** (2026-10-04 리뷰 반영으로 대체 — 리드 결정. 이전 규칙과 바뀐 이유는 아래 「정정 (2026-10-04, 리뷰 반영)」). `advance` 는 세션의 계보 머리를 부모로 적는다. `restore` 는 스냅샷이 잡힌 시점의 계보 머리를 잇는다. 이어쓰기(비지 않은 루트) `load_state` 는 그 루트의 머리 실행이 부모다. **빈 루트로 `load_state` 할 때** (`src/simulator/_internal/lineage.py:263-294`):

1. 후보는 숨김 영역에서 `end_state_digest` 가 불러온 상태와 같은 **실행 사이드카**와, `state_digest` 가 같은 **derivation 기록**이다.
2. 그중 조상 사슬이 끝까지 검증되는 것만 남긴다(아래 사슬 검사 · 조상 루트 검사).
3. 실행 후보를 우선해 `run_id` 사전순 최소를 고른다. 실행 후보가 없으면 derivation 중 `(parent_run_id, 정준 mutations)` 최소를 고르고, 그 `mutations` 를 미기록 변경으로 이어받는다.
4. 후보가 있었는데 검증되는 것이 없으면 `OutputRootError` 다.
5. 후보가 0개이면, 상태 다이제스트가 **갓 `init` 한 상태와 같을 때만** 부모 `None` 을 허용하고 나머지는 `OutputRootError` 다. "현재 시각이 시작일과 같으면" 보다 엄격하다 — 처치만 적용된 시작 상태도 이력(배정)을 가지므로 그것을 잃지 않는다.

**근거:** 같은 다이제스트(처치 노출 이력 포함)로 끝난 이력은 의미상 같은 세계다. 그래서 검증되는 후보 중 무엇을 골라도 `events()` 의 내용은 같고, 정렬로 고르면 결정적이다. 고르지 않고 `None` 으로 두면 이력이 조용히 잘린다.

사슬 검사 (2026-10-04 리뷰 반영으로 대체 — Thomas M1): `부모.end_state_digest → mutations(각 before_digest 가 직전 다이제스트와 같고 after_digest 로 이어진다) → 자식.start_state_digest`. 부모 없는 실행은 `(seed, num_customers, profile)` 로 다시 계산한 초기 다이제스트에서 출발한다(`_internal/lineage.py:109-118` · `:160-184`). **사슬 검사는 우연한 단절을 잡는 장치이지 위변조 방지가 아니다** (리뷰 반영 2차 — Thomas N3). 숨김 영역에 쓸 수 있는 사람은 다이제스트를 맞춘 채 `mutations`·derivation 의 내용(배정, `parent_run_id`)을 바꿔 끼울 수 있다. **조상 루트 검사** (리뷰 반영 2차로 대체 — 2026-10-04 리드 결정·사용자 확인). 조상 루트에서는 **계보 구성원 실행의 run 기록이 주장한 파일만** 읽는다. 고아 파일과 외부 작성자의 파일은 읽지도 판정하지도 않는다. 구성원 실행마다 (`_internal/lineage.py:183` · `:194-225`, 리뷰 반영 3차로 기준값을 사이드카로 옮겼다):

  - F3: `events()` 계약에 "예외가 나면 받은 이벤트를 쓰지 않는다"를 넣고 이터레이터 한계 문단을 갱신했다. `SinkFormatError` 메시지를 쓰는 루트용과 조상 계보용으로 나눴다.
- **왜 바뀌었나 — 최종 확인이 재현한 경계 조건.**
  - G2: 구성원 파티션의 마지막 행을 첫 행의 복사본으로 바꾸고 run 기록 `sha256` 을 다시 계산하니 `events()` 가 12건을 오류 없이 냈다(중복 id 1, 누락 1, `verify_lineage` `ok`).
  - G3: 두 번째 실행의 run 기록이 첫 실행의 `files` 를 주장하게 바꿔 다시 봉인하니 `events()` 가 24건을 오류 없이 냈다 — 첫 실행 이벤트가 두 번, 두 번째 실행 이벤트는 0건.
  - G4: 활성 루트 파일의 바이트 하나를 뒤집으면 `verify_lineage` 는 `ok` 라 `advance` 는 성공하고, 직후 `events()` 와 이어쓰기 `load_state` 는 거부했다 — 같은 루트를 두 관문이 다르게 판정했다.
- **번복 판단.** 기준값의 출처(run 기록 → 사이드카)와 쓰기 관문의 기준이 바뀌었다. 둘 다 이 문서가 이미 번복한 규칙(조상 루트 검증, 쓰기 전 무결성)의 내용이므로 같은 `번복 (부분)` 범위로 처리하고 헤더에 3차를 더했다. 보존하는 것·거부 조건의 방향(fail-closed)·등식 E1~E6 은 바뀌지 않았다.

## 이 결정이 틀렸다면 어떻게 드러나나

- E1~E6 중 하나라도 갈린다 → 상태에 빠진 항목이 있거나 경계가 생성에 샌다. 정준 이벤트 diff 의 첫 불일치가 어느 고객·어느 사건인지 짚는다.
- `format_version` 이 다른 상태 파일을 조용히 읽는다 → 거부 시험(판을 하나 바꾼 파일)으로 막는다.
- 사이드카 사슬에서 `부모 끝 → mutations → 자식 시작` 이 이어지지 않는다 → 기록되지 않은 상태 변경이 있다.
- run 기록만 다시 봉인한 위조(G2·G3)가 통과하거나, 같은 루트를 `advance` 와 이어쓰기 `load_state` 가 다르게 판정한다(G4) → 리뷰 반영 3차 규칙이 깨졌다(회귀 시험).
- 조상 루트에 외부 작성자의 파일·고아 파일을 두었을 때 `events()` 결과가 바뀌거나 실패한다 → 구성원 파일만 읽는 규칙이 깨졌다(N1·D-4 회귀 시험). 주장된 파일의 행을 지웠는데 오류가 없다 → sha256·행 수 대조가 빠졌다(N2 회귀 시험).
- 같은 세계를 두 번 만든 뒤 빈 루트로 이어받은 `events()` 가 한 번 만든 경우와 다르다 → 후보 선택 규칙이 이력을 자른다(H2 회귀 시험).
- 쓰기 도중 실패를 주입한 뒤 같은 루트 재시도가 거부되지 않는다 → fail-closed 가 빠졌다(H1 회귀 시험).
- 어느 출력 루트든 `sink.verify_lineage()` 가 `broken` → 루트 안 사슬을 깨뜨렸다.
- 저장소 `data/` 아래 `hidden/` 밖에서 상태 파일이나 Hidden Trait 이 발견된다 → 위치 규칙 위반.
- `restore` 뒤 기존 루트에 이벤트가 붙는다 → 사용자 결정 3 위반.

## 민감도

- **상태 크기는 재지 않았다.** 고객당 항목(장바구니·최근 조회 ≤ 20·노출 이력·대기 사건)을 수십 개, JSON 항목당 50~100 B 로 **가정**하면 26,000명에 수십~100 MB 다. 이 가정이 맞으면 저장 1회 수 초, 스냅샷 1개 같은 크기의 메모리. 최근 조회 상한 ±20% 는 이 값을 거의 선형으로 움직인다. S1 구현에서 20,000명 기준 실측해 이 칸을 고친다.
- 크기가 1 GB 를 넘거나 저장이 수십 초를 넘으면 압축(gzip 은 mtime 을 0 으로 고정해야 다이제스트가 선다)이나 고객별 분할 파일을 검토한다 — 정준 바이트 정의는 압축 **전** 바이트로 유지한다.
- 판을 넘어 상태를 읽으므로, 결과 경로에 부동소수 연산이 하나라도 새어 들어오면 판 사이에서 **조용히** 다른 세계가 이어진다. 막는 것은 거부가 아니라 골든 해시(E6)와 AST 금지 검사다 — 둘 중 하나라도 빠지면 이 결정의 안전장치가 없다.

## 남은 불확실성

- **주문 장부의 위치**(상태 안 / 숨김 영역 추가 전용 파일) — S4. 640일 주문 수에 따라 상태 크기가 좌우된다.
- **측정 계층 run record 의 `state_digest` 칸** — 필요하면 양 팀 합의 이슈로 연다(리드 판단).
- `data/hidden/simulator` 의 기준을 저장소 루트로 둘지 실행 디렉터리로 둘지 — 저장소 루트를 제안하지만 다른 CLI(`publish` 등)의 관례와 맞춰 볼 필요가 있다.
- **판 간 동일의 실측.** 리드 보고로 골든(`sim-0.1`: 716건)이 3.10·3.12·3.14 에서 일치했다(macOS). **Linux 골든은 첫 CI 가 확인한다.**
- **부분 쓰기 잔재.** fail-closed 는 중복을 막지만 중단된 루트의 잔재는 디스크에 남는다. 그 루트는 이후 쓰기 대상이 될 수 없다.
- **M6 — 비용 미측정.** 리뷰 반영 3차로 `advance` 도 매번 계보 전체를 다시 해시한다(쓰기 관문 F2) — 이 비용이 더해졌다. S1 규모(20,000명×30일)에서는 `events()` 1.0 s 로 거의 늘지 않았다는 Thomas 측정이 있으나 S3 규모는 재지 않았다. `events()`·`metrics()` 는 매번 전체를 다시 읽고 사슬을 검증한다. S3 규모 비용은 재지 않았다.
- **루트를 넘는 사슬의 가시성.** 새 루트 첫 실행의 Sink `parent_run_id` 는 `null` 이다. 루트를 넘는 사슬은 숨김 사이드카에만 있어 시스템 팀은 출력 루트만으로 직전 이력을 추적할 수 없다 — 측정 계약 변경 이슈 후보.
- **사슬 검사는 위변조 방지가 아니다** (N3 · F1). 숨김 영역에 쓸 수 있으면 `mutations`·derivation 을 바꿔 끼울 수 있다. run 기록과 사이드카를 함께 일관되게 위조하면 통과하고, 그때 실제 행 수가 `event_count` 와 다르면 `events()` 가 일부 이벤트를 낸 뒤 실패한다(계약상 그 이벤트는 쓰지 않는다). S6 진단은 사이드카의 배정을 상태 파일의 배정 이력과 교차 대조해야 한다.
- **3.10 + 의존성 설치 조합은 CI 가 돌리지 않는다.** `python-compat.yml` 은 3.10 을 의존성 없이 돈다. R-1 의 "3.10 에서 전 기능"은 Matthias 가 scratchpad venv(3.10 + `requirements.txt`)에서 실측으로 확인했다 — 최종 검증 R-1 PASS, `events()` 전체가 3.12 연속 실행과 같았다. CI 잡은 여전히 없다.
- **F-1 — 3.10 간헐 실패 원인 미상.** 3.10 전체 스위트가 누적 96회 중 1회 실패했고(첫 실패의 테스트 이름이 기록되지 않았다) 그 뒤로 재현되지 않았다. CI `python-compat` 실패 이력을 확인해야 한다.
- **내구성.** macOS 의 `fsync` 는 드라이브 캐시를 비우지 않는다(`F_FULLFSYNC` 필요). 원자성(`os.replace`)과 무관하며 전원 손실 내구성은 요구하지 않는다.
- **decode 의 카탈로그 엄격 검사**(이 판의 카탈로그와 같아야 한다, `src/simulator/_internal/world.py:223`)는 S4 가 카탈로그 생성을 넣을 때 함께 바뀌어야 한다.
- **후속 이슈 후보 (보고만, 고치지 않음):**
  - jsonl.gz 는 gzip 헤더에 mtime 이 들어가 매니페스트 `sha256`(`sink.py:329-334`)이 같은 내용이어도 실행마다 달라질 수 있다 — `docs/data_spec.html:982` 의 "events SHA-256" 대조와 NFR-001 해석에 영향.
  - `sink.py:341` 독스트링은 run_id 를 `MR-…` 라 하고 코드(`:345`)는 `SR-…` 를 만든다.
  - `docs/data_spec.html:236` · `:330` 의 `hash()`·`PCG64` 표기가 `DR-S1-rng` 과 다르다.
  - `docs/data_spec.html:180` 이 말하는 `config/simulator_config.yaml` 이 없다(`config/` 에는 `economic_config.yaml`·`gate1_lock.yaml` 뿐).
