## 무엇을 정하는가

EventBatch·명시적 TimePolicy·ObservationClaim에서 고객/index_date별 원시 시퀀스를 만드는 인메모리 함수를 구현한다. 출력은 고정 토큰30·mask·nullable 상대 간격·gap_mask·VALID/EMPTY_COMPLETE/UNKNOWN·사유·감사/재현 정보다. F36/F37 학습이나 값을 생성하지 않는다.

## 정하지 않으면 무엇이 막히나

순서 근거 없이 event_id나 물리적 행 순서로 선후관계를 만들거나, PAD/null을 실제 간격0으로 오인할 수 있다. 원시 구조가 없으면 모델 선택과 무관한 시퀀스 검산도 진행되지 않는다.

## 선택지

| 안 | 장점 | 한계 |
|---|---|---|
| 인메모리 원시 표현, 필요한 tie만 명시적 합성 ordinal로 판정 | 실제 모델 없이 구조·경계 검증 가능 | 실제 SD3 순서 제공 합의와 파일 연결은 대기 |
| event_id/입력 순서로 tie 해소 | 구현 쉬움 | 발생 순서 근거가 아니므로 기각 |
| 전체 과거의 tie를 모두 거부 | 보수적 | C절의 최종30/선택 경계 검사 범위 위반 |
| null을0·소수 ms를 정수로 축소해 기존 로더 연결 | 연결 쉬움 | 의미/정밀도 변경으로 기각 |

## 조사한 것

설계 C는 과거→최근·왼쪽 PAD·PAD=0 및 명시된16종 순서를 고정한다. 첫 실제 이벤트/PAD gap은 null, 확정된 동시각 gap은0이다. 현재 EventBatch는 공개 출처·입력·cutoff를 검증하고 관측 함수는 #127 수정 상태다. 기존 로더/의미값의 정수 gap+masked0 제약은 새 nullable 표현과 충돌한다. 공유 계약·로더는 수정하지 않는다.

## 결정

구현 전 선택은 d1_raw_sequence.py와 전용 시험이다. 모든 batch에 기존 guard를 먼저 적용하고 E/source/namespace/input pin에 관측 근거를 결합한다. 명시한 H의16종 전체 완전 관측을 요구한다. 충분한30개가 보였다는 이유로 H의 결손을 자동 해소하지 않는다. 명부 행을 보존하며 complete+0건은 EMPTY_COMPLETE(길이0, PAD30, false mask, null gap), 근거 불명은 UNKNOWN이다.

발생시각 그룹을 최신부터 모아30개 선택에 필요한 그룹까지만 순서를 판정한다. 선택 경계 tie는 선택 밖을 포함한 전체 묶음의 순서가 필요하다. 순서 근거가 없거나 선택 묶음을 온전히 설명하지 못하면 AMBIGUOUS_EVENT_ORDER로 UNKNOWN이다. 더 오래된 tie의 모호성은 이 결과를 막지 않는다. 전체 원시 입력의 중복·필수값·출처·금지 시각 검사는 계속 적용한다.

합성 순서 주장은 E·동일 timestamp 묶음·event_id→고유 ordinal·입력 의미 hash·provider/contract/ref에 결합하는 별도 메타데이터다. 인메모리 합성 인터페이스만 제안하며 공개22컬럼이나 실제 SD3 제공 계약을 확정하지 않는다. 실제 운영 provider 승인은 없다. ID는 결합 키일 뿐 정렬 값으로 쓰지 않는다. 여러 주장이 같은 필요한 그룹을 다르게/중복 설명하면 임의 우선하지 않는다.

간격은 timedelta에서 정수 microseconds로 정확히 구한 뒤 1000으로 나누어 정수 ms일 때만 표현한다. 선택된 실제 간격이1µs처럼 정수 ms로 표현되지 않으면 CONTRACT_UNRESOLVED와 구체적 차단 정보를 남겨 해당 시퀀스만 UNKNOWN이다. 소수 ms 새 파일 형식이나 반올림을 만들지 않는다. 선택 밖의 미세 간격은 검사를 확대하지 않는다. 원천 정밀도의 실제 보장은 SD2 대기다.

VALID/EMPTY_COMPLETE는30칸 배열을 가진다. UNKNOWN의 length/배열은 null로 두어 빈 행동을 가장하지 않는다. 키·버전·cutoff·생성 시각·원시/정책/관측·사용한 순서 근거·감사 건수를 보존한다. EMPTY_COMPLETE의 사유는 NO_SEQUENCE_INFORMATION이다. F36/F37 및 기존 FeatureOutput은 변경하지 않는다.

## 기각한 안과 기각 사유

모델/SVD/KMeans·480차원 학습 입력 생성까지 확대하는 안은 이번 원시 생성 범위 밖이다. ordinal을 event_id/수신 순서에서 자동 생성하는 안, 증거 없는 tie/관측 결손을 버려30개를 채우는 안, 기존 로더를 완화하는 안도 기각했다.

## 이 결정이 틀렸다면 어떻게 드러나나

최종30개 밖 tie가 VALID를 막거나 경계 tie가 근거 없이 통과하면 실패다. 첫/PAD null과 실제 gap0 혼동, 1µs의0 변환, 고객 행 삭제, 입력 순서에 따른 결과 변화도 실패다. 서로 다른 원천/고객/input hash의 순서 근거를 수용하면 실패다.

## 민감도

cutoff/H·관측 범위·순서 주장·선택 경계가 바뀌면 결과가 달라질 수 있어 버전과 근거를 남긴다. generated_at과 물리적 입력 순서는 순서 근거가 아니다.

## 남은 불확실성

SD1/SD2 운영 시간·정밀도, SD3 실제 순서/관측 제공, SD4 모델 선택/학습은 미결정이다. nullable gap과 cutoff를 포함한 전체 로더 연결·공식 게시·실제 입력 인수는 보류다. 원시 표현을 FE-006 시퀀스2종 충족이나 D1 완료로 세지 않는다.
