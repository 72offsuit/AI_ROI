# DR-218-lstm-comparison — 독립 LSTM과 공통 고객 비교의 준비 단계

| | |
|---|---|
| 태스크 | #218 · D3 · DL-001~007 |
| 작성 | 광진 작업용 Codex · 2026-11-13 |
| 상태 | 로컬 구현안·독립 검수 반영 중. 실제 데이터 선택·공통 분할·최종 채택은 미승인 |

## 무엇을 정하는가

기존 일별 GRU를 바꾸지 않고, 사건 종류 토큰을 입력받는 CPU LSTM·학습 로그·가중치 저장과
Validation 전용 앙상블 선택을 독립 모듈로 구현한다. 이번 단계는 계약 형식 합성 입력의 연결·거부
검증까지다. #215의 고객·시간 분할, #214의 모델 저장, 오케스트레이션에 임의로 개입하지 않는다.

## 정하지 않으면 무엇이 막히나

기존 GRU는 LSTM/Transformer·토큰 임베딩 요구를 충족하지 않는다. 동시에 진행 중인
PR #279·#280과 공통 파일을 함께 수정하면 저장·평가 계약이 갈릴 수 있다.
최종 ML/DL 비교는 공통 모집단·분할·라벨·시간 정의를 인수하기 전에는 진행할 수 없다.

## 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 토큰 임베딩 + 길이를 반영한 단층 LSTM | 요구 충족, CPU에서 독립 검증 가능 | 시각 간격·구매 금액을 직접 표현하지 않음 |
| B | Transformer | 요구 충족, 다른 표현 비교 가능 | 첫 단계 구현·선택 범위가 늘어남 |
| C | 기존 GRU만 연결 | 기존 계산 유지 | DL-001·003의 필수 구현을 대신하지 못함 |

## 결정

1. A로 로컬 준비 구현한다. 값은 새 `config/decision_dl.yaml`에서 읽으며 기존 공통 config를
   수정하지 않는다. 최대 180일의 최근 128사건, embedding 16, hidden 32, 단층, dropout 0.2,
   Adam lr 0.001, batch 128, 최대 30에포크, patience 5, min_delta 0.0001, seed 42, CPU 2 thread다.
   최적값의 외부 근거는 없다. 합성 연결용 시작값이며 실제 탐색 전에 다시 검토한다.
2. 공개 EventType만 토큰으로 쓴다. 고정 스키마 사전은 Test에서 학습한 어휘가 아니다.
   PAD=0과 NO_HISTORY=1을 구분한다. 파생 상태는 제외·감사하며 미래 사건은 입력에서 제외한다.
   관측 불명은 알려진 무활동으로 바꾸지 않는다. 고객별 전체 창 complete 선언과 참조가 있어야
   학습 가능하고, 선언은 외부 근거 자체의 자동 인증이 아님을 기록한다.
3. 입력 창은 기존 공개 소비 경계와 같은 `[T0-lookback, T0)`다. 시간대와 소수초를 보존하고
   T0 사건은 제외한다. `23:59:59` 초 단위 표현과의 정식 계약 확인 없이 모든 시간 요구 충족을
   선언하지 않는다. 공개 시각 파서를 쓰며 직접 fromisoformat을 호출하지 않는다.
4. Train과 Validation을 호출자가 명시한다. ID는 고유하고 집합이 겹치면 거부한다.
   Validation log loss로 중단·최선 가중치를 복원한다. seed는 모델 생성 전에 설정한다.
   Train 가중치는 사용하지 않는 초기안이며 불균형 처리는 실제 개발 데이터에서 재검토한다.
   이 함수가 고객 분리만 확인했다고 시간 순서·전체 SRS 분할 충족을 주장하지 않는다.
5. 앙상블 alpha는 0~1, 0.1 간격. Validation log loss 최소, 동점은 작은 alpha(ML 쪽)를 택한다.
   최종 ML·DL·혼합 각각의 F1 임계도 Validation에서만 정한다. 양 끝값이 택해지면 혼합 이득
   없음으로 보고한다. 선택 API에 Test 라벨을 넘기지 않는다. 선택 기록을 저장한 뒤 공통 Test
   예측을 같은 ID·라벨 해시로 평가한다. Test 결과로 alpha나 모델을 다시 고르지 않는다.
6. `.pt`는 state_dict와 primitive 메타데이터로 저장한다. 새 디렉터리만 사용하고 SHA-256·바이트·
   설정·토큰 사전·학습/검증 ID 지문·로그를 남긴다. 로드는 weights_only·CPU이며 해시·사전·설정을
   대조한다. 해시는 서명이나 파일 생산자 인증이 아니다. 외부의 신뢰하지 않는 모델을 받지 않는다.
7. 이 단계 출력은 합성 검증용이다. 실제 고객 학습, 정식 비교, 시뮬레이터 재실행, Final Holdout,
   봉인·서명·커밋·푸시·PR 생성은 수행하지 않는다. 결함 Issue 작성은 사용자가 명시 승인한
   아래 검수 반영 범위에서 수행한다.

### 독립 검수에 따른 보완 결정 (#283~#288)

검수 전 코드와 원래 합성 산출은 보존한다. 검수에서 기존 시험이 놓친 반례를 재현했고,
각 결함을 먼저 이슈로 기록한 뒤 보완한다. 이슈 생성은 사용자 명시 승인 범위다.

- [#283](https://github.com/72offsuit/AI_ROI/issues/283): 필터 전 고객 키 형식을 검사한다.
  숫자 변환·ID 별칭 추측은 하지 않으며 정상 서브셋과 완전 관측 0건을 보존한다.
- [#284](https://github.com/72offsuit/AI_ROI/issues/284): coverage·배열·중첩 출처/목적·ID/폭 지문을
  재대조한다. 원본 별칭과 분리한 읽기 전용 배열·재귀 불변 메타데이터로 변경 전파를 막는다.
  고객 순서 변경은 배열·coverage·순서 지문을 함께 옮기는 공개 메서드로 한다.
- [#285](https://github.com/72offsuit/AI_ROI/issues/285): 고객 목록을 tuple로 고정하고 선택·평가
  진입 시 교집합을 다시 확인한다. 생성 때의 검사만으로 이후 상태를 보증하지 않는다.
- [#286](https://github.com/72offsuit/AI_ROI/issues/286): ID 결합 Validation 라벨/예측 snapshot을
  고정하고 후보 손실·선택값·임계를 재계산해 대조한다. 선택 증거는 Test를 읽기 전 목적지별
  독점 예약에 남긴다. 자기 일관성 검사이며 외부 학습 사실·전역 Test 접근의 인증이 아니다.
- [#287](https://github.com/72offsuit/AI_ROI/issues/287): log loss 최솟값과 절대 차이 1e-12 이내를
  수치 동점으로 정의해 가장 작은 alpha를 택한다. 최적화할 값이 아닌 고정 계산 규약이다.
  기존 결정 5의 '정확히 같은 손실'에서 이 수치 동점 규약으로 번복한다.
  Validation 라벨과 두 예측은 고객 ID 문자열의 `sorted()` 순서로 ID 결합한 뒤 손실을 계산한다.
  숫자 접미사를 해석한 순서나 호출자가 넘긴 행 순서를 합산 순서로 쓰지 않는다. 저장하는
  Validation snapshot과 재검증도 같은 순서다. 이는 기존 계산의 명시이며 선택 규칙 변경이 아니다.
- [#288](https://github.com/72offsuit/AI_ROI/issues/288): 모델·비교 산출은 같은 부모의 임시 폴더에서
  완성 후 rename으로 게시한다. 협력 작성자는 목적지별 독점 lock을 사용하고 기존 목적지는
  거부한다. Test는 별도 영구 예약이 남아 실패 후 자동 재평가를 막는다. 예약은 완료 상태가
  아니고 성공 폴더 안의 test_access/comparison만 함께 게시된다. 신뢰 로컬 파일시스템의
  협력 작성자 규약이며, 악의적 비협력 프로세스나 전원 장애의 내구성은 보증하지 않는다.

단일 run_id 강제 제안은 철회했다. 정상 parent/child 계보를 배제하지 않으며 세계·seed·버전의
인수 계약은 #214/#215에서 확인한다. MPS RNG 가설은 미확인으로 남기고 이 수정에서 고치지 않는다.

### PR #290의 P3 회귀 시험 보완 (2026-11-14)

[리뷰](https://github.com/72offsuit/AI_ROI/pull/290#pullrequestreview-5903499349)에서 기존
`V0..V199` fixture는 문자열 정렬 뒤 허용오차를 0으로 되돌려도 통과함을 지적했다.
`V000..V199`로 고정해 실제 log loss의 반올림 반례를 유지하고, 행 순서를 뒤집어도 같은 선택
증거가 나오는지 확인한다. 별도 단위 시험은 scorer 출력을 제어해 1ULP·포함 경계 1e-12에서는
작은 alpha를, 1e-10의 제어된 손실 차이에서는 더 나은 후보를 고르게 한다. 이 단위 시험 전체는
라이브러리의 합산 구현 차이에 의존하지 않는 수치 정책 시험이다. 허용오차를 0으로 바꾼 임시 사본에서
회귀 시험이 실패하는지도 대조한다. 제품의 계산·설정·실제 고객 성능을 바꾸는 작업은 아니다.

## 기각한 안과 기각 사유

Transformer의 열세를 단정하지 않는다. 첫 구현에서 탐색 범위를 한정하기 위해 B를 보류한다.
Test를 보고 길이·모델·가중치·임계를 고르는 안, 같은 seed로 독자 분할하는 안, 빈 이력 고객을
조용히 삭제하는 안, 모든 패딩을 실제 0활동으로 해석하는 안, 전체 데이터로 임베딩을 미리
학습하는 안은 누수·모집단 변경 때문에 기각한다. 실제 원가·이익 계산은 추가하지 않는다.

## 이 결정이 틀렸다면 어떻게 드러나나

패딩 개수·고객 순서가 예측을 바꾸거나 저장 후 다른 프로세스의 예측이 다르다.
Test 라벨을 바꾸면 선택 결과·학습 가중치가 바뀐다. 출처가 다른 입력이나 관측 불명 고객이
학습에 들어간다. Train/Validation/Test 사이 ID가 겹치거나 같은 Test라고 적은 해시가 다르다.

## 민감도

합성 반례는 빈 이력·빈 입력·미지 사건·중복 ID·출처 혼합·KST/UTC·T0 경계·마스크/길이 모순·
한 클래스·결손 라벨·저장 변조·Test 라벨 변경을 다룬다. 실제 길이 64/128/256, lookback,
모델 크기·불균형 처리는 공통 Validation 인수 후 사전 등록한다. 이 단계에서 성능 탐색하지 않는다.

## 남은 불확실성

#215의 고객/시간 분할표와 persona 층화 충돌, ML 예측 인수 형식, #214 저장 통합이 미결정이다.
공통 분할에 대한 시간 순서·라벨 중첩 검증과 5-Fold 연결은 인수 이후 단계다.
실제 데이터 성능·CPU 소요·GATE 2 실제 봉인·11/22 리뷰 완료를 미리 확정하지 않는다.
