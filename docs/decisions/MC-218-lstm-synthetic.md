> 이 카드 전체는 합성 계약 입력의 연결 검증이다. 실제 시뮬레이터 성능·정식 공통 Test 비교·
> GATE 2 Baseline·모델 채택의 근거가 아니다. 실제 모델 카드는 공통 분할 인수 후 별도로 작성한다.

## 무엇을 예측하나

LSTM의 출력은 고객별 이진 라벨 확률 형태다. 이번 라벨은 시험 코드가 번갈아 지정한 0/1이다.
실제 42일 관측에서 만든 Churn 정답이라는 주장은 하지 않는다.

## 어떤 결정에 쓰이나

입력·학습·중단·복원·저장·불러오기·Validation 앙상블 선택·동일 ID 비교가 연결되는지 확인한다.
실제 고객 처치나 예산 선정에 사용하지 않는다.

## 분할

Train/Validation/Test는 서로 다른 합성 ID 접두사로 64/24/24명이며 양성 비율은 각각 0.5다.
ML·DL·앙상블 시험 비교의 ID 집합·행 순서 해시는 동일하다. 시간 분할·5-Fold·실제 적격성·
persona 층화를 검증한 것이 아니며 SRS SPLIT 전체 충족을 선언하지 않는다.

**Final Holdout을 무엇에 썼나:** 사용하지 않았다.

**무엇에 쓰지 않았나:** 하이퍼파라미터·Feature·임계·모델·전략·예산 선택 전부.
최종 전략의 성능 평가도 이 실행 범위가 아니다.

## 학습

| | |
|---|---|
| 알고리즘 | event_type 토큰 → embedding 16 → 단층 LSTM hidden 32 → dropout 0.2 → 이진 logit |
| 학습 | CPU 1 thread · seed 42 · Adam lr 0.01 · batch 4 · 최대 12에포크 |
| 입력 | 2일·최근 최대 16사건. NO_HISTORY와 PAD 구분 |
| Early Stopping | Validation log loss, patience 3, min_delta 0.0001 |
| 실제 중단 | 4에포크 후 중단, 1에포크 가중치 복원 |
| 불균형 | 합성 라벨 1:1, 가중치·리샘플링 없음 |
| 탐색 | 하이퍼파라미터 탐색 0회. 합성 연결용 사전 지정 설정 |
| 앙상블 | Validation log loss로 alpha 0.0~1.0, 0.1 간격 11개 후보. 선택값 0.7 |

앙상블 선택 시 Validation 고객 ID를 문자열 `sorted()` 순서로 정렬하고 라벨·ML·DL 예측을
그 순서로 결합해 손실을 계산한다. 호출자의 행 순서나 ID 숫자 접미사 순서로 합산하지 않는다.
최솟값 + 1e-12 이하를 수치 동점으로 보고 가장 작은 alpha를 선택하며, 저장 snapshot의 재계산도
같은 규칙이다. PR #290 P3 보완은 실제 log loss 반례와 고정 scorer의 1ULP·허용오차 경계·유효 개선,
허용오차 0 사본의 실패를 확인하는 회귀 시험이며 위 합성 모델의 재학습·성능 갱신이 아니다.

모델 학습 wall 약 1.47초·CPU 약 1.46초다. 112명 전체 합성 연결 wall 약 3.59초이며
실제 5만 고객 학습 시간 추정에 사용하지 않는다. 기본 YAML과 다른 값은 이 합성 실행의
명시적 override이며 최적값으로 골랐다는 뜻이 아니다.

## 성능

실제 프로젝트 Train/Validation/Test AUC·PR-AUC·이익 성능은 **미실행**이다.
합성 비교 JSON의 수치는 경로 형식 확인용이며 이 카드에서 모델 우열의 근거로 인용하지 않는다.
학습 손실 곡선 데이터는 `dl_training_log.json` 및 `dl_training_curve.csv`에 보관했다.
곡선의 시각화 그림은 이번 준비 구현에 포함하지 않았다.

### #283~#288 검수 수정 후 합성 재실행

이 카드 위의 최초 실행과 산출은 보존했다. 2026-11-13 수정 후 별도 폴더에서 같은 합성 입력을
다시 실행해 4에포크 중단·1에포크 복원·alpha 0.7과 동일 Test ID 해시를 확인했다.
수정 후 학습 wall 약 1.49초·CPU 약 1.49초다. 최초 시간과 섞어 동일 실행처럼 쓰지 않는다.
실제 고객 성능 비교는 여전히 미실행이다.

관측 상태·중첩 출처·가변 고객 목록·선택값 변조·수치 동점·쓰기/게시 실패를 회귀 반례로
추가했다. 메타데이터는 재귀 불변 사본이며 학습 시 JSON용 사본을 기록한다. 라벨 지문은
이제 고객 ID와 값을 결합한 `sorted-id-value-json-v1`이다. 같은 0/1 배열의 다른 고객 집합은
다른 지문을 갖는다. 지문은 외부 생산자 인증이 아니다.

평가 폴더 밖의 목적지별 예약은 Test를 읽기 전에 선택 snapshot을 기록한다. 실패 뒤 예약을
남겨 같은 목적지 재평가를 거부하고, 완성된 비교/접근 기록만 한 디렉터리로 게시한다.
예약은 완료 상태가 아니며, 새 폴더에서의 외부 조회까지 막는 전역 통제가 아니다.

검증 패키지 `issue218_fixes_20261113/`에 수정 전 실패 로그·수정 후 통합 실행·별도 합성 산출을
보관한다. 기존 PASS만으로 새 반례를 해결했다고 주장하지 않는다. 같은 Claude 세션의 재검수는
별도 기록으로 판정하며 이 카드 자체가 승인·PR 병합·GATE 서명을 뜻하지 않는다.

## 해석

고정 공개 EventType 사전만 사용하며 고객 ID·날짜·persona를 토큰으로 쓰지 않는다.
사건 종류의 순서만으로는 사건 사이 간격·주문 금액 정보를 충분히 표현하지 못한다.
그 한계와 표현 추가 여부는 실제 개발 Validation 인수 전에 검토한다.

## 실패 모드

공개 관측 완전성 근거가 없는 경우, label 미확정·한 클래스, 중복 ID·출처 혼합은 거부한다.
같은 출력 디렉터리의 덮어쓰기를 거부하지만 시스템 밖의 Test 반복 접근을 막는 보안 장치는 아니다.
파일 해시는 바이트 무결성 검사이며 제공자 서명·학습 계보 인증이 아니다.
공통 분할·시간 순서·보정·신뢰구간·실제 원천 연결은 별도 완료 조건이다.
