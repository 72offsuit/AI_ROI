## 무엇을 정하는가

`return_visit_count_60d`의 의미를 B안의 구매 뒤 첫 방문 수로 문서화하고, DL visit은 두 시작 이벤트 수의 합을 유지한다. 구 정의 커머스와 B안·미확인을 입력 메타데이터로 구분하며 커머스를 실험 입력과 섞지 않는 시스템 경로를 정한다.

## 정하지 않으면 무엇이 막히나

같은 이름의 count가 출처마다 다른 뜻인데도 비교·학습 입력에서 같은 값처럼 취급된다. 구 커머스의 시작 이벤트 두 개를 임의로 하나로 바꾸면 원시 이력이 변하고, 부분 창에서 구매를 찾을 수 없다는 이유로 정상 B안 이벤트를 제외할 수도 있다.

## 결정

A를 선택한다. `src.decision.return_visit`의 입력 의미 버전은 `return-visit-input/v1`이며 공유 이벤트/교환 계약 버전과 분리한다. 커머스는 명시적 `every_repeat_session_with_session_start` 또는 `purchase_first_session` 선언과 비어 있지 않은 evidence_ref를 받는다. 선언이 없거나 서로 다른 선언을 가진 입력의 concat으로 선언을 잃으면 unknown으로 남긴다. 생산 버전·날짜에서 새 의미를 만들어내지 않는다.

기본 Feature/DL 호출 목적은 experiment다. 공개 출처 규칙으로 판단한 simulator만 허용하고 커머스는 관측 목적을 명시해야 한다. 혼합 출처는 집계 전 거부하여 같은 customer_id가 출처를 넘어 합쳐지지 않게 한다. 목적 판정은 T0 이전의 실제 계산 대상 행에 한정한다. DL은 고객·lookback 창까지 필터한 뒤 판정한다. 미래 이벤트는 현재 입력의 값·출처 의미를 바꾸지 않는다. 해당 범위가 0건이면 출처를 확인할 수 없으므로 experiment 호출은 거부한다. 관측용 빈 결과의 산술과 실제 관측 완전성 판정은 별개다.

Feature 결과에는 별도 attrs를, DL은 선택적 `(배열, 메타데이터)` 반환을 제공한다. `model_columns`는 커머스 관측 표와 return_visit count가 있는데 메타데이터를 잃은 표를 거부한다. 기존 메타 없는 수작업 산술 시험 1건은 observation 목적을 명시하며 값의 기대는 완화하지 않는다. 공개 시뮬레이터 API 대역의 page_view/purchase 픽스처에는 생성 시 simulator_version·random_seed를 명시해, 기존에 주장하던 simulator 출처와 실제 공개 판정이 일치하게 한다. 임의의 입력 출처를 뒤에서 덮어쓰지 않는다. 범용 수치 행렬 API의 소유·보안 체계를 바꾸는 결정은 아니다.

**근거:** 리드가 요청한 것은 B안에 맞춘 의미·입력 분리이며 원시 재작성이나 새 측정 DQ가 아니다. 출처·의미 메타는 학습 설명 변수가 아니고 선언의 ref는 내용 검증의 대체물이 아니다. simulator 표지도 공개 계약의 기대를 기록할 뿐 실제 생산자의 준수 증명은 성환의 공개 검사 결과로 받는다.

## 기각한 안과 기각 사유

B는 병합 후에도 export에 남는 구 이벤트를 새 정의로 오분류한다. C는 원시 보존 결정에 어긋나고 count 4를 2로 임의 변환해 실제 구매 뒤 첫 방문을 증명할 수 없다. D는 구분 표지가 없어 같은 Feature 이름이 뜻이 다른 입력을 숨긴다. DL에서 session_id로 중복 제거하거나 앞선 구매를 부분 창에서 재검증하는 안도 기존 합을 유지하라는 리드 결정과 다르므로 선택하지 않는다.

## 이 결정이 틀렸다면 어떻게 드러나나

동일 5세션 예시에서 B안 return count 2·visit 5, legacy return count 4·DL visit 9가 보존되지 않는다. 커머스 unknown이 service_version이나 미래 시각만으로 B가 된다. 출처를 섞어 같은 고객으로 합산한다. T0 이벤트·미래 출처가 현재 값을 바꾼다. 관측 입력이 기본 실험 호출이나 model_columns를 조용히 통과한다. 원시 행·기존 F31·학습 설정이 변경된다.

## 민감도

정의 A/B, 출처, 동일 버전 문자열, 부분 시뮬레이터 메타, 0건·미래 행·KST/UTC·관측 목적·메타 소실을 비교한다. 수치 단위를 바꾸거나 모델 성능을 보고 선택을 조정하지 않는다. 신뢰할 생산 이력이 없으면 unknown으로 남기는 조건은 완화하지 않는다.

## 남은 불확실성

실제 Ecommerce #54 이전/이후 파일의 인수 목록과 생산 이력 근거는 데이터 소유자가 제공해야 한다. 이번 반영이 기존 원본을 자동으로 모두 분류했다는 뜻이 아니다. pandas attrs는 영구 저장 계약이 아니므로 CSV/배열 외부화 시 별도 출처·정의 메타데이터를 보존하고 재인수해야 한다. 선언이 위조됐는지, 임의로 조작한 수치 행렬을 범용 모델에 직접 넣는지까지 이 계층이 증명하지 않는다.

③a의 측정 매핑·공유 DQ, 생산자 B안 검사, PR #265와 양 팀 합의, GATE 1·2 서명, F31 제공 계약은 별도다. 실제 데이터 인수·본 학습·모델 성능 실험·Test/Holdout·봉인은 이번에 수행하지 않는다. 검증과 이후 독립 검수의 소스·범위를 구분해 기록한다.
