## 무엇을 정하는가

`return_visit_count_60d`의 의미를 B안의 구매 뒤 첫 방문 수로 문서화하고, DL visit은 두 시작 이벤트 수의 합을 유지한다. 구 정의 커머스와 B안·미확인을 입력 메타데이터로 구분하며 커머스를 실험 입력과 섞지 않는 시스템 경로를 정한다.

## 정하지 않으면 무엇이 막히나

같은 이름의 count가 출처마다 다른 뜻인데도 비교·학습 입력에서 같은 값처럼 취급된다. 구 커머스의 시작 이벤트 두 개를 임의로 하나로 바꾸면 원시 이력이 변하고, 부분 창에서 구매를 찾을 수 없다는 이유로 정상 B안 이벤트를 제외할 수도 있다.

## 결정

A를 선택한다. `src.decision.return_visit`의 입력 의미 버전은 `return-visit-input/v1`이며 공유 이벤트/교환 계약 버전과 분리한다. 커머스는 명시적 `every_repeat_session_with_session_start` 또는 `purchase_first_session` 선언과 비어 있지 않은 evidence_ref를 받는다. 선언이 없거나 concat/merge에서 표지를 잃으면 unknown으로 남긴다. 같은 정의라도 행 수 등 attrs 내용이 다르면 표지를 잃을 수 있다. 생산 버전·날짜에서 새 의미를 만들어내지 않는다.

기본 Feature/DL 호출 목적은 experiment다. 이벤트가 있는 경우 공개 출처 규칙으로 판단한 simulator만 허용하고 커머스는 관측 목적을 명시해야 한다. 혼합 출처는 집계 전 거부하여 같은 customer_id가 출처를 넘어 합쳐지지 않게 한다. 목적 판정은 T0 이전의 실제 계산 대상 행에 한정한다. DL은 고객·lookback 창까지 필터한 뒤 판정한다. 미래 이벤트는 현재 입력의 값·출처 의미를 바꾸지 않는다.

N1 검수 반례와 2026-11-08 사용자 승인에 따라, 범위 안 이벤트 0건은 빈 표·0배열로 반환한다. `groups=[]`, `experiment_source_allowed=null`은 출처 미확인이고, `true`(simulator 행만 있음)·`false`(관측 전용 출처 있음)와 구분한다. 빈 결과를 허용하는 것이 simulator 출처·관측 완전성·무활동을 증명하지는 않는다. 고객 단독/다른 고객 동반 여부로 활동 없는 고객의 DL 수락 여부가 달라졌던 기존 거부안을 철회한다. `model_columns`는 이 메타의 실제 0행 표에만 열 선택을 허용하고, 같은 표지로 비어 있지 않은 행렬을 허가하지 않는다.

Feature 결과에는 별도 attrs를, DL은 선택적 `(배열, 메타데이터)` 반환을 제공한다. 빌더의 결과를 변형 없이 전달하는 경로에서 `model_columns`는 커머스 관측 표와 return_visit count가 있는데 메타데이터를 잃은 표를 거부한다. `combine_first`·`update`는 다른 출처 행을 넣고도 이전 attrs를 남길 수 있으므로 이 검사가 출처 무결성을 증명하지는 않는다. 표 결합·복원 시 원천에서 재인수한다. 기존 메타 없는 수작업 산술 시험 1건은 observation 목적을 명시하며 값의 기대는 완화하지 않는다. 공개 시뮬레이터 API 대역의 page_view/purchase 픽스처에는 생성 시 simulator_version·random_seed를 명시해, 기존에 주장하던 simulator 출처와 실제 공개 판정이 일치하게 한다. 임의의 입력 출처를 뒤에서 덮어쓰지 않는다. 범용 수치 행렬 API의 소유·보안 체계를 바꾸는 결정은 아니다.

### #270(B1) — 관측 리포트 연결

관측 CLI `analytics_report`는 학습하지 않으므로 `purpose="observation"`과 별칭만 제외하는 `observation_columns`를 사용한다. 모델 경로는 계속 `model_columns`를 사용하며 커머스·혼합 입력의 실험 거부를 유지한다. 초기 ③b 구현이 관측 CLI의 기존 호출부까지 막은 것은 의도한 정책이 아닌 회귀다.

혼합 Sink에는 (a) 출처별 새 리포트 형식을 추가, (b) 통합 리포트 3개를 명시적 `not_run`으로 반환, (c) 기존처럼 고객 ID를 합산하는 안을 비교했다. 이번에는 b를 선택한다. a는 출력 이름·출처별 모집단 계약을 추가해야 하고, c는 같은 ID의 다른 출처 고객과 서로 다른 의미의 return count를 합친다. b는 기존 3파일의 위치와 공통 헤더를 유지하며 사유·출처 메타데이터를 남긴다. 혼합 모집단의 `n_customers`는 계산하지 않고 null로 둔다. 단일 출처의 기존 퍼널·코호트·드리프트 구조는 유지한다. 기준/현재 Feature 표가 비면 drift는 `status=not_run`, PSI는 null·등급은 계산 불가다.

계산을 전부 마친 뒤 같은 파일시스템의 임시 디렉터리에 세 JSON을 직렬화하고 교체한다. 계산·직렬화 오류는 기존 결과를 건드리지 않는다. 교체 중 OSError는 이미 바꾼 결과를 역순 복원하거나 새 파일을 지운다. 복원마저 실패하면 이전 결과의 복구 사본을 남기고 그 경로를 오류로 알린다. 기존의 다른 사용자 파일은 수정하지 않는다. 여러 파일을 동시에 읽는 독자나 프로세스 강제 종료까지 포괄하는 전역 원자성·내구성 보장은 이번 선택에 포함하지 않는다.

**근거:** 리드가 요청한 것은 B안에 맞춘 의미·입력 분리이며 원시 재작성이나 새 측정 DQ가 아니다. 출처·의미 메타는 학습 설명 변수가 아니고 선언의 ref는 내용 검증의 대체물이 아니다. simulator 표지도 공개 계약의 기대를 기록할 뿐 실제 생산자의 준수 증명은 성환의 공개 검사 결과로 받는다.

## 기각한 안과 기각 사유

B는 병합 후에도 export에 남는 구 이벤트를 새 정의로 오분류한다. C는 원시 보존 결정에 어긋나고 count 4를 2로 임의 변환해 실제 구매 뒤 첫 방문을 증명할 수 없다. D는 구분 표지가 없어 같은 Feature 이름이 뜻이 다른 입력을 숨긴다. DL에서 session_id로 중복 제거하거나 앞선 구매를 부분 창에서 재검증하는 안도 기존 합을 유지하라는 리드 결정과 다르므로 선택하지 않는다.

## 이 결정이 틀렸다면 어떻게 드러나나

동일 5세션 예시에서 B안 return count 2·visit 5, legacy return count 4·DL visit 9가 보존되지 않는다. 커머스 unknown이 service_version이나 미래 시각만으로 B가 된다. 출처를 섞어 같은 고객으로 합산한다. T0 이벤트·미래 출처가 현재 값을 바꾼다. 관측 입력이 기본 실험 호출이나 model_columns를 조용히 통과한다. 원시 행·기존 F31·학습 설정이 변경된다.

## 민감도

정의 A/B, 출처, 동일 버전 문자열, 부분 시뮬레이터 메타, 0건·미래 행·KST/UTC·관측 목적·메타 소실을 비교한다. 수치 단위를 바꾸거나 모델 성능을 보고 선택을 조정하지 않는다. 신뢰할 생산 이력이 없으면 unknown으로 남기는 조건은 완화하지 않는다.

## 남은 불확실성

실제 Ecommerce #54 이전/이후 파일의 인수 목록과 생산 이력 근거는 데이터 소유자가 제공해야 한다. 최소 인수 기록은 파일 위치·hash, 대상 생산 범위, 구/신 생산자 이력 근거, 선언 책임자와 evidence_ref다. #54 이전 생산분으로 확인된 묶음은 legacy 선언을 붙인다. 근거를 받지 못한 입력의 unknown은 보수적 임시 상태이며, 리드의 구 정의 표시 의무를 완료한 것이 아니다. 이번 반영이 기존 원본을 자동으로 모두 분류했다는 뜻이 아니다. pandas attrs는 영구 저장 계약이 아니므로 CSV/배열 외부화·표 결합 시 별도 출처·정의 메타데이터를 보존하고 원천부터 재인수해야 한다. 선언이 위조됐는지, 임의로 조작한 수치 행렬을 범용 모델에 직접 넣는지까지 이 계층이 증명하지 않는다.

③a의 측정 매핑·공유 DQ, 생산자 B안 검사, PR #265와 양 팀 합의, GATE 1·2 서명, F31 제공 계약은 별도다. 실제 데이터 인수·본 학습·모델 성능 실험·Test/Holdout·봉인은 이번에 수행하지 않는다. 검증과 이후 독립 검수의 소스·범위를 구분해 기록한다.
