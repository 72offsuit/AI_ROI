# DR-S2-trait-sampling — Trait 은 정수 역CDF 매듭표로 뽑아 정수 단위로 상태 JSON 에만 저장하고, 생성 config 를 상태와 world_id 에 결속한다

## 무엇을 정하는가

`DR-S2-hidden-trait-dist` 가 정한 분포를 **`src/simulator` 의 결정성 규칙 아래에서 어떻게 뽑는가.** 규칙은 다음과 같다.

- `DR-S1-rng` 의 "결과에 들어가는 값은 정수만" 규칙을 따른다.
- `tests/test_simulator_api.py:28-33` · `:65-97` 의 AST 금지 목록을 지킨다. float 리터럴, `/`, `**`, `float()`, `sum()`, `hash()`, `math`, `random` 등이 금지다.

함께 정하는 것은 다음과 같다.

- **표집 방식.** 해상도, 오차 상한, 꼬리 절단 질량, α < 1 에서 0 근처 질량을 함께 정한다.
- **값 표현.** 저장할 정수 단위를 정한다.
- **난수 용도 이름.** 기존 스트림과 `RNG_SCHEME` 에 주는 영향을 정한다.
- **저장 위치.**
- **config 결속.** 생성 config 가 바뀌었을 때 옛 상태와 계보를 어떻게 거부할지 정한다.
- **판 상향.** 세 버전 상수를 어떻게 올릴지 정한다.

## 정하지 않으면 무엇이 막히나

- **Phillip 의 구현이 막힌다.** S2 의 신규 모듈 `genconfig.py`·`traits.py`·`persona.py`·`fixedpoint.py` 가 모두 이 결정 위에 선다.
- **재현성 증거가 막힌다.** 이슈 #76 완료 조건은 "같은 seed → 같은 Persona·Trait" 이다. 골든 해시는 3.10·3.12·3.14 와 Linux 에서 일치해야 한다(`DR-S1-rng`).
- **S1 이 S2 로 넘긴 질문에 답해야 한다.** `DR-S1-rng` 「남은 불확실성」은 Beta·LogNormal·Gamma 표집을 정수 규칙 아래에서 어떻게 할지를 S2 가 정하라고 했다.
- **S4·S6 가 막힌다.** S4 는 Trait 값을 정수 분수로 읽는다(`Stream.bernoulli(p_num, p_den)`, `src/simulator/_internal/rng.py:34-37`). S6 의 짝지은 이중 실행(CRN)과 민감도 분석은 "모수를 바꾸면 같은 고객의 값이 단조로 움직이는가"에 달려 있다.
- **상태 판이 막힌다.** S1 상태는 `hidden_traits` 가 비어 있어야 한다고 검사한다(`src/simulator/_internal/world.py:254`). 이 검사를 바꾸려면 상태 판과 계보 규칙을 함께 정해야 한다.

## 결정

**S-B · K=4096 · 양끝 셀 조건부 평균 보존 · 세분 없음 · ppm · 상태 JSON 에만 · 생성 부분 다이제스트를 상태와 `world_id` 에 결속.**

**1. 추첨 — 고객 한 명, Trait 하나에 u64 한 번**

```
페르소나   p = Stream(seed, customer_id, "persona", -1).weighted([ratio_bp …])     # config 순서
Trait t    u = Stream(seed, customer_id, "trait:" + t, -1).next_u64()              # 거부 표집 없음
           i = u >> 52                     # 셀 번호 0 … 4095 (상위 12비트)
           f = u & (2⁵² − 1)               # 셀 안 위치 (하위 52비트)
           값 = Q[p,t][i] + ((Q[p,t][i+1] − Q[p,t][i]) · f) >> 52      # 정수, u 에 단조
```

- **연산.** `>>`·`&`·`*`·`+`·`−` 만 쓴다. 금지 연산은 없다. **보완(2026-10-11):** 구현은 셀 안 보간을 내림이 아니라 반올림(`+ 2⁵¹`)한다 — 아래 「구현 기록」 3항.
- **스트림 분리.** Trait 마다 용도가 따로라서, Trait 하나를 추가·삭제하거나 한 Trait 의 모수를 바꿔도 **다른 Trait 의 값이 바뀌지 않는다.**
- **페르소나 결합.** 같은 u 를 페르소나의 표에 통과시킨다. 그래서 페르소나 비중이 바뀌어 페르소나가 바뀐 고객도 Trait 분위가 그대로다(S6 CRN 과 짝지은 민감도 분석).
- **`day = -1`.** 행동 스트림은 day ≥ 0 이라 열쇠가 겹치지 않는다. 열쇠 형식이 그대로이므로 **`RNG_SCHEME = "sim-rng-v1"` 은 바꾸지 않는다.**
- **가입일과 무관.** S3 가 P6 가입일을 바꿔도 Trait 열쇠에 가입일이 없으므로 Trait 은 바뀌지 않는다.

**2. 매듭표 — 로드 시 config 에서 만든다(S-B)**

- **표의 수.** Beta 는 고유 (α, β) 마다 하나다. 지금 config 는 13 Beta Trait × 6 페르소나에서 **22개 모양**이다. LogNormal 은 표준 정규 분위표 하나를 공유하고, 페르소나별로 `중앙값 × exp(σ·z)` 를 정수로 매긴다. Gamma k=4 는 평균 1 의 분위표 하나를 공유하고 페르소나 평균으로 늘린다.
- **매듭값.** 안쪽 매듭은 `Q[i] = round(F⁻¹(i/4096))` 를 정수 단위로 둔다.
- **양끝 셀 끝값.** `Q[0] = max(하한, 2·E[X | X ≤ Q[1]] − Q[1])`, `Q[4096] = min(상한, 2·E[X | X ≥ Q[4095]] − Q[4095])` 로 둔다. 끝 셀 안의 선형 보간이 균등분포를 만들므로, 그 평균이 실제 조건부 평균과 같아지게 끝값을 고른 것이다.
- **정확도 관문.**
  - 매듭값 계산 오차는 |F(Q[i]) − i/4096| ≤ 10⁻⁶ 이어야 한다(정수 반올림 제외).
  - 최종 분포 오차는 sup\|F(Q̂(u)) − u\| ≤ 10⁻⁴ 이어야 한다.
  - float 참조 테스트(`tests/test_simulator_trait_distribution.py`, float 허용)가 **현재 config 의 모든 모양**에서 잰다. 정수 반올림 때문에 값 v 의 비교는 F(v ± 0.5 단위)로 감싼다. **보완(2026-10-11):** 이 띠 정의는 (a) 양자화 제외 관문과 (b) 저장 단위 해상도 회귀 상한으로 다시 정의했다 — 「구현 기록」 2항.
- **시간 예산.** 프로세스당 1초 이하, config 다이제스트로 캐시한다. 근거는 정수 exp/ln 1회 약 1 µs(3.14 실측)다. 밀도 평가를 22 모양 × 2(2M+1) 회 하면 M=1024 에서 약 0.27 s 로 추정된다(측정이 아니라 추정이다). **구현 뒤에 3.10 에서 실측해 이 DR 에 기록한다.** → 실측 0.21 s(「구현 기록」 7항).
- **되돌림 조건.** 위 관문을 1초 안에 맞추는 정수 알고리즘을 찾지 못하면 **S-A 로 번복한다.**

**정확한 매듭에서의 보간 오차 하한**(`out_knot_design.txt`, K=4096, 양끝 조건부 평균 보존)

**3. 값 표현 — 모두 정수**

| Trait | 단위 | 해상도 근거 |
|---|---|---|
| [0,1] 13종 | **ppm**(0 … 1,000,000) | 해상도 10⁻⁶ 은 보간 오차(10⁻⁵ 자릿수)보다 작다. S4 는 `bernoulli(값, 1_000_000)` 로 바로 쓴다 |
| `base_order_value` | **원** | 측정 계약이 금액을 정수 원으로 둔다(`DR-S1-rng`). 중앙값 31,000원 대비 해상도는 3×10⁻⁵ 이다 |

- **α < 1 과 0 근처 질량.** α < 1 인 칸은 P1 `base_churn_propensity`(μ=0.04, α=0.48) 하나뿐이다.

  - 13.1% 는 1,000 ppm(0.001) 아래다.
  - 0 을 1 로 올려 잡지 않는다. 분포 그대로가 맞고, S4 의 `bernoulli(0, …)` 는 허용된다(`rng.py:35`).
  - 나머지 칸은 α 가 1.2 이상이다. 0 이 될 질량은 4.4×10⁻⁷ 이하로, 26,000명에서 기댓값 0.01명 미만이다.
- **config 도 정수만.** `ratio_bp`, `mu_ppm`, `kappa_milli`(12000), `sigma_ppm`(450000), `shape_milli`(4000), 중앙값·평균은 위 단위를 쓴다. 로더는 다음을 거부한다.
  - `parse_float`·`parse_constant` 로 소수와 `NaN`·`Infinity`
  - `object_pairs_hook` 으로 중복 키
  - 미지 키, ratio 합 ≠ 10000, 페르소나 6종 미만
  - 구간을 벗어난 μ(0 초과 1,000,000 미만)
  - **보완(2026-10-11):** 수치 엔진이 정확도를 검증하지 않은 모수(α·β·κ·σ·k·척도 범위)도 거부한다 — 「구현 기록」 4항

**4. 저장 — 상태 JSON 에만**

- 고객 항목에 `persona`(코드 문자열, `DR-S2-persona-mix`)와 `hidden_traits`(16개 이름 → 정수)를 둔다. 상태 파일은 `data/hidden/simulator/states/` 아래에만 있다.
- **`hidden_traits.parquet` 표 산출물(data_spec §15.1)은 S6·S8 로 미룬다.** 지금은 그것을 읽는 쪽이 없다.
- 상태 검증(`_validate_customer`)은 다음을 본다. Trait 은 **다시 생성하지 않는다** — `advance` 마다 돌기 때문이다. 범위 안의 위조값은 계보(초기 다이제스트 대조)가 잡는다.
  - 허용된 페르소나 코드인지
  - Trait 키 집합이 정확히 16개인지
  - 값이 정수인지(bool 제외), 단위별 범위 안인지 — **보완:** 실제 기준은 그 페르소나 매듭표의 [Q[0], Q[4096]] 다(「구현 기록」 5항)

**5. config 결속**

```
config_digest = sha256( canonical_json({config_version, personas, hidden_traits}) )   # 생성 부분만
상태 최상위   generation = {"config_version": …, "config_digest": …}
world_id      = "W-" + sha256( canonical_json(["sim-world-v2", seed, n, profile, start_ms, config_digest]) )[:16]
초기 다이제스트 캐시 열쇠 = (seed, n, profile, config_digest)
```

- `decode` 에서 `generation` 이 현재 config 와 다르면 **`IncompatibleState`** 다.
- 계보에서는 `initial_digest` 를 계산하기 **전에** `world_id` 를 대조한다. 다르면 **`LineageBroken("생성 설정이 이 계보를 만든 설정과 다르다")`** 다. 원인이 변조가 아니라 config 변경이라는 것을 오류가 먼저 말한다.
- 공개 API 쪽에서는 `init` 이 `ConfigError` 를 `SimulatorError` 로 바꿔 던진다. 오류 메시지에 hidden 경로를 넣지 않는다.
- 다이제스트 범위를 **생성 부분**으로 한정한 이유가 있다. 뒤 태스크가 CFG-001 의 `simulation`·`churn`·`experiment` 블록을 추가해도 S2 생성 결과는 같다. 그런데 파일 전체를 다이제스트하면 그것을 "다른 세계"로 판정한다. 그 블록들은 읽는 태스크가 자기 결속을 둔다.

**근거.**

- **S-B 를 고른 이유.** "config 를 바꾸면 반영된다"를 구조로 보장하는 유일한 안이기 때문이다. S-A 도 같은 분포를 내지만 표와 config 가 두 원천이 되고, 그 어긋남을 테스트로만 잡게 된다.
- **고정소수점 수치 코드는 어차피 생긴다.** S4 감쇠와 S6 처치 부스트가 `exp` 를 쓴다(`docs/data_spec.html:267` · `:357`). S2 의 `fixedpoint.py` 는 그 첫 사용처다.
- **K=4096 이면 충분하다.** 양끝 셀 조건부 평균 보존을 붙이면 K=4096 에서 관문(10⁻⁴)을 넉넉히 맞춘다. K 를 키우면 생성 비용만 늘어난다.
- **u64 한 번 추첨.** 거부 표집이 없어 고객당 소비 난수가 고정이다. 상위 12비트가 셀, 하위 52비트가 보간 위치라 2⁻⁶⁴ 해상도를 다 쓴다.

## 구현 기록 (보완 · 2026-10-11 리뷰·QA 반영)

**이 절은 결정을 바꾸지 않는다.** 상태는 `확정` 그대로다. 번복이 아니라 보완이다(Thomas 판단). 구현(Phillip) 뒤 Thomas 리뷰 M3 와 Matthias QA D-5·D-6 이 "구현에서 생긴 결정과 약속한 실측이 DR 에 없다"고 지적했고, 수정 1라운드 뒤의 상태를 여기에 적는다. 담는 것은 세 가지다.

- 위 본문이 구현자에게 맡긴 것: 매듭값 알고리즘
- 구현 중 사용자가 정한 것 둘: 관문 재정의, 추첨 반올림
- 본문이 "구현 뒤 기록"하기로 한 것: 실측

위 본문과 이 절이 다르면 **이 절이 현재 구현이다.** 수치는 따로 적지 않으면 James 가 2026-10-11 작업 트리에서 다시 잰 값이다(`python3 -m tests.test_simulator_trait_distribution report`, Python 3.14.7, macOS arm64). Phillip 보고값과 대조했고 아래에 출처를 함께 적는다.

**1. 매듭값 알고리즘 — 본문 2절이 구현자에게 맡긴 것**

- **수치 표현.** 정수 고정소수점 2⁶⁴ 척도다(`fixedpoint.py`, `FRAC = 64`). ln·exp·lgamma·정칙 불완전 감마·불완전 베타(Lentz 연분수)를 정수 연산만으로 구현했다.
- **정확히 푸는 매듭.** 표당 375개다. 양 꼬리 64개씩(i = 1 … 64, 4032 … 4095)과 가운데 16칸 간격을 푼다. 방법은 bracket 안 Newton–Halley 이고, 걸음이 bracket 을 벗어나면 이분한다. 직전 매듭의 3차 Taylor 예측이 출발점이다(`traits._solve`·`_predict`).
- **나머지 매듭.** 이웃 정확 매듭의 값과 Q′ = 1/f, Q″ = G·Q′² 로 5차 Hermite 보간을 한다. G = −(ln f)′ 는 유리식이라 초월함수가 필요 없다.
- **푸는 양.** 고유 모양 24개(Beta 22 · 표준 정규 1 · Gamma(4) 1)를 풀고, 그것으로 정수 표 40개를 만든다.
- **정확도.** 반올림 전 매듭 오차는 최대 5.17×10⁻⁹ 다. 분포족별로는 Beta 4.98×10⁻⁹ · 정규 4.28×10⁻⁹ · Gamma 5.17×10⁻⁹ 이고, 관문 10⁻⁶ 의 약 1/190 이다.
- **로더 범위 전역.** Thomas 가 퍼징했다. 대상은 무작위 Beta 1,510개와 모서리 10개, σ 1 ppm ~ 1, k 1 ~ 100, 척도 1 ~ 10¹² 이다. 결과는 예외 0건, 비단조 0건, 최악 원시 매듭 오차 6.0×10⁻⁹ 였다(리뷰 「확인한 것」). 범위 끝 모양은 `TestEngineAtTheEdgesOfTheLoaderRange` 가 계속 잰다. Beta (α, β) = (0.3, 0.7) · (0.7, 0.3) · (0.3, 99.7) · (99.7, 0.3) · (50, 50) 과 Gamma k = 1 · 100 이다.
- **판정.** 「남은 불확실성」의 "정수 매듭표 생성 알고리즘은 아직 증명되지 않았다"는 해소됐다. S-A 로 되돌릴 조건에 해당하지 않는다.

**2. 정확도 관문 재정의 — 사용자 결정 2026-10-11 「저장 단위 유지 + 기준 정의 고침」**

- **원래 문구의 문제.** 본문 2절은 "값 v 의 비교는 F(v ± 0.5 단위)로 감싼다"고 적었다. 이 문구는 매듭의 정수 반올림(±0.5)과 추첨의 정수화(±0.5)를 구분하지 않았다.
  - 두 반올림이 겹치므로, 정수 매듭 + 정수 추첨 구조에서 이 띠로 모든 Trait 에 sup ≤ 10⁻⁴ 를 요구하는 것은 **원리상 달성할 수 없다.** 추첨을 반올림으로 바꿔도 1.22×10⁻⁴ 가 남는다(Thomas M3).
  - 초기 구현은 띠를 [v − 0.5, v + 1.5] 로 넓혀 통과시켰다. 그런데 그 변경이 DR 에 없었다. 또 단위가 거친 Trait 에서는 관문이 사실상 아무것도 재지 않았다(M3).
- **고친 정의.** 저장 단위(ppm·원·밀리일·밀리회)는 그대로 두고 관문을 둘로 나눴다(`tests/test_simulator_trait_distribution.py`).

- **(b) 의 성격.** (b) 는 관문이 아니라 회귀 방지 장치다. config·단위·추첨식을 바꾸면 `report` 로 다시 재서 고친다(`docs/persona_spec.md` 8절).
- **(b) 가 10⁻⁴ 를 넘는 것은 정확도 결함이 아니다.** 해상도 때문이다. 방문 빈도 1 단위는 0.001회/주다.
- **QA 수치와 비교하지 않는다.** QA D-5 의 3.41×10⁻³ · 6.35×10⁻⁴ · 1.63×10⁻⁴ 는 수정 전 값이다(내림 추첨, 점별 \|F(v + 0.5) − u\| 정의). 정의가 달라 위 표와 직접 비교하지 않는다.
- **반증 조건 읽는 법.** 「이 결정이 틀렸다면」 첫 항목의 "sup … 10⁻⁴" 는 (a) 를 뜻한다.

**3. 추첨 정수화: 내림 → 반올림 — 사용자 결정 2026-10-11**

- **바꾼 식.** 본문 1절 식 `((Q[i+1] − Q[i]) · f) >> 52` 를 `((Q[i+1] − Q[i]) · f + 2⁵¹) >> 52` 로 바꿨다(`traits.draw`).
  - 이유(Thomas L3): 내림은 셀 폭이 0 보다 큰 셀에서 값을 체계적으로 아래로 치우치게 한다. 크기는 −0.16 ~ −0.44 단위, 상한 0.5 단위다.
  - 연산은 여전히 `+`·`*`·`>>` 뿐이다. 결과는 u 에 단조이고, [Q[i], Q[i+1]] 안이므로 [Q[0], Q[4096]] 안이다.
- **남은 편향.** 반올림 뒤 뽑힌 정수의 정확한 기댓값과 참 평균의 차이는 **최대 |0.91| 단위**다. P1 `base_churn_propensity` 가 +0.912 ppm(상대 2.3×10⁻⁵)이고, 나머지 Trait 은 상대 1×10⁻⁵ 이하다. 이 잔여는 추첨이 아니라 매듭표 꼬리 처리와 보간에서 온다.
- **0 ppm 질량.** P1 `base_churn_propensity` 는 **0.330%** 다(매듭표 정확 계산 0.3296%). 참조 F(0.5 ppm) 는 0.341% 다.
  - 본문 3절의 0.34% 와 같은 크기다. **본문 값은 맞다.**
  - 초기 구현 보고의 0.48% 는 F(1 ppm) 을 쓴 오류였다(Thomas M2, Matthias D-5). 내림 추첨에서도 실측은 0.341 ~ 0.342% 였다.
- **바뀐 골든.** 생성 골든 `GENERATION_GOLDEN` 은 `c9c991a24689051c08a739b06fe5701a0dd435a44f25ce45d1c390b572dae762` 이고, `sim-0.2` 끝 상태 골든은 `047c9d783cc91c1465a93d229c0916aad1e727c3f2a444ae1032135d68e79e72` 다.
  - 리뷰·QA 보고서의 생성 골든 `3f0967b1…` 은 수정 전(내림) 값이다.
  - 이벤트 골든은 그대로다. `sim-0.2` 는 `77d67f87…` · 716건이고, 라벨을 되돌리면 `sim-0.1` 의 `fdfbc1e4…` 와 같다. 행동이 아직 Trait 을 읽지 않기 때문이다.
  - `sim-0.2` 는 아직 커밋되지 않았다. `main` 의 판은 `sim-0.1` 이다. 그래서 판을 더 올리지 않고 첫 고정값을 바꿨다. 3.10 · 3.12 · 3.14 에서 `tests.test_simulator_reproducibility` 가 통과했다.

**4. 로더 검증 범위 — 새 제약**

본문 3절은 μ 구간(0 초과 1,000,000 미만)만 적었다. 구현은 **수치 엔진이 정확도를 검증하지 않은 모수도 로드에서 거부한다**(`genconfig.FAMILIES` · `_BETA_SHAPE_NANO`).

| 분포족 | 받는 범위 | config 단위 |
|---|---|---|
| Beta | α = μκ, β = (1 − μ)κ 가 모두 [0.3, 100] · κ ∈ [1, 100] · μ ∈ [1, 999,999] ppm | `kappa_milli` 1,000 ~ 100,000 |
| LogNormal | σ ∈ (0, 1] · 중앙값 ∈ [1,000, 10¹²] 정수 단위 | `sigma_ppm` 1 ~ 1,000,000 |
| Gamma | k ∈ [1, 100] · 평균 ∈ [1,000, 10¹²] 정수 단위 | `shape_milli` 1,000 ~ 100,000 |

- **중앙값·평균 하한 1,000 의 이유(Thomas L4).** 척도가 작으면 값이 몇 개의 정수로 뭉개진다. 그런데도 반올림 띠가 오차를 흡수해 관문이 잡지 못한다. 하한이 1,000 이면 1 단위가 척도의 0.1% 이하가 된다. 지금 최솟값은 1,400(P5 방문 빈도)이라 ×0.8 민감도(1,120)도 받는다.
- **퍼짐 하한(Phillip 2라운드, Thomas R1-L3).** LogNormal 은 σ·중앙값 ≥ 100 정수 단위, Gamma 는 평균/√k ≥ 100 단위여야 한다(`genconfig.MIN_SPREAD_UNITS` · `_check_spread`). 비교는 정수로 한다. LogNormal 은 `sigma_ppm · median ≥ 100 · 10⁶`, Gamma 는 제곱해서 `mean² · 1000 ≥ 100² · shape_milli` 다. 해상도 조건은 척도가 아니라 퍼짐을 기준으로 해야 하기 때문이다. 척도 하한만 있으면 σ 가 극소일 때 전원이 한 값으로 뭉개지는데도 관문 (a)·(b) 를 모두 통과한다. 지금 config 의 최솟값은 LogNormal 2,700(`purchase_cycle` P1)과 Gamma 700(P5)이라 통과한다. 새로 생긴 하한의 예로, `purchase_cycle` P1(중앙값 6,000)은 σ ≥ 0.016667(16,667 ppm)이어야 한다. Gamma 조건은 지금 범위(k ≤ 100, 평균 ≥ 1,000)에서는 늘 성립한다. 범위를 넓힐 때를 대비한 방어다(`tests/test_simulator_persona.py` `test_spread_below_the_unit_resolution_floor`).
- **GATE 1 전 조정 공간을 좁힌다.** 위 결정에 없던 제약이다.
  - **κ=12 에서 μ 는 [25,000, 975,000] ppm 이다.** P1 `base_churn_propensity`(μ=0.04)는 0.025 아래로 내릴 수 없다. 지금 값의 0.625배까지다. S5 가 생성 이탈률 15~25% 를 맞출 때 막힐 수 있는 손잡이다.
  - **κ 를 낮추는 방향도 막힌다.** 같은 칸에서 κ ≥ 7.5 다. `DR-S2-hidden-trait-dist` 의 κ=6 대안(기각)을 다시 열면 이 칸(α=0.24)이 로드에서 거부된다. 그 DR 「민감도」의 κ ×0.8(9.6, α=0.384)과 `repurchase_propensity` ×1.2(P1 0.95, β=0.6)는 받는다.
- **넓히는 절차.** 새 모양의 정확도를 `tests/test_simulator_trait_distribution.py`(범위 끝 테스트 포함)로 먼저 확인한 뒤 범위를 넓힌다. 그 변경은 이 DR 의 보완이나 번복으로 남긴다. 범위를 넓히자는 근거는 가드레일뿐이다. AI 결과는 근거가 될 수 없다(FREEZE-002).

**5. 상태 검증 범위**

- **기준.** 본문 4절의 "단위별 범위" 대신, **그 고객 페르소나의 매듭표 [Q[0], Q[4096]]** 안인지 본다(`world._Identity`). 결정적이고 단위 범위보다 엄격하다.
- **비용.** 표는 config 다이제스트 캐시를 다시 쓰므로 `decode` 마다 다시 풀지 않는다.
- **범위 안 위조.** 본문대로 계보가 잡는다. Matthias 가 재봉인 위조 11종이 모두 거부되는 것을 확인했다.
- **본문이 정하지 않은 동작 하나.** `load_state` 에서 생성 config 를 읽지 못하면 `StateFormatError` 다(Thomas L9).

**6. 오류 메시지 정책**

본문 5절 "오류 메시지에 hidden 경로를 넣지 않는다"를 다음처럼 구체화했다. Thomas L5 가 지적한 "이름 노출 정책 불일치"를 이것으로 닫는다.

- **공개 예외 메시지에 싣지 않는 것.** 숨은 필드 이름(`persona`·`hidden_traits`), persona id, Trait 값이다.
- **상태 검증 오류.** 위치(`customers[i]`)와 사유만 싣는다.
  - Trait 은 이름 대신 config 순번(`Trait #n`)으로 가리킨다.
  - 모르는 키·빠진 키 목록에서 숨은 필드는 "숨은 필드" 표기로 가린다.
- **config 오류.** 공개 메시지는 고정 문구("생성 설정 … 을 쓸 수 없다 … 자세한 사유는 원인 예외(`__cause__`)에 있다")다. 키·모수 값·persona id 는 `__cause__` 의 `ConfigError` 에만 둔다(`api.py` `_CONFIG_UNUSABLE`).

**8. 「남은 불확실성」 갱신**

- **해소된 것.**
  - **알고리즘 정확도**: 1항과 2항 (a).
  - **3.10 생성 시간**: 7항.
  - **상태 크기와 `decode`·`advance` 비용 증가**: 7항에서 측정했다.
- **남은 것.**
  - **Linux 골든 — BLOCKED.** 로컬은 macOS 뿐이다. 첫 PR CI(`python-compat.yml` · `tests-with-deps.yml`)가 확인한다. Windows 는 확인하지 않는다.
  - **S3 규모 성능.** `advance` 1회는 `encode` → `decode` → `encode` 를 거친다. 그래서 약 +0.17 s(3.12)가 붙고, 365회 일 단위로 부르면 약 +60 s 다(Thomas L6 추정). 창이 여럿이면 창 수만큼 곱해진다. 「이 결정이 틀렸다면」의 크기·속도 항목은 S3 가 판정한다. 검토 후보는 `advance` 안의 `_Identity` 재검증을 상태 적재 시점으로만 한정하는 것이다.
  - **이름 없는 숫자값 누수 — 격리 테스트의 원리상 한계.** `tests/test_isolation.py` 는 Trait 사전, persona id(식별자 경계), Trait 이름, 생성 라벨을 찾는다. 찾는 곳은 출력 루트의 내용·경로 이름, 실행 기록, 공개 반환값, 대표 오류 메시지다. 그러나 Trait 값 하나가 이름 없이 숫자로만 실리면 잡지 못한다. 값이 평범한 정수라 이벤트의 수량·시간·금액과 구분할 수 없기 때문이다. 이 경로는 코드 리뷰가 맡는다(`docs/persona_spec.md` 7절, 후속 이슈 후보).
  - **persona 별칭(P1~P6)은 지문에 넣지 않는다.** 측정 코드의 문자열과 겹쳐 거짓 실패가 나기 때문이다(사용자 결정 2026-10-11). 지문은 persona id 만 쓴다.
  - **로더 범위가 S5·S6 의 조정 손잡이를 막을 수 있다**(4항).

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| S-A (오프라인 표 커밋) | 두 번째 원천이 생긴다. 재생성을 잊는 실패를 테스트로만 막을 수 있다. 재생성 도구의 판·플랫폼 의존이 표 diff 로 새어 나온다. **다만 S-B 의 관문이 실패할 때 돌아갈 안이다** |
| S-C (추첨마다 정확 변환) | 수십 초 규모로 추정한다(측정하지 않았다). 얻는 것은 보간 오차 6.5×10⁻⁵ 를 없애는 것뿐이다 |
| S-D (정수 α·β 순서통계량) | κ=12 에서 μ 가 1/12 격자에 묶여 data_spec 의 μ 다수를 표현할 수 없다. LogNormal·Gamma 를 다루지 못한다 |
| S-P (Pólya urn) | 정수 α·β 가 필요하고 유한 단계에서는 이산 근사다. S-D 보다 비싸다 |
| S-F · S-F′ (float) | `DR-S1-rng` 의 판 무관 동일 결정과 AST 검사를 깬다. 정수로 같은 일을 할 수 있다 |
| 양끝 셀 끝값을 지지 끝(0·1·∞)에 두기 | ∞ 는 표현할 수 없다. Beta 의 끝을 0·1 로 두면 끝 셀이 0.53 → 1.0 같은 넓은 균등 구간이 된다. 그러면 K=4096 에서도 sup 오차가 1.78×10⁻⁴ 로 관문을 넘고, α=0.48 의 분산 오차가 2.4% 가 된다(`out_knot_table.txt` (a)). **처음 계획(K=4096 + 단순 보간)이 관문을 못 맞춘다는 것을 이 계산이 보였다** |
| 끝값을 Q(1 − 1/(4K)) 로 자르기 | 꼬리 질량 6.1×10⁻⁵ 를 잃고, 분산이 −0.14% 로 편향된다. 평균 보존보다 나쁘다 |
| K=16384 | 관문을 이미 맞추므로 생성 비용 4배를 정당화하지 못한다 |
| 꼬리 이진 세분(2⁻¹³ … 2⁻²⁴) | 잘린 질량이 3.3×10⁻⁵ 에서 8×10⁻⁹ 로 줄지만, 분산 오차가 1.4×10⁻⁴ 에서 4.6×10⁻⁴ 로 오히려 커진다. 조회에 분기가 생긴다. 고객 26,000명에서 잘린 질량의 실익이 없다. S5·S6 가 극단 꼬리(예: 객단가 상위 0.001%)를 쓰게 되면 다시 연다 |
| bp(10⁴) 단위 | 해상도 10⁻⁴ 가 보간 오차보다 거칠다. α=0.48 칸에서 0 이 되는 질량이 커진다 |
| ppb(10⁹) 단위 | 0 이 되는 질량이 7명에서 약 0.2명으로 줄 뿐이다. ppm 이 bp·ppm 관례(`ratio_bp`)와 읽기 쉽다. 차이에 실익이 없다 |
| 별도 `hidden_traits` 산출물 지금 생성 | 읽는 쪽이 없다. 원천이 둘이 된다. S6·S8 이 필요할 때 상태에서 유도한다 |
| 저장하지 않고 decode 때 재생성 | 상태가 13 MB 작아진다. 하지만 상태가 자기완결적이지 않게 되고(`DR-S1-world-state`), 숨은 값을 읽는 모든 쪽(S4 행동, 진단, Matthias 독립 검증)이 생성기를 import 해야 한다. `advance` 마다 재생성 비용이 든다 |
| config 파일 전체 다이제스트 | 생성과 무관한 블록을 추가해도 모든 S2 상태와 계보가 무효가 된다 |
| `world_id` 에 결속하지 않고 상태 필드만 | 계보 대조가 config 변경을 "변조"로 오진한다(`lineage.py:177` · `:189`) |
| `RNG_SCHEME` 상향 | 열쇠 형식이 그대로라 상향 사유가 없다. 올리면 S1 행동 스트림까지 바뀌어 U4 의 "행동 불변" 증명이 불가능해진다 |

## 이 결정이 틀렸다면 어떻게 드러나나

- **정확도 관문 실패.** float 참조 테스트에서 어떤 config 모양의 sup\|F(Q̂(u)) − u\| 가 10⁻⁴ 를 넘거나 매듭 오차가 10⁻⁶ 를 넘으면, 정수 수치 코드나 끝값 처리가 틀렸다. (보완: 여기서 sup 은 「구현 기록」 2항의 (a) 다.)
- **판·플랫폼 결정성 실패.** 생성 골든(seed 42, 50명의 `[cid, persona, traits]` sha256)이 3.10 · 3.12 · 3.14 또는 Linux CI 중 한 곳에서만 다르면, 판에 의존하는 연산이 매듭표 생성 경로에 남아 있다.
- **시간 예산 초과.** 매듭표 생성이 3.10 에서 1초를 넘으면 S-A 로 번복한다.
- **스트림 독립성 실패.** Trait 하나의 모수를 바꿨는데 다른 Trait 값이 하나라도 바뀌면 스트림이 섞였다. 15명과 16명의 앞 15명이 다르면 열쇠에 n 이 섞였다.
- **결속 실패.** config 를 바꾼 뒤 옛 상태가 `load_state` 로 읽히면 결속이 빠졌다. 내용만 바꾸고 `config_version` 을 올리지 않은 변경이 `CONFIG_PINS` 테스트를 통과하면 판 관리가 빠졌다.
- **크기·속도 문제.** 실측 상태 크기나 `decode` 시간이 S3 규모(26,000명 × 창 수)에서 문제가 되면 "저장하지 않고 재생성" 안을 다시 연다.

## 민감도

- **K 를 바꾸면.** 끝값 처리가 같을 때 sup 오차는 대략 1/K 에 비례한다. 정확 매듭 기준으로 K=1024 는 이 설계에서 약 2.6×10⁻⁴(단순 끝값으로는 7.2×10⁻⁴)이고, K=4096 은 6.5×10⁻⁵, K=16384 는 1.6×10⁻⁵ 다. K 를 ±20% 바꾸는 것은 2의 거듭제곱 구조상 의미가 없다. 한 단계(×4) 내리면 관문을 넘는다.
- **모수 ±20%(분포 민감도).** S-B 는 config 를 고치면 매듭표가 자동으로 다시 생성되고 같은 고객의 u 가 그대로다. 그래서 `DR-S2-hidden-trait-dist` 「민감도」의 짝지은 비교를 시뮬레이터 안에서 그대로 재현할 수 있다. S-A 였다면 시나리오마다 표를 재생성하고 커밋해야 한다.
- **단위.** ppm 대신 bp 를 쓰면 α=0.48 칸에서 0 으로 저장되는 질량이 0.34% 에서 3.1% 로 커진다(P(X < 5×10⁻⁵), 계산). ppb 는 0.012% 다. ±20% 자릿수 변화로는 결과가 달라지지 않는다.
- **상태 크기.** 고객 수에 정비례한다. 고객 ±20% 면 상태 파일당 약 10.8~16.1 MB 다(추정).

## 남은 불확실성

- **정수 매듭표 생성 알고리즘은 아직 증명되지 않았다.** 정수 exp/ln 은 정확하고 빠르다(1 µs, 10⁻¹⁸). 하지만 정칙 불완전 베타와 정규 분위를 관문 10⁻⁶ 로 1초 안에 계산하는 정수 알고리즘은 이 DR 에서 시연하지 못했다. 조잡한 적분 시제품은 6.45×10⁻⁴ 로 실패했다. Phillip 의 구현과 float 참조 테스트가 해소한다. 실패하면 S-A 로 번복한다. **→ 해소(2026-10-11): 「구현 기록」 1·2항.**
- **실측하지 않은 것.** 3.10 에서의 생성 시간, 상태 크기, `decode`·`advance` 검증 비용 증가는 측정하지 않았다. 구현 뒤에 이 DR 에 기록한다. **→ 측정함(2026-10-11): 「구현 기록」 7항.** S3 규모 영향은 남는다(8항).
- **Linux 골든.** 첫 PR CI 가 확인한다. Windows 는 확인하지 않는다(`DR-S1-rng` 과 같다).
- **`hidden_traits.parquet` 의 시점과 형태.** S6·S8 이 정한다. 상태 JSON 이 원천이라는 이 결정과 어긋나지 않게, 표는 상태에서 유도하는 파생물이어야 한다.
- 후속 이슈 후보(보고만 하고 고치지 않는다): `src/simulator/_internal/AGENTS.md` 와 `docs/data_spec.html:236` 의 `customer_seed = hash(random_seed, customer_id)` · PCG64 · parquet 표기가 이 결정과 다르다.
