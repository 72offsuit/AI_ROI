## 무엇을 정하는가

42일 구매 라벨과 이벤트 결과 총량을 확정할 관측·쓰기·읽기 근거, 구매 관측 상태, 필드별 결손의 전달 방식을 정한다. 이 기록은 #179 첫 묶음(R1·R5·R6)을 다룬다. R2·R3·R4는 DR-179-evaluation-protocol.md에 별도로 기록하며, 두 기록 모두 실제 데이터 성능 평가나 이슈 종료를 뜻하지 않는다.

## 정하지 않으면 무엇이 막히나

마지막 이벤트가 하루 일찍 끝나거나 구매가 저장에서 거부돼도 무구매·부분 매출이 정식 결과로 남는다. 구매를 관측할 수 없는 분기의 가짜 이탈률이 시간 평가와 가드레일에 들어갈 수 있다.

## 결정

A를 적용한다. Feature는 timestamp가 T0 미만인 이벤트, 라벨은 KST의 [T0, T0+42일)이다. 이는 data_spec의 모든 표기와 같다는 해석이 아니라 공개 API·현재 실행 창에 맞춰 선택한 정본이다. T0=10월 1일 00시일 때 일 단위 T0+1~T0+42 표기는 [10월 2일,11월 13일), 시각 공식 T0 < t ≤ T0+42는 (10월 1일,11월 12일]로 서로 다르다. 이전 초안의 index_date를 Feature 마지막 날로 재해석하는 문장은 철회한다. 공용 문서 자체를 단독 수정하지 않는다.

관측 시작이 T0 이하이고 종료가 라벨 창 끝 이상이어야 한다. 같은 run_id의 읽을 수 있는 실행 기록이 정확히 하나이며 rejected가 정수 0이고, 해당 세계의 events.purchase가 관측 가능한 상태여야 라벨을 확정한다. 근거 누락·손상·쓰기 거부·구매 관측 불가는 정식 라벨을 만들지 않는다. 진단 허용 모드에서도 churn·purchases·revenue는 전부 null이며 사유를 남긴다.

파일 읽기는 실행이 주장한 파티션·내용 다이제스트·중복 제거 전 원시 행 수를 먼저 대조한다. 실험 입력의 실행별 sources 합계와 simulator 단일 출처도 확인한다. 현재 세계의 사슬 밖 실행·미주장 파일·누락 파일을 거부한다. 분기 외부 부모는 검증된 history의 run_read_evidence.run_id(머리)와 정확히 같아야 한다. 조상 ID 목록에 포함됐다는 사실만으로 연결을 승인하지 않는다. 부모가 None이거나 근거가 없으면 HISTORY_PARENT_UNRESOLVED 등 사유로 해당 읽기만 not_run으로 남긴다. 이는 연결을 증명하지 못한 입력의 보수적 처리이며, 실제 시뮬레이터가 None 부모를 제공하는지 또는 허용 계약인지 확정한 결정은 아니다. 실제 E2E·공개 정의 확인은 남아 있다.

2026-10-30 독립 재검토의 비차단 R1에 따라 영향 범위를 명시한다. 분기 읽기가 not_run이면 read_complete=False가 되어 그 분기의 branch_economics도 not_run이고, 정식 sim_*·measured_* 경제 입력은 null이다. 단지 진단용 읽기 표시만 바뀌는 것이 아니다. S1 분기에 이 문제가 생기면 S1을 기준으로 한 S2~S5의 증분 이익·ROI·관련 가드레일도 계산 불가로 전달된다. None 부모를 허용하던 v02에 비해 엄격해진 경로이므로 병합 전 실제 연결을 확인해야 한다. CI의 tests-with-deps에서 tests/test_orchestration_sprint.py가 분기 measured_economics와 incremental_profit_status를 정상으로 확인하는 결과를 대조한다. 실패하면 검사를 완화해 통과시키지 않고, 리드·시뮬레이터 팀의 공개 계약 정의로 원인을 해소한다. 이 기록은 CI 또는 실제 시뮬레이터 E2E 통과를 선언하지 않는다.

N3 보완으로 읽기 감사에 실행별 run_rejections, 사슬 전체 chain_rejected_total, 대상 실행을 뺀 ancestor_rejected_total을 남긴다. 검증된 history의 실행별 거부 수를 분기까지 한 번만 이어받는다. 대상 실행 rejected는 라벨 창 판정용으로 따로 유지한다. 조상 거부의 Feature·Eligible·S1 영향은 감사에 드러내되, 이를 이유로 새 차단 정책을 만들지는 않는다. run_meta의 t1/t2, Feature(t1/t2)의 attrs, 각 전략 분기의 event_read_evidence로 같은 근거를 전달한다. 누락된 조상 수를 0으로 대치하지 않는다.

Feature(t1/t2)의 attrs.event_read_evidence 전달은 메모리 안의 감사 정보다. 게시되는 run_meta.feature_attrs에 그 객체 전체를 복제하지 않으며, 파일 산출물의 같은 근거는 run_meta.event_read_evidence에서 확인한다. main_metric_windows도 목적·창·구매 상태만 담는다. 구매 상태의 상세 사유는 이력 조회의 run_meta.purchase_generated.detail과 라벨 조회의 label_observation.purchase_detail, 조회 예외 메시지는 실행 로그에서 확인한다.

루트 단독 계보 검사에서 외부 부모가 없다는 결과를 정상으로 덮지 않는다. 읽기 중 파일 크기·수정 시각이 바뀌면 중단한다. source root·run_id·읽기 상태를 라벨 감사에 남기며 읽기 증거와 다시 읽은 쓰기 기록의 rejected도 일치해야 한다. 검증된 history 근거는 같은 프로세스가 읽기 검증 후 보존한 영수증이라는 전제이며 임의의 외부 선언을 인증하는 서명은 아니다. 실행 기록은 공개 계약의 불변 기록이라는 전제이며 적대적 동시 변조의 잠금·원자적 스냅샷을 새로 제공하지 않는다.

전체 Feature 모집단을 유지한다. churn·revenue·purchases 각각 유효·결측·비정상 수를 기록한다. 해당 필드가 전원 유효하고 관측 근거도 유효할 때만 전체 합계·평균을 정식 값으로 낸다. 부분 합계는 observed_* 참고 필드로만 남기며 ROI 후보 키로 보내지 않는다. 실제 0은 유지하고 빈 모집단은 null이다.

2026-10-30 독립 검토 B1과 사용자의 보완 지시에 따라, margin_rate_basis와 S1 구매 입력 게이트의 창은 기존 [warmup 시작,t2)로 복원한다. Y1 라벨의 구매 상태만 별도 [t1,t2) 원본 metrics로 판정한다. 본선은 목적이 다른 두 조회이며 각 조회를 한 번씩 호출한다. 두 결과와 실패 상태를 서로 덮어쓰지 않고 main_metric_windows에 목적·시작·끝·구매 상태를 남긴다. 각 전략 분기는 [t2,t2+42일) 원본으로 상태를 판정한 뒤 그 같은 객체를 JSON으로 변환한다. 세계당 metrics 한 번이라는 이전 시험 기대는 리드 요구가 아니므로 철회한다. 실제 margin_rate_basis를 통과하는 창별 금액 반례와 이력/라벨 조회가 독립적으로 실패하는 시험을 둔다. #171 소관의 이익률 정책·S4/S5 가치 의미를 바꾸는 결정은 하지 않는다. S0의 유효한 라벨이 없으면 시간 평가를 not_run으로 남긴다. 독립적으로 유효한 측정 이익·비용 ROI는 이벤트 매출 결손만으로 지우지 않는다.

다만 같은 저장 자료에서 계산한 sim_*·measured_*도 쓰기 거부나 미확정 창과 독립적인 근거는 아니다. 창·쓰기·읽기 근거가 부족하면 원본 측정 보고서는 보존하되 정식 ROI 입력에서는 해당 별칭을 모두 null로 둔다. 읽기 자체를 검증하지 못했으면 branch_economics를 실행하지 않고 not_run 사유를 남긴다. 반대로 창·쓰기·읽기 성공은 확인됐고 이벤트 매출 필드만 결손이면 유효한 측정 이익·비용 입력을 유지한다.

**근거:** 위 리드 결정과 공개 계약. 측정 계층·시뮬레이터·공통 계약은 수정하지 않는다.

## 기각한 안과 기각 사유

| 안 | 왜 택하지 않았나 |
|---|---|
| B 또는 max(timestamp)로 완전성을 증명 | 이벤트 부재와 관측 중단을 구별하지 못하며 반열린 읽기와 맞지 않음 |
| C 또는 sum(min_count=1)만 적용 | 일부 결측의 유한 부분합을 정식 합계로 잘못 승인함 |
| 파일 없음·rejected 누락을 0으로 처리 | 쓰기 성공을 알 수 없는 상태를 성공으로 바꿈 |
| 본선 구매 상태를 모든 분기에 복사 | 분기별 상태 차이를 숨김 |
| JSON dict를 MetricValue 함수에 전달 | 자료형 계약이 다르고 상태 해석을 놓침 |
| 이벤트 매출 결손만으로 모든 ROI 차단 | 독립 측정 이익·비용 근거를 불필요하게 무효화함 |

## 이 결정이 틀렸다면 어떻게 드러나나

창 끝 직전 관측을 완전으로 승인하거나, 쓰기 거부 뒤 churn=1·매출=0 또는 부분 매출이 남는다. 필드 결측이 다른 필드에 숨거나 부분합이 방향 확인 값·가드레일로 우회한다. 한 분기의 미관측이 정상 분기를 지우거나, S0 무효 라벨이 시간 평가에 들어간다.

## 민감도

42일은 변경하지 않는다. 시작·끝 ±1µs, KST/UTC 동치, 조용하지만 완전한 창, 같은 실행·다른 실행, 거부 0/양수/불명, 구매 상태 ok의 0/not_run/불명, 전부·일부·행 결측과 비정상 값을 대조한다.

## 남은 불확실성

시뮬레이터의 strict 설정과 거부 시 advance 완료 의미는 공개 정의 확인 대상이며 리드가 비차단으로 정했다. N2의 None 부모 계약과 N3 조상 거부의 Feature/S1 차단 여부도 미결정이다. 실제 시뮬레이터 실행·개발 데이터 성능·Final Holdout은 이번 시험용 합성 연결 검증으로 증명하지 않는다. R2·R3·R4의 별도 기록, 수정 후 독립 코드 재검토·실제 데이터 인수·병합을 함께 확인해야 한다.

### 2026-10-30 PR #251 연결 검증에서 확인한 차단 조건

구현 head 3e66d29ae5d141b120e24b64a97f181d3b63c15e, 시험 병합 f079bbd514715cc416d0eee6acd807d35316895d의 의존성 CI는 1,475건 실행에서 failure 11·error 23·skip 12를 보고했다. 이는 통과가 아니다. 시스템 팀 시험의 가짜 라벨이 int64 열에 NaN을 대입하며 발생한 오류는 시험 자료형을 명시적으로 float로 바꿔 보완했고, 관측 실패 사유를 정상값으로 바꾸지는 않았다.

오케스트레이션의 허용된 공개 API만 호출하고 공개 sink.run_records만 관측한 재현(seed 7·240명·warmup 60일)에서 S0~S5 6개 분기의 parent_run_id가 모두 None이었다. rejected는 모두 0이지만 N2의 정확한 머리 연결 검사는 HISTORY_PARENT_UNRESOLVED를 반환했다. 따라서 분기 경제 지표 차단은 가능성만이 아니라 이 재현에서 확인한 현상이다. 이 사실이 None 부모의 허용 계약을 승인한 것은 아니다. 내부 생성 코드·숨김 상태는 열람하지 않았다. 공개 계약의 연결 증거를 어느 계층에서 제공할지 리드·시뮬레이터 팀과 확정하기 전에는 검사를 완화하지 않는다.

모델 모듈을 사용할 수 없는 기존 대체 읽기 시험도 read_events_t1에서 src.decision.data의 verify_event_run을 구하지 못해 not_run이 됐다. 이는 선택적 모델 경로와 필수 읽기 검증을 묶은 #179의 별도 회귀다. 검증을 생략하거나 정상 0으로 만들지 말고, 모델 유무와 독립된 검증 위치 또는 공개 events()의 검증된 읽기 계약을 사용하는 대안을 검토해야 한다. 이 기록은 해당 회귀의 수정 완료를 뜻하지 않는다.

후속 사용자 지시에 따라 필수 관측 계약 클라이언트로 분리했다. 설계·대안은 [DR-179-independent-read-verification](DR-179-independent-read-verification.md)에 기록한다. 파일 검증과 관측 상태 판정은 선택적 모델 등록부를 거치지 않으며 기존 호출 이름은 같은 구현을 재노출한다. 이 변경은 N2의 정확한 부모 연결 조건을 완화하지 않는다. 따라서 대체 읽기 회복과 실제 분기 경제값의 계약 차단은 별도로 검증·보고한다.

이전의 실제 연결 미실행 기록은 당시 검증 범위다. 이 추가 기록 이후 공개 API를 통한 연결 재현은 실행했으며 두 차단 조건을 확인했다. 실제 개발 데이터의 모델 성능·S-learner 동점률·Final Holdout은 여전히 미실행이다.
