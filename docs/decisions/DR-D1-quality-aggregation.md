# DR-D1-quality-aggregation — 명시적 모집단의 원시 결측 요약

| 항목 | 내용 |
|---|---|
| 태스크 | D1 · #83 |
| 작성 | Codex · 광진(kwung0206) 요청 · 2026-10-21 |
| 상태 | 제안 |

## 무엇을 정하는가

기존 FeatureOutput과 호출자가 명시한 K 모집단·Feature ID 목록에서 원시 null 수·분모·가용 수·결측률·사유별 건수를 반환하는 인메모리 함수를 구현한다. 입력 모집단과 반환 Feature 목록을 명시하고 공식 합격 여부는 null로 둔다.

## 정하지 않으면 무엇이 막히나

관측 고객만 분모로 고르거나 미구현 Feature를 제외하면 결측률이 실제보다 낮아진다. 사유를 하나만 세면 복수 원인도 사라진다.

## 선택지

| 안 | 장점 | 한계 |
|---|---|---|
| 명시적 K 목록·F-ID와 canonical/quality 대조 | 고객 행 누락·모호한 분모를 거부 가능 | 공식 U_f/예외는 별도 결정 필요 |
| output에서 가용 행만 분모로 추론 | 간단 | 모집단 왜곡으로 기각 |
| 5% 기준/short-history 제외를 함께 적용 | 자동 판정 가능 | SD7 선점으로 기각 |

## 조사한 것

설계 missing-policy §4는 N_f=|U_f|, M_f=null 수이며 사유별 비율은 중복 가능하다고 정한다. SRS FE-009/FS-002는 명시적 결측 정책·메타데이터를 요구한다. 현재 FeatureOutput은42개 canonical과 E/index_date별 quality를 분리하고 미구현 항목도 null/사유를 보존한다.

## 결정

구현 전 선택은 d1_quality_summary.py와 전용 시험이다. 모집단은 중복 없는 명시적 K=(E,index_date) 목록이며 Feature 목록은 전체42종 중 호출자가 고른 고유 ID다. 하나의 호출은 명시한 같은 K 집합을 각 Feature의 분모로 사용한다. Feature별 다른 U_f는 다른 명시적 호출로 구분한다. 여러 index_date는 각각 K 행으로 세고 별도 E 수도 알려 SD6 분할/고객 수와 혼동하지 않는다.

요청 K의 canonical/quality 누락·중복·가용성/사유 모순은 입력 오류다. 부재를0/null로 채우거나 행을 버리지 않는다. 미구현 F36–F41을 포함해 요청 목록을 그대로 집계한다. 사유는 행별 고유 코드로 세며 서로 다른 사유 합계가 N을 넘는 것을 허용한다. 분모0이면 rate=null·ZERO_DENOMINATOR, 원시 count/denominator=0은 그대로 남긴다.

공식 모집단·적격성·short-history 예외·5% 합격을 추론하지 않는다. 출력에 caller_supplied_K, 제외0, 예외 미적용, official_verdict=null을 명시한다. 이것은 원시 요약이며 이벤트 출처·학습 객체·split을 새로 입증하는 로더가 아니다. 원본 FeatureOutput을 변경하지 않는다.

## 기각한 안과 기각 사유

고객 ID만으로 서로 다른 source/index_date를 합치거나 결측 행/미구현 Feature를 자동 제거하는 안은 기각했다. 품질 행이 없을 때 정상이라고 추정하는 안도 기각했다.

## 이 결정이 틀렸다면 어떻게 드러나나

명부 전용 고객 또는 미구현 항목이 분모/결측 수에서 사라지거나, N=0이0%로 나오거나, 사유 합계를 N으로 제한하면 실패다. 모집단 밖 행이 결과를 바꾸거나 중복 K·누락 quality가 수용돼도 실패다.

## 민감도

모집단/Feature 목록을 바꾸면 결과가 달라지므로 반환값에 정확한 범위를 남긴다. 입력 행/quality 순서만 바꿨을 때 count가 변하면 안 된다.

## 남은 불확실성

SD6 공식 split, SD7 U_f·분모·short-history 예외·공식 판정은 미결정이다. 실제 입력 결측률 인수·공식 품질 합격·D1 전체 완료는 이번 결과로 판단하지 않는다.
