## 무엇을 정하는가

새 출력 루트의 parent_run_id가 None인 정상 공개 API 분기를 검증할 시스템 경로를 정한다. 일반 파일 로더의 정확한 외부 부모 검사와 공용 실행 기록의 의미는 바꾸지 않는다.

## 정하지 않으면 무엇이 막히나

검증기가 root-local 실행 기록에 cross-root 부모 번호를 요구하여 실제 S0~S5를 차단한다. 분기 경제값·증분 ROI·S0 미래 시점 평가와 CLI evaluate/full 검사가 진행되지 않는다.

## 결정

A를 선택한다. EventReader가 직접 성공시킨 최근 읽기만 snapshot에 결속한다. history 객체·내용 fingerprint·읽기 근거·until을 고정하고 본선 파일 근거를 재검증한다. 동일 리더의 restore가 토큰을 복원하고 출력 루트를 기록한다. 그 뒤 동일 리더의 advance가 돌려받은 RunSummary만 연결 대상으로 삼는다. read는 root·run_id·end·start(스냅샷 until)가 일치할 때만 이 경로를 사용한다. 연결은 한 번만 소비하며, 복원/진행 실패나 중간 읽기 실패 뒤 재사용하지 않는다.

분기 파일은 기존 verify_event_run으로 검증한다. root-local 사슬은 독립 검증하고, 명시적 외부 부모가 있으면 기존 history 머리 검사를 사용한다. 손상·미주장 파일·잘못된 부모는 어느 쪽에서도 성공하지 않는다. 본선/분기 실행 ID 중복을 거부하며 조상 거부 수는 기존처럼 감사한다. rejected가 있는 현재 창은 정식 라벨·경제 입력으로 승인하지 않는다.

스냅샷 생성 전에는 공개 events의 본선 전량과 검증된 본선 파일의 22필드 내용을 대조한다. 분기 읽기에서는 공개 events 전량과 검증된 본선+분기 파일 전량을 다시 대조한다. 각 행을 22필드 순서 JSON(null 보존, 공용 파서로 UTC 시각 정규화)으로 SHA-256 처리하고, 행 지문을 정렬해 중복을 보존한 채 전체 SHA-256·행 수를 비교한다. 다른 고객·같은 ID의 다른 값·누락·추가·중복은 거부하고 행 순서·동일 순간의 KST/UTC 표기는 허용한다. 본선 행 지문을 스냅샷 생존 기간에 메모리로 보관하는 비용이 있다. 이는 기존 파일 바이트 해시를 대체하지 않는 추가 의미 대조다.

분기마다 공개 events를 끝까지 소비한다. 모델 로더가 없으면 이 스트림으로 프레임을 만들고 history를 다시 붙이지 않는다. 모델 로더가 있으면 API 전량 검증 뒤 기존 파일 로더와 history 결합을 유지한다. Feature 계산·측정 계산을 복제하지 않는다. 읽기 후 본선/분기 파일 fingerprint와 history 불변성을 재확인한다.

근거에는 실제 external_parent_run_id(None 포함), history_head_run_id, 공개 호출 결속 방식, 토큰의 해시(내용 해석 없음), RunSummary 창, 실행별 거부 수를 구분해 남긴다. None을 외부 부모 번호로 위조하지 않는다.

**근거:** 공개 API의 복원 계약과 러너가 소유한 연속 실행을 사용한다. 사용자 파일에서 받은 "복원 성공" 불리언을 믿는 경로는 만들지 않는다. 한 활성 세계를 단일 실행 루프가 사용하는 기존 전제에 한정하며, 외부 프로그램의 동시 세계 교체를 지원한다고 주장하지 않는다.

## 기각한 안과 기각 사유

B는 연결 증명을 생략하므로 기각한다. C는 기존 공개 API로 검증 가능한 흐름에 새로운 공용 필드를 요구하므로 이번에는 선택하지 않는다. D는 정상 스트림과 요청한 실행의 결속을 보장하지 못한다. 일반 파일 검사 실패 뒤 무조건 API로 읽어 성공시키는 안도 기각한다. 연결 근거가 없는 기존 직접 read 호출은 계속 엄격한 부모 검사를 받는다.

## 이 결정이 틀렸다면 어떻게 드러나나

미등록 토큰·다른 history·변경된 프레임/근거/파일·다른 root/run_id/시각 또는 재사용된 연결이 통과한다. 공개 스트림 중간 예외에서 일부 행이 남는다. 명시적으로 틀린 부모가 호출 결속 때문에 통과한다. 조상 거부 수가 사라지거나 같은 이력이 두 번 붙는다. 실제 공개 API의 정상 분기에서 이 조건을 충족할 수 없다.

## 민감도

root-local None/정확한 명시 부모/조상·모르는 부모, 로더 있음/없음, 빈/정상/변조/누락 파일, 현재·조상 rejected, 복원·진행·읽기 실패, KST/UTC와 summary 경계를 비교한다. 규칙 선택을 모델 성능으로 조정하지 않는다.

## 남은 불확실성

프로세스 외부에 저장된 snapshot 토큰을 다시 인수하거나 분기의 분기를 일반화하는 인터페이스는 이번 범위 밖이다. 아래 실제 실행은 확인했으며 독립 검수는 남아 있다. 새 공용 데이터·동작이 필요해지면 해당 부분은 양 팀 합의로 넘긴다. Final Holdout과 정식 공통 분할 D는 사용하거나 변경하지 않는다.
