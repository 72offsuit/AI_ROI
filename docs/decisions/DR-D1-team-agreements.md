## 무엇을 정하는가

본 실행의 시간 경계 선택을 기록하고, 가입일·최초구매·전체 이력의 공개 사용 계약, 공통 고객 분할표, Feature 공식 품질 기준의 공동 결정 요청을 연결한다.

광진은 D1 진행 방향을 선택했으며 실제 제공자의 수락·근거·공유 문서 반영은 관련 담당자와 확인한다. 모델의 코드 검토 판정은 그 수락 기록을 대신하지 않는다.

## 정하지 않으면 무엇이 막히나

가입일·최초/평생 근거가 필요한 실제 Feature 인수, 실제 공통 학습·평가 집합의 인수, 공식 품질 판정이 관련 범위에서 보류된다. 공개 계약의 합성 예시와 독립적인 로컬 구현·검증은 계속할 수 있다.

## 선택지

| 공동 항목 | 이미 선택한 방향 | 팀이 합의할 실제 내용 |
|---|---|---|
| 가입일과 전체 이력 | 적격성·허용 파생 용도 분리, 최고 도달 여정과 근거 부족 구분 | 공개 projection·제공 범위·당시 가용성·최초/평생 근거·반영 책임 |
| 공통 분할 | D2 관리, 고객·시간 분리, Train 그룹 5-Fold, 허용된 배정 결과 확인 | 실제 모집단·표 작성/승인·날짜·seed·라벨 완료·소비자 인수 |
| 공식 품질 | 전체 명부 원시 보고 보존, Feature별 사전 대상·예외 규칙 | 실제 명부·공식 대상·근거 있는 이력 부족 예외·담당자 수락 |

제공할 수 없는 정보는 해당 실제 인수에서 보류하는 안을 유지한다. persona 없는 대체 분할이나 추가 원천 사용은 필요할 때 팀이 별도 검토하며 자동 채택하지 않는다.

## 결정

### 사용자 선택이 완료된 시간 경계

| 항목 | 값 |
|---|---|
| 본 실행 T0 | 2026-10-22T00:00:00+09:00 |
| 같은 순간의 UTC | 2026-10-21T15:00:00Z |
| Feature 입력 | T0 미만, operator=lt, upper_exclusive=T0 |
| 2026-10-21T23:59:59.500+09:00 | 포함 |
| T0 자체와 이후 | 제외 |
| 공동 반영 | [#126](https://github.com/72offsuit/AI_ROI/issues/126)에서 리드·측정/입력 계약 담당과 확인 |

이 날짜는 본 실행의 값이다. 다른 index_date의 T0까지 이 날짜로 고정하지 않는다. 원본 정밀도·변환 손실 부재는 실제 제공 근거로 확인한다.

### 팀 합의 대기 항목

- [#135 가입일과 전체 이력](https://github.com/72offsuit/AI_ROI/issues/135): 용도·공개 필드·제공자·가용성·이력 보장·보류 범위.
- [#136 공통 고객 분할표](https://github.com/72offsuit/AI_ROI/issues/136): 실제 표·담당·고객/시점/라벨·권한 제공 배정·평가 인수.
- [#137 공식 품질 기준](https://github.com/72offsuit/AI_ROI/issues/137): 실제 명부·Feature별 사전 대상·예외·공식 판정.

각 이슈에 결정자·합의자·일자·선택 이유·반영 문서/버전·미지원 범위를 기록하고 최종 DR로 연결한다. 기존 SD1~SD8·Q1~Q5 방향은 유지한다. 이번 요청은 구매 0건의 가정 적용 범위나 현행 계산 정책을 구현하는 작업에 포함하지 않는다.

## 기각한 안과 기각 사유

| 안 | 채택하지 않는 이유 |
|---|---|
| 코드 검토 통과를 제공자 수락·공동 계약 승인으로 취급 | 판단 주체와 확인 범위가 다름 |
| 공개 교환 파일 전체를 자동으로 학습 원천에 추가 | D1의 원천·용도 제한을 넘어감 |
| 시스템에서 숨김 persona를 조회해 층화 | 접근 경계 위반 |
| 같은 seed만으로 공통 Test 일치를 선언 | 적격성·행·라벨·기간 차이를 검증하지 못함 |
| 결측 고객을 결과 확인 후 분모에서 제거 | 공식 품질 판정 기준이 결과에 의존함 |
| 합의 대기 때문에 독립 합성 검증도 전부 중단 | 실제 인수와 로컬 검증의 의존성이 다름 |

## 이 결정이 틀렸다면 어떻게 드러나나

T0와 같은 순간이 입력에 포함되거나 UTC/KST 표기만으로 경계 판정이 달라지면 시간 선택이 잘못 반영된 것이다. 허용하지 않은 가입일 용도, 부족한 이력으로 최초구매 확정, 다른 모델 Test 고객/행 불일치, 결과 후 품질 모집단 변경은 각각 해당 공동 계약의 반례다.

관련 담당자가 제공 불가 또는 기존 요구와의 충돌을 확인하면 그 항목의 대안을 팀과 다시 검토한다. 합의 전 실제 값·평가·공식 품질을 확정하지 않는다.

## 민감도

기준시점·실제 관측 기간·가입일 정밀도·이력 보장·평가 모집단·품질 예외가 바뀌면 Feature 가용성·평가 가능성과 결측률이 달라진다. 날짜와 seed의 예시는 실제 표와 승인된 적용 값으로 구분하며, 모델 성능을 보고 이 조건을 바꾸지 않는다.

## 남은 불확실성

리드·측정/입력 계약 담당의 공통 문구 반영, 실제 제공자 수락과 공개 자료, 실제 분할표·라벨 완료, Feature별 공식 품질 규칙이 남아 있다. 소유 등록과 Python 3.10 실제 실행은 별도 인계 조건이다. 진행 중인 다른 W0/W1 제품·테스트·Dictionary 변경은 이번 문서 커밋에 포함하지 않는다.

### 팀에 보낼 합의 요청문

팀장님과 관련 담당자분들께, D1 작업을 진행 중인 광진입니다.

D1의 실제 데이터 연결을 위해 아래 세 가지를 함께 합의하고 싶습니다.

- 가입일·전체 이력: 어떤 공개 정보를 적격성 판단과 Feature 계산에 사용할 수 있는지, 최초구매·전체 이력을 어디까지 제공·보장할 수 있는지 확인 부탁드립니다. #135
- 공통 고객 분할표: 표의 작성·관리 담당, 실제 고객·기준일·라벨 기간·분할 조건, 모델들이 같은 Test를 사용하는 확인 방법을 합의 부탁드립니다. 숨김 persona를 시스템에서 직접 읽는 방식은 사용하지 않습니다. #136
- 공식 품질 기준: 결측률을 계산할 대상 고객과 이력 부족 예외를 Feature별로 정하고, 필요한 명부·기간 근거를 누가 제공할지 확인 부탁드립니다. #137

시간 경계는 본 실행 T0를 2026-10-22 00:00 KST로 두고 그 시각 미만 기록을 사용하는 방향으로 선택했습니다. 관련 문서·추출 범위·검증 코드의 반영 담당과 정합성 확인을 부탁드립니다. #126

각 이슈에 동의·수정안·제공 불가·추가 확인 중 해당 의견과 담당자, 적용 문서/버전, 제공 가능한 공개 자료와 미지원 범위를 남겨주시면 합의 결과를 DR에 정리하겠습니다. 현재 합성 입력으로 가능한 검증은 진행하고, 실제 근거가 필요한 인수만 보류하고 있습니다.
